## Summary
The change to `lib/plan_batch.sh` is a single-function awk fix in `_plan_batch_emit_tail`: it reorders the JSON-unescape `gsub` calls by stashing literal backslashes as a `\001` (SOH) placeholder before processing `\n`/`\t`/`\"`, then restoring them at the end. No authentication, cryptography, or network I/O is introduced or touched. The awk block operates on a bounded, locally-written JSON file; all gsub patterns are string literals, not user-controlled. Two pre-existing low-severity concerns remain from the existing design: predictable temp-file naming that falls back to world-writable `/tmp`, and `eval` of captured signal-handler strings. Neither is new to this change. The SOH placeholder cannot produce a correctness-exploitable path because well-formed JSON API responses encode control characters as `\uXXXX`, not raw bytes; even if a raw SOH appeared it would only corrupt the decoded line's backslash rendering (no code execution).

## Findings
- [LOW] [category:A05] [lib/plan_batch.sh:89-93] fixable:yes — Temp files `$_pf`, `$_rf`, `$_zf` are created under `${TEKHTON_SESSION_DIR:-/tmp}` with only PID-based names. On a multi-user host this creates a TOCTOU window: an attacker can pre-create a symlink at the predicted path before the `printf '%s' "$prompt" > "$_pf"` write, redirecting the planning prompt to an attacker-controlled destination. Planning prompts can contain sensitive project task descriptions. Fix: use `mktemp` for atomic creation with random suffixes, e.g. `_pf=$(mktemp "${_sd}/tekhton_plan_prompt_XXXXXX.txt")`, or create the session dir with `mktemp -d` and `chmod 700` so no other user can enter it.
- [LOW] [category:A03] [lib/plan_batch.sh:136-144] fixable:yes — `eval "$_prev_trap_int"` and `eval "$_prev_trap_term"` evaluate strings captured from `trap -p INT/TERM`. This is the idiomatic bash pattern for trap save/restore and the source is trusted shell-internal state, but any `eval` of a non-literal string is a potential amplifier if the surrounding environment has been tampered with. Risk is negligible in a single-user pipeline context. If preferred, refactor to a named cleanup function and reference it directly in `trap`, eliminating the dynamic evaluation entirely.
