## Summary
This change is a large notes-pipeline migration from fourteen bash files to Go (`internal/notes/`, `cmd/tekhton/note*.go`, several `internal/finalize/` hooks). The Go surface handles local file I/O (HUMAN_NOTES.md read/write/parse), snapshot persistence, and CLI flag parsing. There are no network endpoints, authentication flows, cryptographic operations, or hardcoded secrets. Three low-severity issues were found: an unsanitised path used in snapshot lookup, unsanitised values written into HTML metadata comments (file corruption risk only, no browser rendering), and an unescaped user-derived value used as a grep regex in bash.

## Findings
- [LOW] [category:A01] [internal/notes/rollback.go:124-136] fixable:yes — `ReadSnapshot` accepts an absolute path for `id` without any bounds check, allowing it to open any path the process user can read (e.g. `tekhton note rollback /etc/passwd`). For the relative-path branch, `filepath.Join` cleans traversal sequences but does not enforce that the result stays under `.claude/notes_snapshots/`; a crafted ID such as `../../sensitive_file` escapes the snapshots directory. Risk is low for a local CLI because the user already has filesystem access, but automated pipeline contexts (inbox automation, CI) should not accept externally-supplied snapshot IDs without validation. Fix: after `filepath.Join`, verify `strings.HasPrefix(path, filepath.Join(projectDir, ".claude", "notes_snapshots"))`.
- [LOW] [category:A03] [internal/notes/parser.go:572-588] fixable:yes — `BuildMetadata` writes user-supplied `priority`, `source`, and `inboxFile` values verbatim into the HTML comment `<!-- note:... priority:VALUE source:VALUE -->`. If any value contains the sequence `-->`, the comment is prematurely closed and subsequent metadata (or free text) is emitted outside the comment, corrupting the metadata block. The file is written locally and never rendered in a browser, so this is a file-integrity issue rather than XSS. Fix: strip or reject values containing `-->` before embedding them.
- [LOW] [category:A03] [lib/inbox.sh:210,223] fixable:yes — `_process_manifest_append` uses `$mid` and `$dep` (both derived from the first line of an attacker-controlled inbox file) directly as grep patterns: `grep -q "^${mid}|"`. If either variable contains regex metacharacters (`.`, `*`, `(`, etc.), the duplicate/dependency check may produce false positives or false negatives, allowing duplicate or orphaned milestones to slip through. Fix: use `grep -qF "^${mid}|"` and `grep -qF "^${dep}|"` (fixed-string mode).
