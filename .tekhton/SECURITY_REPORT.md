## Summary
This review covers the m20 provider-routing arc: `cmd/tekhton/run_stage.go` and `cmd/tekhton/supervise.go` are updated to route through env-var-driven provider resolution; `internal/runner/provider_select.go` and `internal/runner/supervise_bridge.go` are new files implementing `ResolveProvider`, `ProviderFromRequest`, and the request/result bridge functions. The previous m19 finding (hardwired claude in run_stage.go) is fixed — provider resolution is now per-stage via `PROVIDER_<STAGE>` env vars. Provider selection uses a strict allowlist switch; error paths emit structured JSON envelopes rather than raw stacks; env-key construction sanitizes label characters before lookup; test self-skip guards are non-exploitable grep probes. One file-read path in the bridge lacks directory containment.

## Findings
- [LOW] [category:A01] [internal/runner/supervise_bridge.go:57] fixable:yes — `os.ReadFile(req.PromptFile)` reads whatever path is in the parsed JSON request envelope with no directory containment check. In production the bash pipeline writes temp paths under `$TEKHTON_DIR/`, but a crafted request JSON (via `--request-file` or piped stdin) can point `prompt_file` at any file readable by the process (e.g., `~/.ssh/id_rsa`). Because `tekhton supervise` is a local IPC binary with no network exposure, an attacker must already have write access to pipeline working files — keeping real-world risk low. Suggested fix: validate that `req.PromptFile` resolves under a known prefix (e.g., `os.TempDir()` or `$TEKHTON_DIR`) using `filepath.Clean` + `strings.HasPrefix` before the read.
- [LOW] [category:A03] [internal/runner/supervise_bridge.go:43-49] fixable:yes — `req.Provider` in the request JSON bypasses env-var resolution entirely and calls `constructProvider` directly, meaning a crafted request can override the operator's `PROVIDER=` env setting. The allowlist (`claude`, `codex`, `qwen-local`) prevents arbitrary code execution and limits impact to unexpected provider selection. No exploitability for a local CLI, but it silently overrides a configuration-layer control. Consider documenting the bypass explicitly or gating it on a flag (`--allow-request-provider`) so operators can opt out.
