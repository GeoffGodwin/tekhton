## Summary
The m07 Codex provider scaffold introduces four Go files (`codex.go`, `exec.go`, `flags.go`, `exit_codes.go`). The implementation uses `exec.CommandContext` with an `args []string` slice (not a shell string), so there is no shell injection risk. The prompt is piped via stdin. No hardcoded credentials, API keys, or auth tokens are present. The main concern is that temporary files created by `makeOutputLastMessagePath` (which capture agent last-message output) are never cleaned up — they accumulate in the OS temp directory and may contain sensitive pipeline output. A secondary low-severity concern is that the `codex.cwd` value from `ProviderSpecific` is passed through as a `--cd` argument without path validation.

## Findings
- [MEDIUM] [category:A02] [internal/provider/codex/flags.go:72-78] fixable:yes — `os.CreateTemp` creates a `tekhton-codex-last-*.md` file in the OS temp dir but the path is only returned into the args slice; neither `buildExecArgs` nor the `RunAgent` caller tracks or removes it. On long-running pipelines this accumulates potentially sensitive agent output on disk. The file should be removed after `RunAgent` returns (both on success and error paths), or the path should be surfaced in `provider.Result` so the caller can clean up.
- [LOW] [category:A03] [internal/provider/codex/flags.go:37-45] fixable:yes — The `codex.cwd` value from `req.ProviderSpecific` is used verbatim as the `--cd` argument with no path validation (no check for absolute path, no guard against traversal sequences). A caller that passes a user-controlled string here could direct the agent to operate in an unintended working directory (e.g. outside the project root). Add a check that the resolved path is absolute and, if a project root is known, that it is a subdirectory of it.
- [LOW] [category:A03] [internal/provider/codex/flags.go:54-59] fixable:yes — Inline config values from `ProviderSpecific["codex.config.*"]` are formatted as `KEY=VALUE` with no character-level validation. Since execution goes through `exec.CommandContext` (not a shell), injection is not possible, but a value containing `=` produces a malformed config entry silently (the extra `=` becomes part of the value). Consider rejecting or quoting values that would produce ambiguous entries.
