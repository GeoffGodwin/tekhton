## Summary
Security review for the `theseus/Phase2` branch, covering the implemented milestone arc m12–m17 (multi-provider chain, Codex provider, per-stage selection, tier enforcement, provider wiring to runner + CLI, qwen-local scaffold, m15 fix landing `_emit_provider_section` + `_emit_section_workspace`). The Go code uses `exec.CommandContext` with explicit argument slices throughout — no shell interpolation, no injection surface. Credential injection follows the standard `cmd.Env` pattern. Context cancellation propagates correctly. The config emitter correctly single-quote-escapes all values before they pass through `eval`, and the config parser rejects command substitution and common shell metacharacters. The one elevated gap remains incomplete credential redaction: `Redact()` scrubs Anthropic keys but not Codex API keys. No critical or high-severity vulnerabilities were identified.

## Findings
- [MEDIUM] [category:A09] [internal/errors/redact.go] fixable:yes — `Redact()` covers `ANTHROPIC_API_KEY` and `sk-ant-*` patterns but not `CODEX_API_KEY`. The supervisor tees agent stderr through `Redact()` into the causal log. If a Codex invocation fails and the error output surfaces a `CODEX_API_KEY` value (e.g. in a diagnostic trace), it will pass through unredacted. Fix: add `regexp.MustCompile(`CODEX_API_KEY=[^ \r\n]*`)` alongside `redactAnthropicEnvRE` and apply the substitution to the output.
- [LOW] [category:A01] [internal/provider/codex/flags.go:38-46] fixable:yes — `codex.cwd` from `req.ProviderSpecific` is passed directly to `--cd` with no validation. A misconfigured or adversarial internal caller could set it to a path outside the project root, causing the codex subprocess to read and write files anywhere on the filesystem. Add a guard that rejects values that are not absolute paths under the project working directory.
- [LOW] [category:A02] [internal/provider/codex/auth.go:33-34] fixable:no — The per-request API key from `ProviderSpecific["codex.api_key"]` is placed in `cmd.Env` as `CODEX_API_KEY=<key>`. This is the correct Go pattern for injecting secrets into child processes without mutating the parent env, but the value is briefly visible in `/proc/<pid>/environ` for the subprocess lifetime. No code-layer mitigation is available; this risk belongs in operator documentation.
- [LOW] [category:A04] [internal/provider/codex/flags.go:104-109] fixable:yes — Tempfile TOCTOU in `makeOutputLastMessagePath`: the file is created, immediately closed, and the path passed to the subprocess via `--output-last-message`. Linux sticky-bit on `/tmp` and mode `0600` make exploitation impractical on a standard host, but in shared-uid CI container environments the race window is real. Consider keeping the descriptor open through the subprocess boundary.
- [LOW] [category:A03] [lib/init_config_workspace.sh:57-62] fixable:yes — Workspace type/name values from project-file detection (package.json workspace names, etc.) are echoed directly into the generated `pipeline.conf` without sanitization. The Go parser strips outer quotes and rejects `$(` and `;|&><`, but does NOT reject `"`. A workspace name with `"` produces `WORKSPACE_TYPE="foo"bar"`, which parses to `foo"bar` — `shellQuote` then wraps it safely in single quotes, so actual shell injection is prevented. However, a workspace name containing `$(` would cause `--init` to abort with a parse error. Sanitize workspace names before emission: strip or reject characters outside `[A-Za-z0-9._-]`.
- [LOW] [category:A05] [internal/proto/agent_v1.go:128-130] fixable:yes — `AgentRequestV1.Validate()` confirms `PromptFile` is non-empty but does not check that the path is within an expected working directory. The current call graph always produces `PromptFile` from the internal prompt-render subsystem, so practical exposure is near-zero. A `filepath.Clean` containment check would harden the validation boundary against future callers.
