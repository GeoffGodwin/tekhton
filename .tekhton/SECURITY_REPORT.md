## Summary
The m35.1 change set ports security-stage helpers from bash into Go (`internal/security/`, `cmd/tekhton/security.go`) and replaces `lib/security_helpers.sh` with a 60-LOC shim that shells out to the Go binary. The code handles only file I/O and string manipulation against trusted pipeline-internal files (SECURITY_REPORT.md, CODER_SUMMARY.md). No network communication, no cryptography, no authentication surfaces, and no hardcoded credentials were introduced. The overall security posture of this change is good; all findings are low severity and one is an acknowledged, intentional preservation of a pre-existing bash limitation.

## Findings
- [LOW] [category:A03] [cmd/tekhton/security.go:49] fixable:yes — TSV tab injection: the `parse-findings` subcommand emits findings as `severity\tfixable\tdesc` and the bash shim splits on `IFS=$'\t'`. If a finding description contains a literal tab, `read -r sev fix desc` will truncate the description at the first embedded tab and silently drop the remainder. The code comment acknowledges this is an inherited bash behavior preserved for parity; a fix would be to percent-encode tabs in the emitter or switch to a length-prefixed protocol. Low severity because (a) security reports are generated by a pipeline agent rather than raw external input, and (b) truncated descriptions underreport detail but cannot corrupt severity/fixable classification since those fields precede the description in the TSV row.
- [LOW] [category:A01] [cmd/tekhton/security.go:62,156] fixable:yes — The `--report` and `--summary` flags accept arbitrary filesystem paths with no restriction to the project directory. A caller controlling these flags can open any file the process owner can read (e.g. `--report /etc/passwd` returns an empty findings list because the format does not match). In practice the bash shim populates these from `${SECURITY_REPORT_FILE:-.tekhton/...}` and `${CODER_SUMMARY_FILE:-.tekhton/...}`, which are pipeline-controlled env vars. Since the tool runs at user privilege with no setuid there is no privilege-escalation path; this is an accepted pattern for internal dev-tooling CLIs. A hardening option is to reject paths that escape `project-dir` via `filepath.Rel`, but this is not blocking.
- [LOW] [category:A09] [lib/security_helpers.sh:14] fixable:yes — `2>/dev/null` on the Go binary call in `_parse_security_findings` silently suppresses all stderr, including binary-not-found and permission-denied errors. If `TEKHTON_BIN` is misconfigured the shim silently yields an empty findings array and the stage proceeds as if no security issues exist. The `[[ ${#_SEC_SEVERITIES[@]} -gt 0 ]]` return value makes a binary failure indistinguishable from a clean scan to callers. Fix: capture stderr and forward it through the pipeline's `warn` helper, returning a distinct exit code on binary failure.
