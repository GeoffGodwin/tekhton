## Findings
- [LOW] [category:A03] [lib/quota_probe.sh:67] fixable:yes — `IFS=',' read -ra items <<< "$spec"` correctly avoids word-splitting, but the loop variable `item` on line 69 undergoes leading/trailing whitespace trimming via parameter expansion on line 69–70 before comparison. If PROVIDER ever contains shell glob characters (e.g. `*`), bash parameter expansion inside `[[ ]]` is glob-safe, so no actual expansion risk exists here. The real concern is that `spec` is printed directly into `log` messages (line 56) via `${QUOTA_PROBE_MIN_INTERVAL:-600}` — not `$spec` itself — so no injection path. Informational only; no fix required.
- [LOW] [category:A04] [lib/quota_probe.sh:97] fixable:yes — Temporary file is created under `${TEKHTON_SESSION_DIR:-/tmp}`. If `TEKHTON_SESSION_DIR` is unset and /tmp is world-writable, the stderr capture file is visible between creation and the `rm -f` on line 138. The `XXXXXX` mktemp suffix prevents predictable names (no symlink/race), but a co-located attacker could read probe stderr. In practice probe stderr contains only rate-limit error text, not credentials. Prefer enforcing mode-700 on the session directory at startup; no change needed in this file if that invariant holds.
