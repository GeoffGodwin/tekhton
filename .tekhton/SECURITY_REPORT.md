## Summary
The change to `lib/plan_batch.sh` refines the provider-aware `_call_planning_batch` dispatcher and its accompanying parsing helpers (`_plan_batch_emit_tail`, `_trim_document_preamble`, `_extract_template_sections`). No authentication, cryptography, or network I/O is introduced. All shell variable expansions are quoted; the AWK-based JSON parser operates on a bounded, locally-written file with no user-controlled patterns. Two low-severity concerns remain from the existing design: predictable temp-file naming that falls back to world-writable `/tmp`, and `eval` of captured signal-handler strings. Neither is exploitable in the normal single-user pipeline context, but both are worth hardening for shared-host deployments.

## Findings
- [LOW] [category:A05] [lib/plan_batch.sh:89-93] fixable:yes — Temp files `$_pf`, `$_rf`, `$_zf` are created under `${TEKHTON_SESSION_DIR:-/tmp}` with only PID-based names. On a multi-user host this creates a TOCTOU window: a race-condition attacker can pre-create a symlink at the predicted path before the `printf '%s' "$prompt" > "$_pf"` write, redirecting the planning prompt to an attacker-controlled destination. Planning prompts can contain sensitive project task descriptions. Fix: use `mktemp` for atomic creation with random suffixes, e.g. `_pf=$(mktemp "${_sd}/tekhton_plan_prompt_XXXXXX.txt")`, or create the session dir with `mktemp -d` and `chmod 700` so no other user can enter it.
- [LOW] [category:A03] [lib/plan_batch.sh:136-144] fixable:yes — `eval "$_prev_trap_int"` and `eval "$_prev_trap_term"` evaluate strings captured from `trap -p INT/TERM`. This is the idiomatic bash pattern for trap save/restore and the source is trusted shell-internal state, but any `eval` of a non-literal string is a potential amplifier if the surrounding environment has been tampered with. Risk is negligible in a single-user pipeline context. If preferred, refactor to a named cleanup function and reference it directly in `trap`, eliminating the dynamic evaluation entirely.
