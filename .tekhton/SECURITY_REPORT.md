## Summary
The changes span `lib/init_config_sections.sh` (config file generator), the new helper `lib/init_config_sections_helpers.sh`, and `lib/plan_batch.sh` (planning agent invocation). The primary concern is in the config generator: auto-detected project values (test commands, build commands, paths) are interpolated into shell variable assignments without escaping double-quotes. If project detection sources (e.g., `package.json`, `Makefile`) contain embedded double-quotes, the generated `pipeline.conf` can contain malformed or injected shell tokens that execute when the file is later sourced. A secondary, lower-severity issue is PID-based temp file naming in `/tmp` in `plan_batch.sh` when `TEKHTON_SESSION_DIR` is unset. The `eval` of `trap -p` output in `plan_batch.sh` is idiomatic bash trap-save/restore and is not a real vulnerability. No hardcoded secrets, authentication bypasses, or network-facing vulnerabilities were found.

## Findings
- [MEDIUM] [category:A03] [lib/init_config_sections_helpers.sh:36,40,43,48] fixable:yes — `_emit_verified_line` writes `echo "${key}=\"${val}\""` without escaping double-quotes in `$val`. Auto-detected values from project files (e.g., `package.json` scripts, Makefile targets) can contain `"` characters, which break the quoting and inject arbitrary shell tokens into the generated `pipeline.conf`. Since `pipeline.conf` is sourced by `lib/config.sh` during every pipeline run, this is a config-injection → code-execution path. A malicious project under `--init` (supply-chain scenario) could exploit this. Fix: escape `"` before emission — `val="${val//\"/\\\"}"`  — or use `printf '%s=%q\n'` and strip the outer quoting to match the expected format.
- [LOW] [category:A01] [lib/plan_batch.sh:89-91] fixable:yes — Temp files `$_pf`, `$_rf`, `$_zf` are created under `${TEKHTON_SESSION_DIR:-/tmp}` with only PID-based names (no random component). On a multi-user host a local attacker can pre-create a symlink at the predicted path, redirecting the planning prompt write to an attacker-controlled file. Fix: replace the manual constructions with `mktemp "${_sd}/tekhton_plan_XXXXXX.txt"` for atomic, unpredictable creation.
