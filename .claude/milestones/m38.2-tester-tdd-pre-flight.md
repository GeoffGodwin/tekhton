# m38.2 — Tester TDD Pre-Flight

## Overview

| Item | Detail |
|------|--------|
| **Arc motivation** | Second decimal of m38. Ports `stages/tester_tdd.sh` (110 LOC) — the TDD write-failing pre-flight that runs BEFORE the coder when `PIPELINE_ORDER=test_first`. ## Design

### Goal 1 — `tdd.Run` entry point

```go
// internal/tester/tdd/tdd.go
package tdd

type Options struct {
    MaxTurns        int     // TESTER_WRITE_FAILING_MAX_TURNS=10
    Model           string  // CLAUDE_TESTER_MODEL=claude-sonnet-4-6
    AgentTools      string  // AGENT_TOOLS_TESTER
    PreflightFile   string  // TDD_PREFLIGHT_FILE
    LogDir          string  // LOG_DIR
    Timestamp       string  // TIMESTAMP (run id)
}

type Result struct {
    Timing          tester.TesterTiming
    PreflightExists bool
    NullRun         bool
    AgentExitCode   int
    Turns           int
    DurationS       int
}

// Run executes the TDD write-failing pre-flight. Returns a non-nil error
// ONLY on UPSTREAM API failure (which halts the pipeline — regression-canary).
// Null-run is warn-and-return-nil — TDD null runs fall back to "coder proceeds
// without pre-written tests", matching bash semantics at line 89-92.
//
// Mirrors stages/tester_tdd.sh::_run_tester_write_failing.
func Run(ctx context.Context, req *Request) (*Result, error)
```

### Goal 2 — UPSTREAM error returns non-nil error (regression-canary)

This is the load-bearing semantic of M38.2. The bash version at `stages/tester_tdd.sh:74-86`:

```bash
if [[ "${AGENT_ERROR_CATEGORY:-}" = "UPSTREAM" ]]; then
    warn "TDD tester hit an API error ..."
    write_pipeline_state \
        "tester" \
        "TDD pre-flight API error: ${AGENT_ERROR_SUBCATEGORY:-unknown}" \
        "$_tdd_resume_flag" \
        "${TASK:-}" \
        "UPSTREAM error during TDD write-failing phase"
    export SKIP_FINAL_CHECKS=true
    exit 1                                # <-- LOAD-BEARING: halts the pipeline
fi
```

Go equivalent:

```go
if agentResult.ErrorCategory == "UPSTREAM" {
    state.Write(req, state.Entry{
        Stage:       "tester",
        ExitStage:   "TDD pre-flight API error: " + agentResult.ErrorSubcategory,
        ResumeFlag:  buildResumeFlag("test"),
        Task:        req.Task,
        Reason:      "UPSTREAM error during TDD write-failing phase",
    })
    req.SkipFinalChecks = true
    return nil, fmt.Errorf("tdd pre-flight upstream error (%s): %s",
        agentResult.ErrorSubcategory, agentResult.ErrorMessage)  // <-- non-nil error
}
```

The `tdd_test.go` regression-canary:

```go
func TestRun_UpstreamReturnsNonNilError(t *testing.T) {
    fakeAgent := &fakeAgentRunner{
        result: &AgentResult{
            ErrorCategory:    "UPSTREAM",
            ErrorSubcategory: "rate_limit",
            ErrorMessage:     "Too many requests",
        },
    }
    req := newTestRequest(t, fakeAgent)
    _, err := tdd.Run(ctx, req)
    if err == nil {
        t.Fatal("UPSTREAM error must return non-nil error — regression at stages/tester_tdd.sh:85")
    }
    if !strings.Contains(err.Error(), "rate_limit") {
        t.Errorf("error should include subcategory; got %v", err)
    }
    // And state was written:
    if !req.StateWritten {
        t.Error("state must be written before returning error")
    }
}
```

### Goal 3 — Null-run is non-fatal in TDD

Bash semantics at `stages/tester_tdd.sh:89-92`:

```bash
if was_null_run; then
    warn "TDD tester was a null run — falling back. Coder will proceed without pre-written tests."
    return
fi
```

Go equivalent returns `nil` error with `Result.NullRun=true`. The caller (M38.6's `RunStage`) inspects `NullRun` and proceeds to the coder without pre-written tests. A separate test asserts null-run returns nil error.

### Goal 4 — Preflight file archival

Bash at `stages/tester_tdd.sh:97-98`:

```bash
cp "$_preflight_file" "${LOG_DIR:-.claude/logs}/${TIMESTAMP:-}_$(basename "${TDD_PREFLIGHT_FILE:-.tekhton/TESTER_PREFLIGHT.md}")"
```

Go equivalent uses `os.Open` + `io.Copy` (avoid shell-out). Archival failure is best-effort (warn-and-continue) per bash semantics.

### Goal 5 — Context-budget reporting wiring

Bash calls `build_context_packet`, `_add_context_component`, `log_context_report` — these are provided by `lib/context.sh` and `lib/context_compiler.sh`, both already Go-native or shimmed. The Go port at M38.2 calls into `internal/context` for the same effect. The exact shape is small — three calls in a row — and matches the M34/M35/M36/M37 pattern.

### Goal 6 — No bash deletion in this decimal

`stages/tester_tdd.sh` STAYS on disk at M38.2 close. The bash dispatch in `tester.sh:50-54` continues to call `_run_tester_write_failing`. M38.6 is where the dispatch flips to call `tdd.Run` and the bash file deletes.

## Watch For

- **UPSTREAM error MUST return non-nil error.** This is the M38 parent-flagged regression hot-spot. Returning `nil` after writing state is the bug — the pipeline keeps running, hits unrelated downstream failures, and the post-mortem points at the wrong stage. The `TestRun_UpstreamReturnsNonNilError` test is the canary; do not delete or weaken it.
- **Null-run is NOT a regression and is NOT fatal in TDD.** Bash returns success from null-run; the Go port matches. TDD null-runs fall back to "coder proceeds without pre-written tests" — see `stages/tester_tdd.sh:89-92`. The distinction matters: UPSTREAM = API failure = halt; null-run = agent died before writing = warn-and-continue.
- **`TESTER_WRITE_FAILING_MAX_TURNS=10` is intentionally low.** TDD pre-flight is bounded — the agent's job is small (write a few failing tests), and a wide turn budget invites scope creep. Preserve the default of 10. The `TESTER_MAX_TURNS=50` budget applies to the verify-passing main tester, not TDD.
- **`TDD_PREFLIGHT_FILE` is a distinct artifact from `TESTER_REPORT_FILE`.** The TDD path produces `.tekhton/TESTER_PREFLIGHT.md` (not TESTER_REPORT.md). The Go port preserves the separate path. M38.6 wires the dispatch — until then, the bash file at `stages/tester.sh:50-54` continues to branch on `TESTER_MODE=write_failing`.
- **`pipeline_order.sh` sets `TESTER_MODE`. Do NOT port pipeline_order in this milestone.** The decision-to-run-TDD lives in `lib/pipeline_order.sh`, which stays bash through all of M38. M38.6 reads `TESTER_MODE` from the request envelope; the bash setting flow is unchanged.
- **`print_run_summary` is called at `tester_tdd.sh:63` after the agent.** The Go port wires this to `internal/finalize.PrintRunSummary` (which already exists from M21). Don't open-code a custom summary.
- **The bash file STAYS on disk in this decimal.** M38.2 only adds Go code; M38.6 is where the bash deletion happens. A test that asserts `stages/tester_tdd.sh` exists is a small sanity guard that catches premature deletion.
