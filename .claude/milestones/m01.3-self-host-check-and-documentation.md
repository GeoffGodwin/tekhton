#### Milestone 1.3: Self-Host Check and Documentation

Add the self-host smoke script that proves the Go binary is reachable during a Tekhton pipeline run, plus the developer onboarding documentation. After this sub-milestone, the full m01 acceptance criteria are satisfied.

Files to create:
- `scripts/self-host-check.sh`
- `docs/go-build.md`

Acceptance criteria:
- `scripts/self-host-check.sh` exits 0 in default (CI-safe) mode: builds the Go binary, prepends `bin/` to `$PATH`, exercises the dispatcher routing matrix, and asserts `tekhton --version` output matches `VERSION`.
- The full `tekhton.sh --dry-run` smoke is gated behind `TEKHTON_SELF_HOST_DRY_RUN=1` (live Claude CLI agents require auth CI cannot satisfy).
- Script is idempotent — safe to run twice in the same CI job, no lockfile or state-file writes that fail on re-run.
- `docs/go-build.md` covers: prerequisite Go install, `make` targets, cross-compile output layout, CI artifact location.
- `docs/go-build.md` is ≤ ~100 lines (one-page max).
- No file under `lib/`, `stages/`, `prompts/`, or `tools/` is modified.
- `bash tests/run_tests.sh` parity check still identical before/after.

Watch For:
- Self-host check must remain idempotent — no writes that fail on second invocation.
- Do not exercise live Claude CLI agents in the default mode; the env-gated tier is for humans with auth.
- The bash pipeline runs the exact same way it did before — the Go binary's presence on `$PATH` is observed but unused.
- Documentation is dev onboarding, not a user manual — keep it tight.

Seeds Forward:
- m02's `tekhton causal emit` will be the first subcommand that bash code actually invokes; the self-host harness established here is the verification surface for that change.
- The `TEKHTON_SELF_HOST_DRY_RUN=1` env gate becomes the convention for future tiers that require live auth.
