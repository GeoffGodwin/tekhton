## Design

### Goal 1 — `scripts/audit-bash-env.sh`

The audit is a grep-based scanner, not a true bash parser. We do not need AST-level precision for this — operationally, the false-positive rate of a careful regex is acceptable because every flagged site gets manual review during the sweep (m27.2). The script must be fast enough that running it in CI on every PR is painless (target: under 2 seconds on the whole repo).

Allowlist construction:

```bash
# Hardcoded knobs the StageEnvV1 contract emits (internal/runner/env.go AsKV)
_STAGE_ENV_KEYS=(
    MILESTONE_MODE _CURRENT_MILESTONE TASK AUTO_ADVANCE AUTO_ADVANCE_LIMIT
    HUMAN_MODE HUMAN_NOTES_TAG LOG_DIR LOG_FILE TIMESTAMP SESSION_DIR
    # ... full list extracted from env.go at script-write time
)

# pipeline.conf keys (extracted from internal/config/defaults.go at runtime
# via `tekhton config defaults --emit shell` so the script stays in sync
# automatically when new keys are added).
_pipeline_conf_keys() {
    "${TEKHTON_BIN:-tekhton}" config defaults --emit shell 2>/dev/null \
        | grep -oE '^[A-Z_][A-Z0-9_]*' \
        | sort -u
}
```

Detection pattern — flag any `${VARNAME}` or `$VARNAME` from the allowlist that is NOT inside a `${VARNAME:-...}` default expansion. The trick is that `${VARNAME:-...}` and `${VARNAME-...}` and `${VARNAME:=...}` and `${VARNAME+...}` and `${VARNAME:+...}` are all safe under `set -u`; bare `${VARNAME}` and `$VARNAME` are not. Use `pcregrep` (with `-P` perl mode) so we can use negative-lookahead:

```bash
# Matches ${VARNAME} but NOT ${VARNAME:-...}, ${VARNAME-...}, etc.
_pcre_unguarded='\$\{(' "${joined_keys}" ')\}'
# Plus bare $VARNAME with word boundary
_pcre_bare='\$(' "${joined_keys}" ')\b'
```

False-positive scenarios the script must exclude:
- Inside `#` comments
- Inside single-quoted strings (bash doesn't expand them)
- Variable read inside `[[ -v VARNAME ]]` / `[[ -n "${VARNAME+x}" ]]` patterns
- Variable read inside a heredoc with `<<'EOF'` quoted marker (no expansion)

Output format — one line per site, no extra noise so the output is grep-able:

```
lib/intake_helpers.sh:191:MILESTONE_MODE
lib/finalize_commit.sh:47:_CURRENT_MILESTONE
stages/coder.sh:450:CODER_MAX_TURNS
```

Exit code: 0 when no findings, 1 when any findings (so CI can fail on regression).

### Goal 2 — `tests/test_audit_bash_env.sh`

Six fixture files under `tests/testdata/audit_bash_env/`, each isolating one detection case. The test harness runs the audit script against each, asserts the expected match (or absence). Sample fixtures:

```bash
# fixtures/01-guarded.sh — must NOT flag
echo "${MILESTONE_MODE:-false}"

# fixtures/02-unguarded.sh — must flag at line 1
echo "${MILESTONE_MODE}"

# fixtures/03-comment.sh — must NOT flag (inside a #-comment)
# echo "${MILESTONE_MODE}"

# fixtures/04-conditional.sh — must NOT flag
[[ -n "${MILESTONE_MODE+x}" ]] && echo set

# fixtures/05-out-of-allowlist.sh — must NOT flag
echo "${SOME_LOCAL_VAR}"

# fixtures/06-heredoc.sh — must NOT flag (single-quoted heredoc marker)
cat <<'EOF'
${MILESTONE_MODE}
EOF
```

### Goal 3 — `.tekhton/M27_INVENTORY.md` initial snapshot

On m27.1 close the implementer runs `bash scripts/audit-bash-env.sh > .tekhton/M27_INVENTORY.md`. The snapshot is committed at m27.1 close so m27.2 has a stable, reviewable punch list to work from. Once m27.2 closes the punch list, the file is deleted (m27.2 acceptance criterion).

## Watch For

- **Dogfood stability invariant.** m27.1 adds a script, a test, and a one-time inventory file. No runtime behavior changes. tekhton-stable can be safely rebuilt after this milestone; no follow-up milestone is required first.
- **Allowlist drift.** The hardcoded `_STAGE_ENV_KEYS` list and the `tekhton config defaults --emit shell` output drift over time. Capture both at script-write time and add a comment block in the script citing `internal/runner/env.go:AsKV` and `internal/config/defaults.go` as the authoritative sources so future maintainers know where to re-sync.
- **`pcregrep` portability.** macOS BSD grep does not support `-P`; the script must check for `pcregrep` or `grep -P` availability and fall back to a slower-but-portable awk parser. Document the fallback in the script header.
- **Performance.** The audit runs on every CI pass after m27.3 wires it in. Targeting <5s on the current repo is fine; if the script grows to >10s, switch from a per-file grep to a single repo-wide invocation with `--include` patterns.
