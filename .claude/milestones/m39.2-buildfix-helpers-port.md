# m39.2 — Buildfix Helpers Port

## Overview

| Item | Detail |

## Design

### Sequencing note

m39.2 must land before m39.3 — the loop body (m39.3) consumes the helpers as a typed Go API. Developing both in parallel risks interface drift; m39.2's strict pure-function shape is the lever that keeps m39.3 reviewable. The bash `stages/coder_buildfix_helpers.sh` stays sourced by `stages/coder_buildfix.sh` during m39.2 — premature deletion would break the bash-coder path that's still serving the pipeline through m39.3 close.

### Goal 1 — Shared types in `types.go`

Both m39.2 (helpers) and m39.3 (loop) reuse the same type vocabulary. Landing them in `internal/coder/buildfix/types.go` in m39.2 avoids a churn diff in m39.3.

### Goal 2 — `ComputeBudget` (the most config-laden helper)

```go
// internal/coder/buildfix/helpers.go

// ComputeBudget mirrors _compute_build_fix_budget. Returns 0 when the
// cumulative cap is exhausted (signal to halt the loop). Inputs are
// integer-only (matching bash's lack of fp math).
//
// Schedule:
//   attempt 1 → 1.0× base
//   attempt 2 → 1.5× base
//   attempt 3+ → 2.0× base
//
// Clamps applied in order: floor 8, upper (max_turns * multiplier / 100,
// floored at 8), cumulative remaining cap.
func ComputeBudget(attempt, base, used int, cfg Config) int {
    if cfg.EffectiveCoderMaxTurns <= 0 {
        cfg.EffectiveCoderMaxTurns = 80
    }
    if cfg.MaxTurnMultiplier <= 0 {
        cfg.MaxTurnMultiplier = 100
    }
    if cfg.TotalTurnCap <= 0 {
        cfg.TotalTurnCap = 120
    }

    var budget int
    switch attempt {
    case 1:
        budget = base
    case 2:
        budget = base * 3 / 2
    default:
        budget = base * 2
    }

    if budget < 8 {
        budget = 8
    }

    upper := cfg.EffectiveCoderMaxTurns * cfg.MaxTurnMultiplier / 100
    if upper < 8 {
        upper = 8
    }
    if budget > upper {
        budget = upper
    }

    remaining := cfg.TotalTurnCap - used
    if remaining <= 0 || remaining < 8 {
        return 0
    }
    if budget > remaining {
        budget = remaining
    }
    return budget
}
```

The 14-row table test:

| # | attempt | base | used | multiplier | cap | expected | reason |
|---|---------|------|------|-----------|-----|----------|--------|
| 1 | 1 | 27 | 0 | 100 | 120 | 27 | 1× base |
| 2 | 2 | 27 | 0 | 100 | 120 | 40 | 1.5× = 40 (27*3/2) |
| 3 | 3 | 27 | 0 | 100 | 120 | 54 | 2× = 54 |
| 4 | 1 | 4 | 0 | 100 | 120 | 8 | floor clamp |
| 5 | 1 | 27 | 0 | 50 | 120 | 27 | upper = 80*50/100=40, no clamp |
| 6 | 3 | 80 | 0 | 100 | 120 | 80 | upper = 80, clamps 160→80 |
| 7 | 1 | 27 | 100 | 100 | 120 | 20 | remaining = 20, clamps 27→20 |
| 8 | 1 | 27 | 113 | 100 | 120 | 0 | remaining = 7 < 8 → halt |
| 9 | 1 | 27 | 120 | 100 | 120 | 0 | remaining = 0 → halt |
| 10 | 1 | 27 | 130 | 100 | 120 | 0 | remaining = -10 → halt |
| 11 | 2 | 100 | 0 | 200 | 240 | 150 | upper = 160; 100*3/2=150; no clamp |
| 12 | 3 | 100 | 100 | 200 | 240 | 140 | 2×=200, upper=160, remaining=140 |
| 13 | 1 | 27 | 0 | 0 | 120 | 27 | multiplier=0 defaults to 100 |
| 14 | 1 | 27 | 0 | 100 | 0 | 27 | cap=0 defaults to 120 |

### Goal 3 — `ProgressSignal` (M128 stall detection)

```go
// ProgressSignal mirrors _build_fix_progress_signal.
//   - improved   when newCount < prevCount
//   - worsened   when newCount > prevCount
//   - unchanged  when counts equal AND tails equal
//   - improved   when counts equal but tails differ
func ProgressSignal(prevCount, newCount int, prevTail, newTail string) Signal {
    if newCount < prevCount {
        return SignalImproved
    }
    if newCount > prevCount {
        return SignalWorsened
    }
    if prevTail == newTail {
        return SignalUnchanged
    }
    return SignalImproved
}
```

Table test (7 rows): improved (count down), worsened (count up), unchanged (counts + tails equal), improved (counts equal, tails differ), edge cases (both zero + tails equal → unchanged; both zero + tails differ → improved; one empty tail).

### Goal 5 — `AppendReport` (per-attempt history)

`_append_build_fix_report` writes a markdown section per attempt with seven fields (turn budget, terminal class, gate result, progress signal, error-count delta, M127 classification). The Go port preserves the exact markdown shape — downstream parsers (notes pipeline, watchtower) rely on simple grep/sed access.

```go
func AppendReport(path string, r AttemptReport) error
```

Schema example:

```markdown
## Attempt 1
- Turn budget: 27
- Terminal class: max_turns
- Gate result: fail
- Progress signal: improved
- Error-count delta: 12→5
- M127 classification: code_dominant
```

Header (created on first append):

```markdown
# Build-Fix Report — 2026-06-01 10:23:45

Per-attempt history of the coder-stage build-fix continuation loop (M128).
Each attempt records the adaptive turn budget, the agent's terminal class,
the post-attempt build-gate result, the progress signal vs. the prior
attempt, and the M127 routing classification at loop entry.
```

Both the header and the per-attempt section are byte-asserted against the bash output in a fixture-based test.

## Watch For

- **`ComputeBudget` is integer-arithmetic only.** Bash has no fp math (`base * 3 / 2` not `base * 1.5`). The Go port must preserve integer arithmetic — `base * 3 / 2` not `int(float64(base) * 1.5)`. For `base = 27`, both yield 40, but for `base = 5`, `5 * 3 / 2 = 7` whereas `int(5 * 1.5) = 7` — they coincide here, but for `base = 11`, integer is `11 * 3 / 2 = 16` and float-cast is `int(11 * 1.5) = 16` — they still coincide, but rounding behavior diverges in edge cases (e.g., negative inputs, which shouldn't occur but parity demands integer semantics). A unit test asserts `ComputeBudget` agrees with a `bash -c` invocation of `_compute_build_fix_budget` on 20 random inputs.
- **`BUILD_FIX_TOTAL_TURN_CAP=120` is load-bearing.** The cumulative cap is the failsafe that prevents a runaway build-fix loop from consuming the entire EFFECTIVE_CODER_MAX_TURNS budget across multiple attempts. The default (120) is 1.5× the default `CODER_MAX_TURNS=80`. Operators tuning this should understand the 1.5× headroom — document this in the `Config` struct doc comment.
- **The 20-line tail window is fixture-load-bearing.** `_bf_get_error_tail` returns the last 20 non-blank lines exactly. Changing to 15 or 25 silently breaks `tests/test_build_fix_loop.sh` (referenced in the bash comment). The Go port preserves 20 as a typed constant `const defaultErrorTailWindow = 20` and a unit test asserts the constant.
- **`AppendReport` is append-only.** The bash version uses `>> "$file"` for the per-attempt section and `> "$file"` only for the initial header. The Go port preserves this: `os.OpenFile(path, os.O_APPEND|os.O_CREATE|os.O_WRONLY, 0644)`. A test that calls `AppendReport` three times asserts three `## Attempt N` sections in the final file (not one with the last attempt overwriting the others).
- **The pipe-separated record format from `classify_build_errors_with_stats` is operator-visible vocabulary.** The bash function emits 8 pipe-separated fields per record (category | safety | remediation | diagnosis | count | total_matched | total_lines | unmatched). The Go parser in `EmitRoutingDiagnosis` must parse all 8 fields, even though the rendered markdown only shows category / safety / count / diagnosis. The remaining fields are header-level stats (total_matched / total_lines / unmatched_lines) extracted from the FIRST record only — preserve this byte-identically.
- **`ExtraContextFor` returns the empty string for `DecisionNoncodeDominant`** even though the loop never reaches this code path for that decision (it exits at the noncode_dominant branch before reaching `ExtraContextFor`). The empty-string return is defensive — preserve it so a future refactor that re-routes noncode through the loop doesn't inject a stale `mixed_uncertain` context block.
- **`SetSecondaryCause` writes to a typed struct, not to env vars directly.** The bash version exports `SECONDARY_ERROR_*` env vars; the Go port writes to `*SecondaryCause` and the orchestrator wires those to env vars at process boundary (when invoking child bash stages or writing pipeline state). This decouples the helpers package from environment side effects — easier to test, easier to compose with other Go subsystems. A unit test asserts the struct fields match the four bash env var values byte-identically.

## Seeds Forward

- **m39.3 — Build-fix loop + scout sub-stage:** Consumes every helper from m39.2.
