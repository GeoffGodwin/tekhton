## Design

### Sequencing note

m36.2 lands after m36.1 (which delivers the pre-stage gate Go pattern) and before m36.3 (which consumes m36.2's helpers in-process). The critical sequencing rule: m36.2 must NOT delete the two bash helper files. M36.3 deletes them along with `stages/intake.sh`. Deleting in m36.2 breaks the bash stage which still calls `_intake_parse_verdict` etc. by source-time function lookup. The replacement-by-shim pattern (bash function body becomes a one-line exec into Go) keeps the bash stage working through the m36.2 → m36.3 window.

### Goal 1 — `internal/intake/helpers.go` API

```go
package intake

import (
    "crypto/sha256"
    "encoding/hex"
    "io"
    "os"
    "path/filepath"
    "regexp"
)

type Helpers struct {
    ProjectDir          string
    TekhtonHome         string
    SessionDir          string  // typically .tekhton/session/<TIMESTAMP>
    MilestoneDir        string  // typically .claude/milestones
    ClarificationsFile  string  // typically .tekhton/CLARIFICATIONS.md
    DagEnabled          bool    // MILESTONE_DAG_ENABLED
    ProjectRulesFile    string  // typically CLAUDE.md
}

// MilestoneContent returns the milestone file body (DAG mode) or the
// extracted CLAUDE.md milestone block (inline mode), or the task string
// (non-milestone mode). Ports stages/intake_helpers.sh::_intake_get_milestone_content.
func (h *Helpers) MilestoneContent(milestoneMode bool, currentMs, task string) (string, error)

// ContentHash returns SHA-256 of content (hex, lowercase).
func (h *Helpers) ContentHash(content string) string

// ShouldSkip returns true if hash matches the previously saved value
// in <SessionDir>/intake_content_hash.
func (h *Helpers) ShouldSkip(hash string) bool

// SaveHash writes hash to <SessionDir>/intake_content_hash.
func (h *Helpers) SaveHash(hash string) error

// ParseVerdict reads the report file and returns one of:
// PASS | TWEAKED | SPLIT_RECOMMENDED | NEEDS_CLARITY. Defaults to PASS if
// the file is missing or unparsable (bash parity).
func (h *Helpers) ParseVerdict(reportPath string) string

// ParseConfidence reads the report file and returns an int in 0-100.
// Defaults to 100 if missing or invalid.
func (h *Helpers) ParseConfidence(reportPath string) int

// ParseTweaks extracts the "## Tweaked Content" section body.
func (h *Helpers) ParseTweaks(reportPath string) string

// ParseQuestions extracts the "## Questions" section body.
func (h *Helpers) ParseQuestions(reportPath string) string

// ApplyTweakMilestone writes tweakedContent to the milestone file for
// msNum, with three guards:
//   - Size guard: reject if tweakedLines < minPct% of origLines.
//     On reject, write rejected tweak to <SessionDir>/REJECTED_TWEAK.md
//     and return ErrTweakRejected.
//   - Atomic: write to tmpfile in MilestoneDir, then os.Rename.
//   - Backup: cp the original to <msFile>.pre-tweak before overwrite.
// On success, calls AddPMMetadata to stamp the PM-tweaked comment.
func (h *Helpers) ApplyTweakMilestone(tweakedContent, msNum string, minPct int) error

// ApplyTweakTask updates the TASK env (returned in newTask) using the first
// non-empty line of tweakedContent. Persists to
// <SessionDir>/INTAKE_TWEAKED_TASK.md for resume.
func (h *Helpers) ApplyTweakTask(tweakedContent string) (newTask string, err error)

// AddPMMetadata inserts or updates the `<!-- PM-tweaked: YYYY-MM-DD -->`
// comment in msFile. Atomic via tmpfile + os.Rename. Matches
// bash _intake_add_pm_metadata semantics (insert after milestone-meta
// block if present, else after the first line).
func (h *Helpers) AddPMMetadata(msFile string) error

// ErrTweakRejected is returned by ApplyTweakMilestone when the size guard fails.
var ErrTweakRejected = errors.New("intake: tweak rejected — size below minimum")
```

Implementation notes:

- `MilestoneContent` ports the awk script at bash lines 222-228 as a Go regexp + line-scanner. The fallback to CLAUDE.md inline mode preserves the `#{1,5} (M|m)ilestone <num>(.<num>)*` heading match.
- `ParseVerdict` normalizes to uppercase + strips whitespace + validates against the four allowed values (bash lines 53-58). Anything else falls back to `PASS`.
- `ApplyTweakMilestone` reads original line count via `bytes.Count(buf, []byte{'\n'})`; computes `pct := (newLines * 100) / origLines`; rejects if `origLines > 20 && pct < minPct`. The `> 20` floor matches bash line 130.

### Goal 2 — `internal/intake/verdict.go` API

```go
package intake

type VerdictHandler struct {
    H               *Helpers
    AutoSplit       bool        // INTAKE_AUTO_SPLIT
    ConfirmTweaks   bool        // INTAKE_CONFIRM_TWEAKS
    CompleteMode    bool        // COMPLETE_MODE (autonomous)
    MilestoneMode   bool        // MILESTONE_MODE
    CurrentMs       string      // _CURRENT_MILESTONE
    Task            string      // TASK
    PipelineStateFn func(stage, exitReason, args, task, msg, ms string) error
    SplitMilestoneFn  func(ms, claudeMd string) error    // injected (resides in bash post-port; uses CLI exec)
    SwitchSubMsFn     func(ms, claudeMd string) error    // injected
    ClarifyHandleFn func(reportPath, projectDir string) error  // execs `tekhton clarify handle`
    TekhtonBin      string
    Stdout          io.Writer   // for the rejection-message print
    Stderr          io.Writer
    Stdin           io.Reader   // for interactive y/n + s/c/q prompts
}

// HandleTweaked applies tweaks and (if ConfirmTweaks) requests user confirmation.
// In CompleteMode, never prompts — user-rejected tweaks always succeed silently
// since there is no human to ask (matches bash behavior where TTY check fails).
func (v *VerdictHandler) HandleTweaked(reportPath string) error

// HandleSplitRecommended invokes split-milestone or prompts for user choice.
// On AutoSplit + MilestoneMode + non-empty CurrentMs + non-nil SplitMilestoneFn,
// splits automatically and switches to the first sub-milestone. Otherwise
// presents [s]plit, [c]ontinue, [q]uit options.
func (v *VerdictHandler) HandleSplitRecommended(reportPath string) error

// HandleNeedsClarity writes the questions to CLARIFICATIONS.md in the
// `## Q: <question>` format (matches bash lines 146-160 byte-for-byte).
// In CompleteMode, never attempts interactive clarification — saves state
// and exits with PipelineStateFn. Otherwise, synthesizes a tiny intake-
// clarify report under <SessionDir>/intake_clarify_report.md and invokes
// ClarifyHandleFn.
func (v *VerdictHandler) HandleNeedsClarity(reportPath string) error
```

### Goal 4 — Bash file rewrites (shim pattern)

`lib/intake_helpers.sh` (post-M36.2 shape — slim shims, NOT deleted):

```bash
#!/usr/bin/env bash
set -euo pipefail
# =============================================================================
# lib/intake_helpers.sh — M36.2 SHIM. Functions delegate to `tekhton intake helpers ...`.
# DELETED in M36.3 along with stages/intake.sh.
# =============================================================================

_intake_content_hash() {
    local content="$1"
    printf '%s' "$content" | "${TEKHTON_BIN:-tekhton}" intake helpers content-hash --stdin
}

_intake_should_skip() {
    "${TEKHTON_BIN:-tekhton}" intake helpers should-skip --hash "$1"
}

_intake_save_hash() {
    "${TEKHTON_BIN:-tekhton}" intake helpers save-hash --hash "$1"
}

_intake_parse_verdict() {
    "${TEKHTON_BIN:-tekhton}" intake helpers parse-verdict --report "$1"
}

# ... etc for every function name preserved.
```

Function names + signatures + exit codes + stdout shape preserved. Function bodies replaced with one-line exec. Same shape for `lib/intake_verdict_handlers.sh`.

The bash stage (`stages/intake.sh`) calls these functions by name — it does NOT know they delegate to Go. Zero diff on the caller side.

The keyword-overlap matcher (`stages/intake.sh:145-179`) — extract 4-character-minimum words from TASK, scan note text for any match — is the only bash logic in `stages/intake.sh` that calls a helper-file function transitively (via the existing `tekhton note extract` command from m24). M36.2 does NOT port this — it lives in `internal/stages/intake/context.go` in M36.3. The reason: this is stage logic, not helper logic; M36.2 stays scoped to the two helper files only.

## Watch For

- **Bash files are rewritten to shims, NOT deleted.** Deleting in m36.2 breaks `stages/intake.sh`, which sources these via the stagerunner's `Helpers` list and calls the functions by name. The bash files delete in M36.3 alongside `stages/intake.sh`. The transition shim subcommands (`tekhton intake helpers ...`) also delete in M36.3.
- **Operator-vocabulary preservation is the hardest constraint.** The rejection message (`Tweaks rejected by user. Saving state.`), the NEEDS_CLARITY status (`Intake: needs clarification.`), the `## Q: <question>` format in CLARIFICATIONS.md, and the `--complete` mode message all have email filters in operator dashboards. Byte-for-byte preservation is mandatory. The verdict_test.go regression tests enforce this.
- **The 50% shrinkage guard floor is 20 lines.** Bash line 130 has `[[ "$orig_lines" -gt 20 ]]` — milestones with ≤ 20 lines bypass the guard. Preserve. A test for a 10-line milestone with a 5-line tweak asserts acceptance.
- **`ApplyTweakMilestone` is atomic + has a backup.** Bash uses `mktemp` + `mv -f` + `cp -f <orig> <orig>.pre-tweak` before overwrite. The Go port uses `os.CreateTemp(MilestoneDir, "intake_tweak.*")` + `os.Rename` + `io.Copy` for the backup. The backup file `<msFile>.pre-tweak` MUST exist post-port — operators have rollback scripts.
- **DAG-mode milestone lookup has a manifest-lazy-load fallback.** Bash lines 199-204 lazy-load the manifest when `_DAG_LOADED != true`. The Go port does NOT need this (it instantiates `Helpers` with explicit `MilestoneDir` / `ProjectRulesFile` paths and resolves directly), but the inline-mode fallback (lines 219-230) must port: when the milestone file doesn't exist under MilestoneDir, fall back to extracting the `#{1,5} (M|m)ilestone <num>(.<num>)*` block from CLAUDE.md.
- **`HandleNeedsClarity` in CompleteMode does NOT invoke `tekhton clarify handle`.** Bash lines 163-172 explicitly check `COMPLETE_MODE` and short-circuit to `write_pipeline_state` + `exit 1`. The Go port mirrors this exact branch; the autonomous mode never attempts interactive clarification.
- **The `tekhton clarify handle` call is preserved (out-of-process).** The clarify subsystem is its own Go package (m25). M36.2 keeps the exec into `tekhton clarify handle --report <path> --project-dir <dir>` — porting clarify is out of M36 scope.
