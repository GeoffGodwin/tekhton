#### Milestone 1.1.1.1: Go Module Skeleton + Version Package + Plain Main

Establish the Go module and a minimal `main.go` that compiles and prints the version. This sub-milestone produces a working binary via direct `go build` (no Makefile yet), proving the module path and version package are wired correctly before the Makefile layer is added.

Files to create:
- `go.mod`
- `internal/version/version.go`
- `cmd/tekhton/main.go`

Acceptance criteria:
- `go.mod` declares module `github.com/geoffgodwin/tekhton` with `go 1.23` (pinned exactly).
- `internal/version/version.go` exposes a package-level `Version` string variable defaulting to the `dev` sentinel.
- `cmd/tekhton/main.go` is a plain `func main()` that prints `version.Version` (trimmed of trailing whitespace) followed by a newline and exits 0.
- `go build -o bin/tekhton ./cmd/tekhton` produces a binary.
- Running `./bin/tekhton` with no arguments prints `dev` and exits 0.
- No `go.sum` file is created (no third-party imports).
- No file under `lib/`, `stages/`, `prompts/`, or `tools/` is modified.

Watch For:
- Keep `cmd/tekhton/main.go` dependency-free (only `fmt` and the internal version package). Any third-party import here forces `go.sum` churn that belongs in 1.1.2.
- Pin `go 1.23` exactly in `go.mod` — drift to `1.23.X` or `1.24` causes downstream CI flake.
- `Version` must be a package-level `var` (not `const`), otherwise `-ldflags "-X"` cannot override it in 1.1.1.2.
- Trim trailing whitespace at print time as a defense-in-depth measure even though the `dev` sentinel has none — this keeps behavior identical once the Makefile injects a value from `VERSION`.

Seeds Forward:
- Milestone 1.1.1.2 adds the Makefile (`build`, `test`, `clean`) and the `-ldflags "-X github.com/geoffgodwin/tekhton/internal/version.Version=..."` injection that overrides the `dev` sentinel with the contents of repo-root `VERSION`.
- The exported `Version` symbol path established here is the exact target of the ldflags expression in 1.1.1.2 — do not rename or relocate it.
