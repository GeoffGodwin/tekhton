#### Milestone 1.2: CI Matrix (Build, Vet+Test, Lint)
Add the GitHub Actions workflow that exercises the Go toolchain on every PR and push. `.github/workflows/go-build.yml` triggers on PR + push to `main` and `feature/GoWedges`, runs three jobs on `ubuntu-latest`: (1) `make build-all` with five binaries uploaded as workflow artifacts; (2) `go vet ./...` and `go test ./...`; (3) `golangci-lint run ./...` with the "advanced" preset. `actions/setup-go` reads `go-version-file: go.mod` so local and CI Go versions cannot drift. The bash test suite stays gated by its existing CI rules — this workflow only adds Go CI.

Files to create:
- `.github/workflows/go-build.yml`

Acceptance criteria:
- CI workflow `go-build.yml` runs on push to `main` and `feature/GoWedges` and on PRs targeting either branch.
- All three jobs (build-all, vet+test, lint) are green on the V4 branch.
- Five binary artifacts (`tekhton-linux-amd64`, `tekhton-linux-arm64`, `tekhton-darwin-amd64`, `tekhton-darwin-arm64`, `tekhton-windows-amd64.exe`) are uploaded and downloadable from the workflow run.
- `actions/setup-go` is configured with `go-version-file: go.mod` (not a hardcoded version).
- `golangci-lint` runs the "advanced" preset; lint errors fail the job.
- The workflow does NOT invoke `bash tests/run_tests.sh`.

Watch For:
- No coverage gate yet — that lands in m04. Don't add a coverage threshold to `go test` here.
- `golangci-lint-action` should be pinned to a major version; floating tags are a flake source.
- The artifact upload step must run even if a later step fails, so build outputs are inspectable on broken runs.

Seeds Forward:
- Milestone 1.3's self-host check is invoked from the bash test path, not this workflow — keep them separate.
- m04 will tighten this workflow with a coverage gate; the test job is the hook point.
