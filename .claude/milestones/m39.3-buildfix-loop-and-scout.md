## Design

### Sequencing note

m39.3 lands two sub-packages in one milestone because they are entangled through `EFFECTIVE_CODER_MAX_TURNS`. The scout's `apply_scout_turn_limits` writes the value; `ComputeBudget` (m39.2) reads it; the loop body (m39.3) calls both. Splitting them across decimals would require either (a) stubbing `EFFECTIVE_CODER_MAX_TURNS` to a fixed value during the loop-only decimal, then re-flowing tests when the scout lands — large churn risk; or (b) defining a `TurnLimitProvider` interface in m39.2 that m39.3-loop and m39.3-scout both implement — abstraction overkill for one config value. The bundled decimal is the lesser foot-gun.

### Goal 1 — `internal/coder/buildfix/loop.go` (M128 continuation loop)

```go
// internal/coder/buildfix/loop.go
package buildfix

type LoopConfig = Config  // re-export from types.go (m39.2)

type LoopResult struct {
    Outcome              Outcome
    Attempts             int
    TurnBudgetUsed       int
    ProgressGateFailures int
    Classification       Decision
    FinalProgress        Signal
    FinalDelta           string // "prev→new"
    SecondaryCause       *SecondaryCause // populated on no_progress / exhausted
    StateExit            *StateExit       // populated on terminal failure
}

type StateExit struct {
    Stage      string
    ExitReason string  // "build_failure" | "env_failure"
    ResumeFlag string
    Task       string
    Notes      string
}

type Deps struct {
    ReadRawErrors          func() (string, error)
    Classify               func(raw string) Decision
    FilterCodeErrors       func(raw string) string
    RenderPrompt           func(name string, env map[string]string) (string, error)
    RunAgent               func(ctx context.Context, inv *agent.Invocation) (*agent.Outcome, error)
    RunBuildGate           func(ctx context.Context, label string) (bool, error)
    EmitRoutingDiagnosis   func(path string, raw string) error  // wraps helpers.EmitRoutingDiagnosis
    DriftHumanActionAppend func(ctx context.Context, source, desc string) error
    WritePipelineState     func(stage, reason, resumeFlag, task, notes string) error
    Log                    func(format string, args ...any)
    Warn                   func(format string, args ...any)
    Error                  func(format string, args ...any)
}

// Run is the M128 continuation loop entry point. Returns LoopResult on every
// code path; the orchestrator decides whether to exit based on Outcome and
// StateExit. The four Goal-7 stats are populated on every exit path.
func Run(ctx context.Context, cfg *LoopConfig, deps *Deps) (*LoopResult, error)
```

The loop body, in pseudocode:

```
1. Initialize stats (Outcome=NotRun, Attempts=0, TurnBudgetUsed=0, ProgressGateFailures=0).
2. If !cfg.Enabled, write build_failure state, return with StateExit set.
3. raw = deps.ReadRawErrors()
4. decision = deps.Classify(raw)  // may default to code_dominant
5. Switch decision:
   - noncode_dominant: HumanActionAppend + write env_failure state + return with StateExit.
   - mixed_uncertain: deps.EmitRoutingDiagnosis(BUILD_ROUTING_DIAGNOSIS_FILE, raw)
   - code_dominant | unknown_only | (unrecognized — warn): proceed
6. extra = ExtraContextFor(decision, BUILD_ROUTING_DIAGNOSIS_FILE)  // from helpers
7. base = cfg.EffectiveCoderMaxTurns / cfg.BaseTurnDivisor  (floor 8)
8. prevCount = CountErrors(BUILD_RAW_ERRORS_FILE); prevTail = ErrorTail(...)
9. Loop while attempt < cfg.MaxAttempts:
     attempt++
     budget = ComputeBudget(attempt, base, used, cfg)
     If budget == 0: outcome = OutcomeExhausted; break (cap reached)
     invokeBuildFix(raw, extra, decision, budget, deps)
     used += budget
     terminalClass = TerminalClass(exitCode, turns, budget)
     If RunBuildGate("post-coder-fix-N") == true:
         outcome = OutcomePassed; AppendReport; break
     newCount = CountErrors(...); newTail = ErrorTail(...)
     progress = ProgressSignal(prevCount, newCount, prevTail, newTail)
     AppendReport(attempt, budget, terminalClass, "fail", progress, "prev→new", decision)
     raw = deps.ReadRawErrors()  // refresh for next attempt
     If cfg.RequireProgress && attempt >= 2 && (progress == Unchanged || progress == Worsened):
         outcome = OutcomeNoProgress; break
     // M130 classification-required save_exit
     If cfg.ClassificationRequired && decision == MixedUncertain && attempt >= 1:
         outcome = OutcomeExhausted; break  // save_exit semantics
     prevCount = newCount; prevTail = newTail
10. ExportStats(result.Stats, outcome)
11. Switch outcome:
    - passed: return (success)
    - no_progress: SetSecondaryCause(...); write build_failure state; return with StateExit
    - exhausted: SetSecondaryCause(...); write build_failure state; return with StateExit
```

### Goal 2 — M127 routing classifier (`routing.go`)

```go
// internal/coder/buildfix/routing.go
package buildfix

import "github.com/geoffgodwin/tekhton/internal/errors"

// Classify wraps the m17 error classifier with the M127 4-token decision
// logic. Falls back to code_dominant when the classifier returns no signal.
func Classify(rawErrors string) Decision {
    if rawErrors == "" {
        return DecisionCodeDominant  // bash default fallback
    }
    stats, err := errors.ClassifyBuildErrorsWithStats(rawErrors)
    if err != nil || stats.TotalLines == 0 {
        return DecisionUnknownOnly
    }

    codeRatio    := float64(stats.CodeCount) / float64(stats.TotalLines)
    noncodeRatio := float64(stats.NoncodeCount) / float64(stats.TotalLines)
    unknownRatio := float64(stats.UnmatchedLines) / float64(stats.TotalLines)

    // Thresholds match the m17 classifier's bash mirror (frozen vocabulary).
    if noncodeRatio >= 0.7 {
        return DecisionNoncodeDominant
    }
    if codeRatio >= 0.7 {
        return DecisionCodeDominant
    }
    if codeRatio > 0 && noncodeRatio > 0 {
        return DecisionMixedUncertain
    }
    if unknownRatio >= 0.5 {
        return DecisionUnknownOnly
    }
    return DecisionCodeDominant  // last-resort fallback
}
```

### Goal 4 — Scout turn-limit application (`turn_limits.go`)

The most critical helper in m39.3. Must preserve floors AND scaling:

```go
// internal/coder/scout/turn_limits.go
package scout

type Estimate struct {
    FilesToModify       int
    EstimatedLines      int
    Interconnected      string   // "low" | "medium" | "high"
    RecommendedCoder    int
    RecommendedReviewer int
    RecommendedTester   int
}

type TurnLimits struct {
    Coder    int
    Reviewer int
    Tester   int
}

// DefaultFloors returns the bash defaults: coder=15, reviewer=5, tester=15.
func DefaultFloors() TurnLimits {
    return TurnLimits{Coder: 15, Reviewer: 5, Tester: 15}
}

// Apply preserves both the floor invariant (no value below the configured
// floor) AND the scaling invariant (values track the scout-recommended
// numbers, which themselves track the complexity band).
//
// Bash apply_scout_turn_limits is the byte-identical reference. The logic:
//   1. Read scout's Recommended N turns.
//   2. If <= 0 (parse failure), keep the configured default (CODER_MAX_TURNS etc.).
//   3. Otherwise, apply: result = max(scout_recommended, floor).
//
// The DYNAMIC_TURNS_ENABLED=false branch skips Apply entirely; the orchestrator
// gates this call.
func Apply(e *Estimate, floors TurnLimits) TurnLimits {
    out := floors
    if e == nil {
        return out
    }
    if e.RecommendedCoder > 0 {
        out.Coder = max(e.RecommendedCoder, floors.Coder)
    }
    if e.RecommendedReviewer > 0 {
        out.Reviewer = max(e.RecommendedReviewer, floors.Reviewer)
    }
    if e.RecommendedTester > 0 {
        out.Tester = max(e.RecommendedTester, floors.Tester)
    }
    return out
}
```

Parity tests (`turn_limits_test.go`):

| Test | Estimate | Floors | Expected Coder | Expected Reviewer | Expected Tester | Invariant covered |
|------|----------|--------|---------------|-------------------|-----------------|-------------------|
| Trivial | (1, 8, low, 20, 8, 20) | (15,5,15) | 20 | 8 | 20 | Scaling above floor preserved |
| Below floor | (1, 4, low, 10, 3, 12) | (15,5,15) | 15 | 5 | 15 | Floor clamp applied |
| Milestone | (12, 800, high, 100, 18, 70) | (15,5,15) | 100 | 18 | 70 | Large-band scaling preserved |
| Zero values | (1, 8, low, 0, 0, 0) | (15,5,15) | 15 | 5 | 15 | Parse-fail → defaults |
| Mixed | (3, 50, medium, 40, 4, 30) | (15,5,15) | 40 | 5 | 30 | Per-field floor + scaling |
| Nil estimate | nil | (15,5,15) | 15 | 5 | 15 | Defensive default |

### Goal 5 — `ShouldScout` predicate (`should_scout.go`)

The scout-vs-skip decision is a 4-arm branch in bash:

```bash
case "$NOTES_FILTER" in
  BUG)    case "${SCOUT_ON_BUG:-always}" in always|auto) SHOULD_SCOUT=true ;; never) SHOULD_SCOUT=false ;; esac ;;
  FEAT)   case "${SCOUT_ON_FEAT:-auto}" in always) SHOULD_SCOUT=true ;; auto) <est_turns + brownfield-grep check> ;; never) SHOULD_SCOUT=false ;; esac ;;
  POLISH) case "${SCOUT_ON_POLISH:-never}" in always) SHOULD_SCOUT=true ;; auto) <brownfield-grep check> ;; never) SHOULD_SCOUT=false ;; esac ;;
  *)      if [ "${DYNAMIC_TURNS_ENABLED:-true}" = "true" ]; then SHOULD_SCOUT=true ;; fi ;;
esac
```

Ported as a `ShouldScout(cfg ShouldScoutConfig) bool` with input fields for `NotesFilter`, `ScoutOnBug`, `ScoutOnFeat`, `ScoutOnPolish`, `DynamicTurnsEnabled`, `EstimatedTurns` (from triage), `Task` (for brownfield-keyword grep), `NotesContent` (for brownfield-keyword grep), `HumanNoteCount`, `NotesShouldClaim`, `ScoutCached`.

A 12-row table test covers every branch.

### Goal 6 — `_invoke_build_fix` ported as `invokeBuildFix`

The bash `_bf_invoke_build_fix` renders the `build_fix` prompt with the body = filter_code_errors(raw) + extra_context, then runs the agent with the computed budget. Ports as an unexported helper in `loop.go`:

```go
func invokeBuildFix(ctx context.Context, deps *Deps, label string, decision Decision, raw, extra string, budget int) error
```

The label format ("Coder (build fix — code_dominant)") matches bash byte-identically — operators grep for it in logs.

## Watch For

- **The M127 routing classifier MUST default to `DecisionCodeDominant` when `Classify` has no signal.** Bash `classify_routing_decision` defaults to `code_dominant` when stats are empty or when the classifier function isn't sourced. The Go port preserves this — empty input or classifier failure → `DecisionCodeDominant`, NOT `DecisionUnknownOnly`. The fallback semantics are load-bearing because they let the loop continue when the classifier subsystem is missing rather than save_exit-ing the user.
- **The M130 mixed_uncertain save_exit semantics are gated on `BUILD_FIX_CLASSIFICATION_REQUIRED=true`.** Default is `false` — the loop runs `MaxAttempts` for mixed_uncertain just like code_dominant. Only when classification is *required* (operator-set knob) does mixed_uncertain transition to save_exit after attempt 1. The Go port preserves this conditional — DO NOT make save_exit unconditional for mixed_uncertain.
- **The routing decision is fixed at loop entry, not re-classified per attempt.** Bash's comment at `coder_buildfix.sh:238` explicitly says: "the routing decision is fixed at loop entry per Watch For". The Go port preserves this — `Classify` is called once, before the loop, and the decision is captured in a local; subsequent attempts use the same decision even if the error stream's content drifts. Re-classifying per attempt would cause classification thrashing as the agent fixes some errors but introduces others.
- **`BUILD_RAW_ERRORS_FILE` is re-read per attempt, but only the raw stream — the routing decision is NOT re-derived.** Subsequent attempts get fresh error streams (the agent may have fixed some, surfaced others), but the loop's M127 routing context is preserved. A unit test asserts this by mocking `ReadRawErrors` to return different content per call and asserting the agent's prompt body differs across attempts but the `Classification` field in `AppendReport` is constant.
- **`apply_scout_turn_limits` preserves both floors AND scaling — both are tests on the same call.** A test that asserts only "value >= floor" would pass a buggy implementation that returns the floor unconditionally (scaling broken). A test that asserts only "value == scout_recommended" would pass a buggy implementation that doesn't clamp below the floor. The 6-row table test asserts BOTH invariants on different rows.
- **The DYNAMIC_TURNS_ENABLED gate decides whether to scout, NOT whether to apply scout's recommendations.** Bash branches `[ "${DYNAMIC_TURNS_ENABLED:-true}" = "true" ]` gate `SHOULD_SCOUT=true` (whether to invoke the agent). Once the scout has run, `apply_scout_turn_limits` is called regardless — the floors+scaling always apply when scout data is present. The Go port preserves this: `ShouldScout` is independent of `Apply`. A unit test asserts that `Apply` is callable on a scout `Estimate` regardless of how it was obtained (live agent, cached file, fixture).
- **`SCOUT_CACHED=true` short-circuits the agent invocation and reads from disk.** When `SCOUT_CACHED=true`, the scout sub-stage doesn't invoke the agent — it reads `SCOUT_REPORT_FILE` directly, applies turn limits, and archives the report (mirroring the dry-run code path at `coder.sh:176-187`). The Go port preserves this in `scout.Run` via a `cfg.Cached` boolean that bypasses `RunAgent`.
- **The scout substage TUI breadcrumb is M114-shipped.** Bash calls `_tui_call substage-begin --label "scout"` and `--end --label "scout" --verdict "PASS"`. The Go port preserves these calls via `deps.TUISubstageBegin / TUISubstageEnd` — operators rely on the "coder » scout" breadcrumb in the live timings row.
- **The DYNAMIC_TURNS_ENABLED default is `true`.** The bash default `${DYNAMIC_TURNS_ENABLED:-true}` means scout-by-default for non-NOTES_FILTER runs. The Go port preserves this default in `Config.DynamicTurnsEnabled = true` when unset. Operators who want to disable scouting set it to `false` explicitly.
- **`stages/coder.sh` still sources `coder_buildfix.sh` during m39.3.** Don't break the bash sourcing — `_invoke_build_fix` and `run_build_fix_loop` must remain callable from bash for as long as the bash coder.sh exists. Premature deletion of `stages/coder_buildfix.sh` breaks the bash-coder path that m39.1+m39.2 left intact.
