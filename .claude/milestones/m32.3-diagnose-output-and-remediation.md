## Design

### Sequencing note

m32.3 is where the Phase 5 diagnose arc closes. Three deliverables that cannot be reordered:

1. **Land the four Go output files first** (`output.go`, `crash.go`, `dashboard.go`, `remediation.go`). They each have parity tests against the 15 v3 baselines from m32.1.
2. **Rewire the callers second** (`tekhton-legacy.sh:657-659`, the three stage-failure files). Before this rewire, the bash callers still route through `lib/diagnose.sh`, so the bash files must stay on disk.
3. **Delete the bash files last.** After every caller is rewired and the parity gate passes, delete the 10 bash files. Deleting before the rewire breaks `tekhton --diagnose`; deleting before the output ports breaks the engine's report-writing path.

The `VERSION` bump and `docs/v4-phase5-stub.md` update happen last, after the delete.

### Goal 1 — `output.go` (`generate_diagnosis_report` + `print_diagnosis_summary` + `write_last_failure_context`)

```go
// internal/diagnose/output.go
package diagnose

type ReportWriter struct {
    ProjectDir   string
    TekhtonHome  string
    NowFunc      func() time.Time   // injectable for testing
}

// WriteReport renders the full DIAGNOSIS.md report. Returns the absolute path.
// Matches lib/diagnose_output.sh::generate_diagnosis_report byte-for-byte
// (after timestamp normalization).
func (w *ReportWriter) WriteReport(d Diagnosis, c *Context) (string, error)

// PrintSummary prints the terminal-friendly diagnosis summary to w. Matches
// lib/diagnose_output.sh::print_diagnosis_summary including the color-code
// envelope (CYAN heading, YELLOW confidence, etc. — uses internal/term/colors).
func (w *ReportWriter) PrintSummary(out io.Writer, d Diagnosis, c *Context) error

// WriteLastFailureContext writes/updates LAST_FAILURE_CONTEXT.json. m25 ported
// the *reader* (internal/failure_context); m32.3 ports the *writer* via that
// package's existing API. This function exists so the diagnose engine's
// "secondary cause" annotations propagate back to the v2 schema correctly.
func (w *ReportWriter) WriteLastFailureContext(d Diagnosis, c *Context) error
```

The report shape (matching bash `generate_diagnosis_report`):

```markdown
# Tekhton Diagnosis — <ISO-8601 timestamp>

## Classification
<CLASSIFICATION>  (confidence: <high|medium|low>)

## Stage
<stage>  task: <task-snippet>  milestone: <milestone>

## Cause Chain (collapsed)
<arrow-joined max-5-link chain>

## Recurring
<note about repeat-failure count or "First occurrence in recent runs">

## Suggested Recovery
1. <suggestion 1>
2. <suggestion 2>
...

## Raw Context
<JSON-collapsed Context dump for forensics>
```

### Goal 2 — `crash.go` (`print_crash_first_aid`)

```go
// internal/diagnose/crash.go
package diagnose

// PrintCrashFirstAid prints fast, no-agent-call recovery hints. Called from
// the crash handler (no PIPELINE_STATE yet) or as a fallback when run_diagnose
// has nothing to diagnose. Matches lib/diagnose_output_extra.sh::print_crash_first_aid.
func PrintCrashFirstAid(out io.Writer, c *Context) error {
    // Check 1: QUOTA_PAUSED file present → quota message.
    // Check 2: BUILD_ERRORS_FILE present + non-empty → build-failure message.
    // Check 3: PIPELINE_STATE.md exit_stage present → resume message.
    // Check 4: Recent log shows rate-limit / overloaded / server_error / timeout → transient message.
    // All checks are pure-IO (file existence + tail-grep); no agent calls.
}
```

`tekhton diagnose crash <stage>` is the standalone CLI entry: useful for the post-crash hook that fires before the engine has artifacts.

### Goal 3 — `dashboard.go` (`emit_dashboard_diagnosis`)

```go
// internal/diagnose/dashboard.go
package diagnose

import "github.com/tekhton/tekhton/internal/proto"

// WriteDashboardDiagnosis emits ${DASHBOARD_DIR}/data/diagnosis.js if the
// dashboard is enabled. The file format is `TK_DIAGNOSIS = <json>;` where
// <json> matches proto.DiagnosisV1 (m32.1-shipped).
func WriteDashboardDiagnosis(c *Context, d Diagnosis) error {
    if !isDashboardEnabled(c) {
        return nil
    }
    env := proto.DiagnosisV1{
        Available:      d.Classification != "" && d.Classification != "SUCCESS",
        Classification: d.Classification,
        Confidence:     string(d.Confidence),
        Stage:          c.Stage,
        CauseChain:     d.CauseChain,
        Suggestions:    d.Suggestions,
        RecurringCount: d.Recurring.Count,
        SchemaVersion:  1,
    }
    if !env.Available {
        env = proto.DiagnosisV1{Available: false, SchemaVersion: 1}
    }
    return writeJSFile(
        filepath.Join(c.ProjectDir, dashboardDir(c), "data", "diagnosis.js"),
        "TK_DIAGNOSIS", env)
}
```

`writeJSFile` is a small helper that wraps `TK_DIAGNOSIS = <json>;`. Output byte-for-byte matches bash `_write_js_file`.

### Goal 4 — `remediation.go` (`lib/remediation.sh` port)

```go
// internal/diagnose/remediation.go
package diagnose

// RemediationPolicy controls safe-list bounds. Defaults match bash:
//   MaxAttempts = 2, Timeout = 60s.
// Future per-project override hook lives here (a V5 candidate).
type RemediationPolicy struct {
    MaxAttempts int
    Timeout     time.Duration
    Blocklist   []string  // command fragments that reject unconditionally
}

func DefaultPolicy() RemediationPolicy {
    return RemediationPolicy{
        MaxAttempts: 2,
        Timeout:     60 * time.Second,
        Blocklist: []string{
            "rm -rf", "rm -fr", "drop ", "delete ", "destroy",
            "reset --hard", "--force", "force push", "truncate ",
        },
    }
}

type Remediator struct {
    Policy RemediationPolicy
    state  *remediationState  // per-gate-invocation counters
}

type RemediationResult struct {
    Attempted     []string  // commands that ran (or were rejected)
    AttemptCount  int
    Outcome       string    // "ok" | "blocked" | "max_attempts" | "timeout" | "skipped"
    LogEntries    []proto.RemediationLogEntry  // JSONL append-targets for RUN_SUMMARY
}

func (r *Remediator) Attempt(d Diagnosis, c *Context) RemediationResult
func (r *Remediator) Reset()  // call at start of each gate invocation
func (r *Remediator) Log() []proto.RemediationLogEntry  // for RUN_SUMMARY.json
```

The remediation safe-list is a thin wrapper around `os/exec.CommandContext` with a hardcoded denylist match (bash uses substring `grep -F`; Go uses `strings.Contains` in a loop). The 2-attempt cap is per-`Remediator`-instance. Causal event logging routes through `internal/causal` (the m02-shipped package).

A new `proto.RemediationLogEntry` type lands in `internal/proto/diagnosis_v1.go` (or a sibling file `remediation_v1.go` — design call: keep them grouped because both are diagnose-arc deliverables).

### Goal 5 — `cmd/tekhton/diagnose.go` wiring

```go
// cmd/tekhton/diagnose.go — modify newDiagnoseRunCmd, add newDiagnoseCrashCmd
func newDiagnoseRunCmd() *cobra.Command {
    return &cobra.Command{
        Use:    "run",
        Hidden: true,
        RunE: func(cmd *cobra.Command, _ []string) error {
            home := os.Getenv("TEKHTON_HOME")
            proj := projectDirFlag(cmd)
            eng := diagnose.NewEngine(rules.New())

            ctx, err := eng.ReadContext(cmd.Context(), &diagnose.Input{
                ProjectDir: proj, TekhtonHome: home,
            })
            if err != nil { return err }
            if ctx == nil {
                // No pipeline state — degrade to crash first-aid.
                return diagnose.PrintCrashFirstAid(cmd.ErrOrStderr(), &diagnose.Context{ProjectDir: proj})
            }

            d := eng.Run(cmd.Context(), ctx)

            // Side effects: report, dashboard, last-failure-context update.
            rw := &diagnose.ReportWriter{ProjectDir: proj, TekhtonHome: home}
            if _, err := rw.WriteReport(d, ctx); err != nil { return err }
            if err := rw.WriteLastFailureContext(d, ctx); err != nil { return err }
            if err := diagnose.WriteDashboardDiagnosis(ctx, d); err != nil { return err }

            return rw.PrintSummary(cmd.OutOrStdout(), d, ctx)
        },
    }
}

func newDiagnoseCrashCmd() *cobra.Command {
    return &cobra.Command{
        Use:    "crash <stage>",
        Short:  "Print crash first-aid hints (no pipeline state required)",
        Args:   cobra.ExactArgs(1),
        Hidden: true,
        RunE: func(cmd *cobra.Command, args []string) error {
            proj := projectDirFlag(cmd)
            return diagnose.PrintCrashFirstAid(cmd.OutOrStdout(),
                &diagnose.Context{ProjectDir: proj, Stage: args[0]})
        },
    }
}
```

### Goal 6 — Caller rewires

**`tekhton-legacy.sh:657-659`** (the `--diagnose` early-check):

```bash
# Before:
if [ "${1:-}" = "--diagnose" ]; then
    source "${TEKHTON_HOME}/lib/diagnose.sh"
    run_diagnose
    exit $?
fi

# After (m32.3):
if [ "${1:-}" = "--diagnose" ]; then
    tekhton_bin="${TEKHTON_BIN:-${TEKHTON_HOME:-.}/bin/tekhton}"
    if [[ ! -x "$tekhton_bin" ]]; then
        echo "Error: tekhton binary not found at $tekhton_bin. Run 'make build'." >&2
        exit 2
    fi
    exec "$tekhton_bin" diagnose run "${@:2}"
fi
```

**`stages/coder_buildfix.sh`** (and `hooks_final_checks.sh`, `lib/finalize_commit.sh`) — the inline classifier call:

```bash
# Before:
source "${TEKHTON_HOME}/lib/diagnose.sh"
classify_failure_diag
case "$DIAG_CLASSIFICATION" in
    BUILD_FAILURE|MAX_TURNS_EXHAUSTED) ... ;;
esac

# After (m32.3):
DIAG_CLASSIFICATION=$("$tekhton_bin" diagnose classify --input "$BUILD_ERRORS_FILE" 2>/dev/null || echo UNKNOWN)
case "$DIAG_CLASSIFICATION" in
    BUILD_FAILURE|MAX_TURNS_EXHAUSTED) ... ;;
esac
```

The rewired callers use the m17-shipped `tekhton diagnose classify` (NOT the new `diagnose run`) because the inline path only needs the routing token, not the full report.

### Goal 8 — Parity gate (`tests/test_diagnose_parity.sh`)

Three scenarios diff Go-emitted artifacts against the v3 baselines captured in m32.1:

1. **`crash-no-state`** — empty project, no `.claude/`. Expected: `tekhton diagnose run` prints "No pipeline runs found. Nothing to diagnose." (matches bash `run_diagnose` `has_state=false` branch).
2. **`ui-gate-interactive-reporter`** — fixture with Playwright html-reporter timeout signals. Expected: `DIAGNOSIS.md`, `data/diagnosis.js`, and `[diag] rule=...` stderr line all byte-identical to the v3 baseline after timestamp/PID normalization.
3. **`max-turns-coder`** — fixture with coder MAX_TURNS exhaustion. Expected: same byte-identical assertion across all three artifacts.

Each scenario is parameterized along the lines of m22's `tests/test_preflight_parity.sh`. The test wires into `make dogfood` so CI runs it on every PR.

## Watch For

- **Delete order matters.** Rewire callers FIRST, run the parity gate against the rewired tree, THEN delete the bash files. Deleting before rewiring breaks `tekhton --diagnose` mid-run. Deleting before the parity gate passes means the bash baseline is gone — you have no fallback if a Go output bug surfaces.
- **`emit_dashboard_diagnosis` JSON format is operator-visible via the Watchtower TUI.** The bash version produces `TK_DIAGNOSIS = {"available":true,"classification":"...","confidence":"...","stage":"...","cause_chain":"...","suggestions":["..."],"recurring_count":N};`. The Go version (via `proto.DiagnosisV1` marshalling) must match field order — JSON-encoding order. Go's `encoding/json` orders fields by struct declaration; the struct definition in `proto/diagnosis_v1.go` (m32.1) was chosen specifically to match bash's `printf` field order. If you reorder struct fields, the dashboard parser diff catches it.
- **`lib/remediation.sh` blocklist is byte-for-byte operator-facing.** Operators have audit hooks that grep for blocklist hits in causal logs. Do NOT extend or trim the blocklist in m32.3 — port verbatim. A future milestone can add new entries.
- **The 2-attempt remediation cap is per-gate, not per-pipeline-run.** Each call to `Remediator.Reset()` (typically once per stage failure handler entry) zeroes the counter. The Go port preserves this: `Remediator` is a value type returned from `NewRemediator()`, and callers must call `Reset()` at gate entry — same shape as bash `reset_remediation_state`. A test that runs two stage failures back-to-back asserts the counter zeros between them.
- **Rewiring `stages/coder_buildfix.sh` to exec `tekhton diagnose classify` introduces a subprocess-spawn cost in the hottest stage-failure path.** Bash `classify_failure_diag` was in-process (sourced); the rewire is one exec per build-fix loop iteration. The cost is ~20ms per invocation, called at most a few times per run — acceptable. But if a future build-fix loop becomes hotter (e.g. M139 inline-retry), the cost grows. Document this in `docs/go-migration.md` as a known transition tax that retires when the build-fix loop itself ports.
- **`tekhton-legacy.sh:657` line number is approximate.** The actual line may shift by ±5 due to upstream edits. Always grep for the `--diagnose` early-check block: `grep -n -- '--diagnose' tekhton-legacy.sh | head -3`. The block to rewire is the one with `source "${TEKHTON_HOME}/lib/diagnose.sh"` immediately following.
- **The parity gate's normalization rules are sensitive.** Timestamps in `DIAGNOSIS.md` and `data/diagnosis.js` must be stripped before diff (use a `sed` filter or a Go `regexp.ReplaceAll` in the test harness). PIDs in log files same. Absolute paths normalize to `<PROJECT>/...` placeholders. The harness in `tests/test_diagnose_parity.sh` must apply the same normalizer to both sides of the diff.
- **Do NOT modify `internal/errors/`.** m17 owns the classifier; m32.3 only consumes it. A diff in `internal/errors/` during m32.3 work is a sign that scope has crept — back the change out.
- **`docs/go-migration.md` Phase 5 closeout section is operator-facing.** It captures the bash LOC delta, the patch-bump count, notable bugs, and any drift entries opened during the run. Operators read it to understand the migration's velocity. Write it as a retro, not a marketing post.

## Seeds Forward

- **m33 — Migrate command port (next arc):** With diagnose closed, the next portable bash surface is `lib/migrate.sh` + companions. The m32 `_rule_migration_crash` rule already detected migration-backup directories under `MIGRATION_BACKUP_DIR/pre-*`; m33 takes ownership of those backup dirs Go-natively. The diagnose engine continues to surface migration failures via the rule, but the migration code itself moves to `internal/migrate/`.
- **m34 — Health command port:** `lib/health.sh` is the next-most-touched standalone command. Same shape as m32: port the orchestrator + rules + output + (no remediation — health is read-only). The m32 engine pattern (Engine + Rule + Diagnosis types) is reusable; consider extracting a shared `internal/checker/` package if m34 wants to deduplicate.
- **V5 multi-provider remediation policies:** `RemediationPolicy` (m32.3) currently uses `DefaultPolicy()` everywhere. A V5 feature could let `pipeline.conf` declare per-classification policies (e.g. `remediation.transient.max_attempts: 5`). The `Policy` field on `Remediator` is the seam.
- **Dogfooding feedback loop:** Track every bug surfaced during the m32.3 implementation run as a patch bump (`4.32.1`, `4.32.2`, …) with one-line postmortems in `docs/go-migration.md`. m21 had 17 bumps over a similar-sized port; m22 had 9. - **Inline classifier subprocess-spawn cost retirement:** The build-fix-loop exec of `tekhton diagnose classify` is a transition tax. When the build-fix loop itself ports (m37-ish), the classifier call moves back in-process via direct `internal/errors.ClassifyAgent` API. Document this as a deferred optimization in `docs/go-migration.md`.
- **Per-project rule overrides:** A future operator-facing feature could let `pipeline.conf` disable specific diagnose rules (`diagnose.disabled_rules: [security_halt]`). The `rules.Registry.Rules()` API is the seam — a future overlay decorator filters the slice based on config. Designed in m32.2; first operator demand for it will trigger the milestone.
