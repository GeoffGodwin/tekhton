#### Milestone 1.1.1.1.2: Plain Main + Build Verification

Add the `cmd/tekhton/main.go` entry point that prints the version, then verify the binary builds and runs correctly via direct `go build` (no Makefile yet — that lands in 1.1.1.2).

Files to create:
- `cmd/tekhton/main.go`

Acceptance criteria:
- `cmd/tekhton/main.go` declares `package main` with a plain `func main()` (no `init()`, no flag parsing, no subcommand routing).
- The only imports are `fmt` (stdlib) and `github.com/geoffgodwin/tekhton/internal/version`.
- `main()` prints `version.Version` trimmed of trailing whitespace (e.g., via `strings.TrimRight` — if used, add `strings` to the imports) followed by a single newline, then returns (implicit exit 0).
- `go build -o bin/tekhton ./cmd/tekhton` produces an executable at `bin/tekhton`.
- Running `./bin/tekhton` with no arguments writes exactly `dev\n` to stdout and exits 0.
- Still no `go.sum` file exists in the repo root (no third-party dependencies were introduced).
- No file under `lib/`, `stages/`, `prompts/`, or `tools/` is modified.
- The `internal/version/version.go` and `go.mod` files from 1.1.1.1.1 are not modified in this sub-milestone.

Watch For:
- Keep imports limited to `fmt`, `strings` (if used for trimming), and the internal version package. Any third-party import here forces `go.sum` churn that belongs in 1.1.2, not this milestone.
- Trim trailing whitespace at print time even though the `dev` sentinel has none — this defense-in-depth keeps observable behavior identical once 1.1.1.2's Makefile injects a value from `VERSION` (which may have a trailing newline from typical text-editor saves).
- Do not call `os.Exit(0)` explicitly; let `main()` return normally. Explicit `os.Exit` would skip deferred cleanup in any future additions and is needless ceremony here.
- The `bin/` directory is created by `go build -o` — do not pre-create it or add a `.gitkeep`. If `bin/` is not already gitignored, that is a concern for a later milestone, not this one.

Seeds Forward:
- Milestone 1.1.1.2 introduces the Makefile (`build`, `test`, `clean` targets) which wraps the exact `go build -o bin/tekhton ./cmd/tekhton` invocation validated here and adds the ldflags injection that overrides `dev`.
- The `cmd/tekhton/main.go` print contract (trimmed version + newline, exit 0) is the behavioral baseline that 1.1.1.2's smoke test will re-verify after ldflags injection.
