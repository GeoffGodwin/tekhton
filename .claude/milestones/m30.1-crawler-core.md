## Design

### Goal 1 — `internal/crawler/` package shape

```go
// crawler.go — orchestrator
package crawler

type Options struct {
    ProjectDir   string
    BudgetChars  int
    IndexDir     string             // defaults to ProjectDir + "/.claude/index"
    Detector     *detect.Detector   // m29 import; nil-tolerant (falls back to defaults)
    Writer       Writer             // os-backed by default; tests inject a fake
}

type Result struct {
    IndexDir       string
    FileCount      int
    TotalLines     int
    TreeLines      int
    Manifests      []Manifest
    KeyDeps        []Dependency
    DocQuality     int
    Errors         []error            // non-fatal per-step issues
}

func Crawl(ctx context.Context, opts Options) (*Result, error) {
    // 1. Resolve options + ensure index dir exists.
    // 2. Single file-list call (covers all phases — preserves crawler.sh:63 M67 fix).
    // 3. doc-quality assessment via opts.Detector.AssessDocQuality (m29).
    // 4. Phase 1: emit each artifact in fixed order (tree, inventory, deps, configs,
    //    tests, samples, meta) — meta MUST be last because it reads counts from
    //    inventory.jsonl (preserves crawler_emit.sh:200 ordering invariant).
    // 5. Phase 2: regenerate view (delegates to internal/index — handled by m31+,
    //    for now exec `tekhton index view` if present, else log a TODO).
    // Return Result + errors.
}
```

Atomic-write pattern preserved across all emitters: write to a temp file in `indexDir`, then `os.Rename` to the final path. Mirrors the bash `mktemp + mv` pattern (e.g. `crawler.sh:25-28`, `crawler_emit.sh:213-216`). The temp file lives in `indexDir` (not `/tmp`) so the rename is same-filesystem atomic — preserve this; do not move temp files to the OS temp dir.

### Goal 2 — Seven manifest parsers, ported preserving rule ordering

The seven parsers are heuristic-heavy. Each MUST be ported preserving exact rule ordering — drift here surfaces as a single-package wrong-version output that is silent without the parity gate. Key invariants per parser:

| Parser | Rule-order invariant |
|--------|----------------------|
| `_parse_node_deps` | Uses `_extract_json_keys` (from `internal/detect` post-m29) for both `"dependencies"` and `"devDependencies"`. Both arrays merge into one output. Order: `dependencies` first, `devDependencies` second. |
| `_parse_cargo_deps` | `[dependencies]` and `[dev-dependencies]` sections only. Simple form `crate = "ver"` checked *before* table form `crate = { version = "x" }`. Section-end `[` check happens *after* the in-deps flag — drift caught by the parity test. |
| `_parse_python_deps` | Reads `[project] dependencies = [ "..." ]` array. The `in_deps` toggle resets on `]`. Constraint stripped from package name via `pkg%%[^a-zA-Z0-9_-]*`. |
| `_parse_go_deps` | Reads `require ( ... )` block. Module name = first whitespace-delimited token, version = second. `short_mod = mod##*/` for the annotation lookup. |
| `_parse_gemfile_deps` | Line starts with `gem ` (whitespace tolerant). Gem name = first single/double-quoted string; version = second optional quoted string. |
| `_parse_gradle_deps` | Lines containing `implementation|api|testImplementation|compileOnly`. Dep string = first quoted token. Annotation key = last `:`-separated segment. |
| `_parse_pom_deps` | Stateful `<groupId>` / `<artifactId>` pair detection. Output `group:artifact` after both seen, reset both to empty. |

Each parser has a `parseXDeps_test.go` table-driven scenario list with at least:
- Empty manifest (graceful zero output).
- Single dependency, simple form.
- Single dependency, table/complex form (where applicable).
- Multiple dependencies, mixed normal + dev.
- Malformed lines (trailing whitespace, missing quote — parser must skip not crash).
- Comment-only manifest (no output).

### Goal 3 — `_annotate_package` lookup table

`crawler_deps.sh:10-33` is a 23-arm `case` statement mapping well-known package names to short purpose strings. Port verbatim as a `map[string]string` in `annotations.go`:

```go
var packagePurposes = map[string]string{
    "express": "Web framework", "koa": "Web framework", /* ... */
    "react": "Frontend framework", "preact": "Frontend framework", /* ... */
    // ... continued
}

func annotatePackage(pkg string) string {
    if p, ok := packagePurposes[pkg]; ok {
        return p
    }
    // Glob-pattern arms (@angular/*, drizzle*, spring-boot*) handled by a
    // small slice of {pattern, purpose} entries.
    for _, entry := range packagePurposeGlobs {
        if matched, _ := path.Match(entry.pattern, pkg); matched {
            return entry.purpose
        }
    }
    return ""
}
```

The bash case-statement glob patterns (`@angular/*`, `drizzle*`, `spring-boot*`) port to a `path.Match` loop. The `echo) echo "HTTP router"` arm is intentional — the bash `case` allows `echo` (the literal package name "echo") as an arm; preserve in the Go map.

### Goal 4 — Content sampling: priority order + budget allocator

`_crawl_sample_files` and `_emit_sampled_files` share the candidate ordering. Both emit the same priority sequence:

1. README (one of `README.md`, `README.rst`, `README`, `README.txt`).
2. Entry points (`main.py`, `app.py`, `index.ts`, `index.js`, `main.ts`, `main.go`, `main.rs`, `lib.rs`, `src/main.rs`, `src/lib.rs`, `src/index.ts`, `src/index.js`, `src/app.ts`, `src/app.js`, `src/main.py`, `cmd/main.go`).
3. Primary manifest (`package.json`, `Cargo.toml`, `pyproject.toml`, `go.mod`, `Gemfile`, `pubspec.yaml`, `composer.json`).
4. Architecture docs (`ARCHITECTURE.md`, `CONTRIBUTING.md`, `$DESIGN_FILE`, `docs/ARCHITECTURE.md`, `docs/design.md`).
5. First test file (regex `\.(test|spec)\.[^.]+$|_test\.[^.]+$`).
6. First source file (regex `^src/.*\.(py|ts|js|go|rs|java|rb)$`).

Port verbatim. The Go `Sample()` function takes the file list and the budget, returns an ordered slice of `Sample{Path, Content, Chars}`. The budget allocator from `crawler.sh:_budget_allocator` (fixed-percentage allocation 10/15/10/5/5 with surplus reflow into a 55% sampled-files base) ports to `budgetAllocator(total, sizes...) int`. Identical math, same surplus reflow rule.

**Sample storage:** the `stored_name = f//\//__` translation (`crawler_content.sh:199`) replaces `/` with `__` so the sample file lives flat under `samples/`. Port: `storedName := strings.ReplaceAll(rel, "/", "__") + ".txt"`. Round-trip tested in `content_test.go`.

**Large-file truncation:** `>1000 lines → first 50 + last 20 with omission marker`. Char-budget truncation cuts at the last newline (`content%$'\n'*`). Port: `strings.LastIndexByte(content[:budget], '\n')`. Off-by-one is a parity-test catch.

## Watch For

- **Artifact schema is the contract.** Init, scout, rescan (m30.2), and downstream agents consume `.claude/index/*.json` by *shape*. A field rename, numeric-format change, or key-order change in any emitter ripples into every consumer. The parity gate's byte-level golden files exist to catch this — do not weaken the gate to "fields present" only. If the Go JSON marshaller emits keys in different order than the bash hand-formatted printf, you'll need an explicit field-order preserving emitter (a struct with `json:"key"` tags has Go-determined order; if the order differs from bash, write the JSON by hand to preserve byte-identical output).
- **`crawler_deps.sh` rule-order is load-bearing.** The simple-form-before-table-form check in Cargo parsing, the `[dependencies]` vs `[dev-dependencies]` section detection happening before the section-end `[` check, the `<groupId>`/`<artifactId>` stateful pair detection in pom.xml — each is a specific ordering that the parity test will catch if drifted. Port the regex/match logic in the same source order as the bash; do not "tidy up" the conditional structure.
- **`_emit_meta_json` MUST run last.** `meta.json` reads `file_count` and `total_lines` *from the just-written `inventory.jsonl`* (`crawler_emit.sh:200-206`). Reordering the emit phase to write meta before inventory produces a `file_count: 0` regression that is silent without the parity test. Enforce ordering in `Crawl()` by making the emitters dependent (each takes a typed result from the previous step, not an arbitrary args list).
- **Crawler is read-only on the project tree, write-only to `.claude/index/`.** This separation must be enforced explicitly in Go — no package under `internal/crawler/` may take a write handle to any path outside `${IndexDir}`. A `fakeWriter` in tests should record every Write call and assert the path prefix matches `${IndexDir}`. The bash version trusts itself; the Go port should not.
- **Detect Port (m29) hard dependency.** `_extract_json_keys` must be available as `detect.ExtractJSONKeys` post-m29. If m29 ships with a different API surface (e.g. returning `[]string` of "key=value" rather than `[]Pair{Key, Value}`), the port is mechanical but requires a thin adapter. Do NOT re-implement JSON key extraction inside `internal/crawler/` — duplication is the trap.
- **The 300-line bash file ceiling does NOT carry over.** `crawler_inventory.sh` and `crawler_inventory_emitters.sh` are bash-split for size management, not domain reasons. Merge them into one Go file (`internal/crawler/inventory.go` or split across `inventory.go` + `emit.go` by *domain* — emit functions in emit.go, inventory-building logic in inventory.go). DESIGN_v4.md §Package Layout calls this out explicitly.
- **Rescan stays bash until m30.2.** Do NOT preemptively port rescan in m30.1 to "save a milestone." That breaks the dogfooding contract (m30.1 must be independently dogfood-able) and conflates two work streams.
