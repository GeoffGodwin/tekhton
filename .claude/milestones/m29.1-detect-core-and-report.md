## Design

### Sequencing note

m29.1 ports a *subset* of the detect subsystem: the engine, the report formatter, and one of the nine detectors (`languages`). The remaining eight detectors stay in bash through m29.1's close. This is unusual relative to m22 (which ported the whole preflight subsystem in one shot) but necessary here because the detect subsystem is ~2,666 lines vs preflight's ~1,500 — a one-shot port produced m23's partial cascade and we are explicitly designing around that experience.

The bash report formatter (`lib/detect_report.sh`) stays in place through m29.1's close. Every existing caller still sources bash. The Go engine ships in parallel but no caller invokes it yet — `tekhton detect summary` is the only entry point and it is `Hidden`, intended for parity-gate use only during m29.1. m29.2 will atomically cut every caller over and delete the bash.

### Goal 1 — `internal/detect/detect.go` engine + interface

```go
package detect

import "context"

// Detector is the contract every domain detector implements.
// All detectors are read-only — they MUST NOT write to the filesystem.
type Detector interface {
    Name() string
    Run(ctx context.Context, in *Input) (*Result, error)
}

// Input carries the project directory plus the pre-computed languages/
// frameworks from the languages detector. Later detectors (commands,
// services, infrastructure) consume those to disambiguate. The Engine
// guarantees languages is populated before any other detector runs.
type Input struct {
    ProjectDir string
    Languages  []Language
    Frameworks []Framework
}

type Language struct {
    Name       string // "typescript", "go", "python", …
    Confidence string // "high" | "medium" | "low"
    Manifest   string // "package.json", "go.mod", …
}

type Framework struct {
    Name     string
    Language string
    Evidence string
}

type Result struct {
    Detector string                 // Name() of the producing detector
    Findings []map[string]string    // Flat per-row findings (matches bash pipe-delimited shape)
}

type Engine struct {
    detectors []Detector            // Registration order = execution order = report order
    cache     map[string]*Result    // Per-run cache keyed by Detector.Name()
}

func New() *Engine {
    return &Engine{cache: make(map[string]*Result)}
}

func (e *Engine) Register(d Detector) { e.detectors = append(e.detectors, d) }

func (e *Engine) Run(ctx context.Context, projectDir string) (*Summary, error) {
    in := &Input{ProjectDir: projectDir}
    s := &Summary{ProjectDir: projectDir}

    // Languages runs first; later detectors consume in.Languages.
    for _, d := range e.detectors {
        if d.Name() == "languages" {
            r, err := d.Run(ctx, in)
            if err != nil { return nil, err }
            e.cache[d.Name()] = r
            in.Languages = languagesFromResult(r)
            in.Frameworks = frameworksFromResult(r)
            s.Languages = in.Languages
            s.Frameworks = in.Frameworks
        }
    }

    for _, d := range e.detectors {
        if d.Name() == "languages" { continue }
        r, err := d.Run(ctx, in)
        if err != nil { return nil, err }
        e.cache[d.Name()] = r
        s.attach(d.Name(), r)
    }

    return s, nil
}
```

`Summary` is the unified output struct rendered by `report.go` as markdown or by the CLI as JSON. It has one field per detector domain (`Languages []Language`, `Frameworks []Framework`, `Commands []Command`, `Workspaces []Workspace`, `Services []Service`, `CI []CIConfig`, `Infrastructure []InfraItem`, `TestFrameworks []TestFW`, `DocQuality *DocQuality`, `AIArtifacts []AIArtifact`). m29.1 populates `Languages` + `Frameworks`; m29.2 fills the rest.

The registration-order-determines-execution-order invariant matches the m22 `internal/preflight/orchestrator.go` pattern. m29.2 adds a `TestRegistrationOrder` test that fails red if a future edit reorders the slice.

### Goal 2 — `internal/detect/report.go` markdown formatter

A byte-for-byte port of `lib/detect_report.sh::format_detection_report` (lines 17-86). The shape:

```go
func Render(s *Summary) string {
    var b strings.Builder
    fmt.Fprintln(&b, "## Tech Stack Detection Report")
    fmt.Fprintln(&b)
    fmt.Fprintf(&b, "### Project Type: %s\n\n", s.ProjectType())

    renderLanguages(&b, s.Languages)
    renderFrameworks(&b, s.Frameworks)
    renderCommands(&b, s.Commands)
    renderEntryPoints(&b, s.EntryPoints)
    renderWorkspaces(&b, s.Workspaces)
    renderServices(&b, s.Services)
    renderCI(&b, s.CI)
    renderInfrastructure(&b, s.Infrastructure)
    renderTestFrameworks(&b, s.TestFrameworks)
    renderDocQuality(&b, s.DocQuality)
    return b.String()
}
```

Each `render*` function mirrors a `_format_<section>` bash function from `detect_report.sh:121-225`. The Go and bash outputs must be byte-identical (modulo whitespace normalization in the parity gate's diff step). m29.1's parity gate covers `renderLanguages` + `renderFrameworks` only (the others are stubs that emit `"(none detected)"` since m29.1's Go engine doesn't populate those fields yet).

### Goal 3 — `internal/detect/languages.go` first detector

Ports `detect_languages` (lib/detect.sh:21-169), `detect_frameworks` (lib/detect.sh:247-329), and `detect_ui_framework` (lib/detect.sh:331-456) as a single `Detector` implementation. Three-pass shape:

```go
type LanguagesDetector struct{}

func (LanguagesDetector) Name() string { return "languages" }

func (LanguagesDetector) Run(ctx context.Context, in *Input) (*Result, error) {
    // Pass 1: manifest detection. Walk the project root for package.json,
    // go.mod, Cargo.toml, pyproject.toml, etc. Match the exact file-existence
    // checks at lib/detect.sh:27-71. Populate lang_manifest map.
    manifests := detectManifests(in.ProjectDir)

    // Pass 2: source-file counting (top 2 levels, excluding _DETECT_EXCLUDE_DIRS).
    // Mirror _count_source_files at lib/detect.sh:208-245.
    sourceCounts := countSourceFiles(in.ProjectDir)

    // Pass 3: merge + assign confidence per the bash rules:
    //   - manifest + source files: high
    //   - manifest OR source files only: medium
    //   - <5 source files, no manifest: low
    languages := mergeAndScore(manifests, sourceCounts)

    // Frameworks: mirror lib/detect.sh:247-329. Depends on languages.
    frameworks := detectFrameworks(in.ProjectDir, languages)

    // UI frameworks: mirror lib/detect.sh:331-456. Depends on frameworks.
    uiFramework := detectUIFramework(in.ProjectDir, frameworks)
    if uiFramework != nil {
        frameworks = append(frameworks, *uiFramework)
    }

    return resultFromLanguages(languages, frameworks), nil
}
```

The `_DETECT_EXCLUDE_DIRS` regex from `lib/detect.sh:13` ports verbatim as a Go `[]string` exclusion list — keep the same names, same order, so future drift is grep-able.

### Goal 4 — `cmd/tekhton/detect.go` Cobra surface

Mirror m22's `tekhton preflight` shape exactly:

```go
var detectCmd = &cobra.Command{
    Use:    "detect",
    Short:  "Detect project tech stack and emit structured findings",
    Hidden: true,
}

var detectSummaryCmd = &cobra.Command{
    Use:   "summary",
    Short: "Run all detectors and emit a unified summary",
    RunE:  runDetectSummary,
}

func init() {
    detectSummaryCmd.Flags().Bool("json", false, "Emit JSON instead of markdown")
    detectSummaryCmd.Flags().Bool("markdown", false, "Emit markdown (default)")
    detectSummaryCmd.Flags().String("project-dir", "", "Project directory (defaults to $PWD)")
    detectCmd.AddCommand(detectSummaryCmd)
    rootCmd.AddCommand(detectCmd)
}

func runDetectSummary(cmd *cobra.Command, _ []string) error {
    dir, _ := cmd.Flags().GetString("project-dir")
    if dir == "" { dir, _ = os.Getwd() }

    e := detect.New()
    e.Register(detect.LanguagesDetector{})
    // m29.2 will register the remaining eight detectors here.

    s, err := e.Run(cmd.Context(), dir)
    if err != nil { return err }

    asJSON, _ := cmd.Flags().GetBool("json")
    if asJSON {
        return json.NewEncoder(cmd.OutOrStdout()).Encode(s)
    }
    fmt.Fprint(cmd.OutOrStdout(), detect.Render(s))
    return nil
}
```

`Hidden: true` matches `tekhton finalize` + `tekhton preflight` — the standalone invocation is a developer/debug lever; user-facing callers go through bash today and through Go callers post-m29.2.

#!/usr/bin/env bash
set -euo pipefail
fail=0
for fixture in monorepo-pnpm polyglot-services ai-heavy-mess; do
    bash_baseline="tests/testdata/detect/baselines/${fixture}.md"

### Goal 6 — Read-only contract test

`internal/detect/readonly_test.go`:

```go
func TestReadOnlyContract(t *testing.T) {
    forbidden := []string{
        `os\.Create\b`, `os\.WriteFile\b`, `ioutil\.WriteFile\b`,
        `os\.OpenFile\b.*O_WRONLY`, `os\.OpenFile\b.*O_CREATE`,
        `os\.Remove\b`, `os\.RemoveAll\b`, `os\.MkdirAll\b`, `os\.Rename\b`,
    }
    files, _ := filepath.Glob("*.go")
    for _, f := range files {
        if strings.HasSuffix(f, "_test.go") { continue }
        body, _ := os.ReadFile(f)
        for _, pat := range forbidden {
            if regexp.MustCompile(pat).Match(body) {
                t.Errorf("read-only contract violation: %s matches %s", f, pat)
            }
        }
    }
}
```

## Watch For

- **Read-only contract is a package boundary, not a code review item.** Every detector implementation in m29.2 will be expected to pass `internal/detect/readonly_test.go`. Get the test green at m29.1 close; if a future detector needs to write (it shouldn't, but if), the discussion happens in code review against a red test, not silently. The CLI surface (`cmd/tekhton/detect.go`) writes to `os.Stdout` only — package-internal code must not.
- **Dogfood stability invariant.** m29.1 adds Go code + tests + fixtures + a baseline capture. No bash files change. No bash callers change. tekhton-stable can rebuild after m29.1 with full confidence. If a regression is reported between m29.1 close and m29.2 start, the bug is in the Go side and the bash side is the rollback path — keep the bash subsystem intact through this milestone exactly so this rollback is free.
- **The languages-first invariant must be load-bearing.** Several later detectors (`commands`, `services`, `infrastructure`) consume `Input.Languages` to disambiguate (e.g. "this `package.json` is TypeScript not JavaScript because tsconfig.json exists"). m29.1's engine guarantees `languages` runs first; m29.2 will rely on that. Document the invariant in the `Engine.Run()` doc comment AND assert it in `TestLanguagesFirstInvariant` so a future "let me reorder the detectors for clarity" PR fails red.
- **Baseline capture is a one-time gate.** The `scripts/capture-detect-baselines.sh` script regenerates the baselines from the current bash tree. Run it ONCE at m29.1 close. After m29.1 closes, the baselines are frozen. m29.2 must match them byte-for-byte from the Go engine; a mismatch means the Go port diverged, not that the baseline is wrong. If the bash side legitimately needs to change after m29.1, that's a new milestone (with a fresh baseline capture) — don't silently regen.
- **The report formatter must mirror bash's whitespace exactly.** `lib/detect_report.sh:36-43` emits `echo ""` between sections — that's a literal empty line. The Go port must emit `fmt.Fprintln(&b)` (or equivalent) in the same places. The parity gate's whitespace normalization is intentionally pessimistic; a missing blank line still fails. Use the bash baseline as the byte-level reference, not a "looks right" eyeballing.
- **`detect_ai_artifacts.sh` and the seven other domain detectors stay bash through m29.1.** The Go `Summary` struct has fields for their outputs (`AIArtifacts []AIArtifact`, etc.) but those fields are zero-valued until m29.2 wires them up. The bash report formatter (still the canonical path through m29.1) handles those sections; the Go `report.go` just emits `"(none detected)"` placeholders. The parity gate only asserts on the Languages/Frameworks/Project Type sections in m29.1 — the rest of the rendered report is identical because both sides defer to bash for them.
