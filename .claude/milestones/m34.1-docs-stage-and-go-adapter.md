## Design

### Sequencing note

Within m34.1 the work order matters:

1. **Land the `StageDef.GoImpl` field + dispatch wedge first.** Until the dispatcher knows how to route to a Go stage, the docs port has nowhere to plug in. This step is additive and behavior-preserving — every existing test continues to pass because every existing `StageDef` has a nil `GoImpl`.
2. **Land `internal/stages/docs/` second, with `DefaultStageDefs[StageDocs].GoImpl` still nil.** Until the package compiles cleanly and its tests pass, do not flip the dispatch. Wire it via `helpers_test.go` first.
3. **Flip the dispatch (set `GoImpl: docs.RunStage`) third.** From this commit forward, the docs stage runs in Go. The bash file is still on disk so `tekhton --diagnose` and any operator path that sources it directly keeps working.
4. **Capture the v4-stage-port baseline tag fourth.** `git tag v4.33.99-stage-baseline-docs` against a tree that still has `stages/docs.sh` + `lib/docs_agent.sh` checked in, before the delete commit. Used by the parity harness as the bash reference.
5. **Delete the bash files fifth.** `git rm stages/docs.sh lib/docs_agent.sh` in one commit; update `DefaultStageDefs[StageDocs].Helpers` to drop the `lib/docs_agent.sh` entry in the same commit.
6. **Wire the parity harness + wedge-audit + docs sixth.** Bump VERSION last.

### Goal 1 — `StageImpl` type + `StageDef.GoImpl` field

Add to `internal/stagerunner/helpers.go` at the top:

```go
// StageImpl is the entry-point signature every Go-native stage exports. The
// dispatcher in BashAdapter.Run prefers a non-nil StageDef.GoImpl over the
// bash Script path.
type StageImpl func(ctx context.Context, req *proto.StageRequestV1) (*proto.StageResultV1, error)
```

Extend `StageDef` (additive):

```go
type StageDef struct {
    Script  string
    Helpers []string
    GoImpl  StageImpl  // NEW (m34.1): when non-nil, dispatcher routes here.
}
```

Add `helpers_test.go` validation:

```go
func TestDefaultStageDefs_NoDoubleWiredEntry(t *testing.T) {
    // An entry with both Script != "" AND GoImpl != nil is a misconfiguration —
    // the dispatcher prefers GoImpl, the Script will never run, and the
    // intent is ambiguous. We let Script stay set for the audit-trail-of-
    // deleted-file rationale (see m34 parent Goal 5), so this test allows
    // Script set + GoImpl set together — but if a future stage attempts to
    // run BOTH (e.g. GoImpl returns and the bash path then also runs), the
    // dispatcher logic catches it. The test asserts only the documented
    // precedence.
    for name, def := range DefaultStageDefs {
        if def.GoImpl == nil && def.Script == "" {
            t.Fatalf("stage %q has neither GoImpl nor Script set", name)
        }
    }
}
```

### Goal 2 — `BashAdapter.Run` dispatch wedge

Insert near the top of `BashAdapter.Run` (after the request validate, before the bash work):

```go
// m34.1: Go-native dispatch wedge. When the stage has a Go entry point,
// skip the bash sourcing chain entirely.
if def.GoImpl != nil {
    return a.runGo(ctx, req, def)
}
```

New helper:

```go
// runGo dispatches to a Go-native stage. The Now hook is honored so tests
// can pin DurationSec; otherwise the stage's own duration field (if set)
// is preserved.
func (a *BashAdapter) runGo(ctx context.Context, req *proto.StageRequestV1, def StageDef) (*proto.StageResultV1, error) {
    now := a.Now
    if now == nil {
        now = time.Now
    }
    start := now()
    res, err := def.GoImpl(ctx, req)
    if res != nil {
        if res.DurationSec == 0 {
            res.DurationSec = int(now().Sub(start).Seconds())
        }
        res.EnsureProto()
        if res.Stage == "" {
            res.Stage = req.Stage
        }
    }
    return res, err
}
```

Test case in `adapter_test.go`:

```go
func TestBashAdapter_Run_GoDispatch(t *testing.T) {
    called := false
    a := &BashAdapter{
        Stages: map[string]StageDef{
```

### Goal 3 — `internal/stages/docs/` package contents

#### `stage.go` — entry point (port of `stages/docs.sh:run_stage_docs`)

```go
// Package docs implements the m75-lineage docs-agent stage. M34.1 ports it
// from stages/docs.sh + lib/docs_agent.sh.
package docs

func RunStage(ctx context.Context, req *proto.StageRequestV1) (*proto.StageResultV1, error) {
    log := staglog.New(req)

    log.Header(req.Stage)

    // Gate 1: disabled.
    if env.Bool("DOCS_AGENT_ENABLED", false) == false {
        log.Info("[docs] Docs agent disabled (DOCS_AGENT_ENABLED=false). Skipping.")
        return pass(req, "disabled"), nil
    }

    // Gate 2: --skip-docs flag.
    if env.Bool("SKIP_DOCS", false) {
        log.Info("[docs] Docs stage skipped (--skip-docs). Skipping.")
        return pass(req, "skip-flag"), nil
    }

    // Gate 3: public-surface check.
    if shouldSkip(ctx, log) {
        return pass(req, "no-public-surface-change"), nil
    }

    // Prepare template variables and render the prompt.
    vars, err := prepareTemplateVars(req)
    if err != nil {
        log.Warn(fmt.Sprintf("[docs] prepare vars: %v", err))
        return pass(req, "prepare-failed"), nil
    }
    promptText, err := prompt.Render(promptsDir(req), "docs_agent", vars)
    if err != nil {
        log.Warn(fmt.Sprintf("[docs] render prompt: %v", err))
        return pass(req, "prompt-failed"), nil
    }

    // Invoke the docs agent (best-effort — failures are warnings, not failures).
    model := env.String("DOCS_AGENT_MODEL", "claude-haiku-4-5-20251001")
    turns := env.Int("DOCS_AGENT_MAX_TURNS", 10)
    tools := env.String("AGENT_TOOLS_CODER", "Read Write Edit Glob Grep Bash")
    log.Info(fmt.Sprintf("[docs] Invoking docs agent (model=%s, turns=%d)...", model, turns))

    sup := supervisor.New(nil, nil) // causal/state seams from req context — wired by caller
    promptFile, cleanup, err := writePromptTmpFile(promptText)
    if err != nil {
        log.Warn(fmt.Sprintf("[docs] write prompt: %v", err))
        return pass(req, "prompt-write-failed"), nil
    }
    defer cleanup()

    agentReq := (&supervisor.AgentSpec{
        Label: "Docs", Model: model, MaxTurns: turns,
        PromptFile: promptFile, WorkingDir: req.EnvOverrides["PROJECT_DIR"],
        Env: map[string]string{}, // tools threaded via AllowedTools
    }).ToProto()
    agentReq.AllowedTools = tools

    agentRes, agentErr := sup.Run(ctx, agentReq)
    if agentErr != nil || (agentRes != nil && agentRes.Outcome != proto.OutcomeSuccess) {
        log.Warn("[docs] Docs agent run failed — continuing pipeline without docs updates.")
        return pass(req, "agent-failed"), nil
    }

    log.Info(fmt.Sprintf("[docs] Docs agent finished. Report: %s", env.String("DOCS_AGENT_REPORT_FILE", "")))
    return &proto.StageResultV1{
        Proto: proto.StageResultProtoV1, Stage: req.Stage, Verdict: proto.VerdictPass,
        ExitReason: "agent-completed", AgentCalls: 1,
    }, nil
}

func pass(req *proto.StageRequestV1, reason string) *proto.StageResultV1 {
    return &proto.StageResultV1{
        Proto: proto.StageResultProtoV1, Stage: req.Stage,
        Verdict: proto.VerdictSkip, ExitReason: reason,
    }
}
```

The docs stage **never returns verdict=fail** (matches the bash semantics: the bash function ends with `return 0` on every branch). Either it ran successfully (verdict=pass) or it skipped (verdict=skip). Any internal error becomes a verdict=skip with an exit_reason that identifies which step failed.

#### `prepare.go` — port of `_docs_prepare_template_vars`

```go
func prepareTemplateVars(req *proto.StageRequestV1) (map[string]string, error) {
    vars := map[string]string{}

    // CODER_SUMMARY_CONTENT
    summaryFile := env.String("CODER_SUMMARY_FILE", ".tekhton/CODER_SUMMARY.md")
    if b, err := safeReadFile(filepath.Join(req.EnvOverrides["PROJECT_DIR"], summaryFile)); err == nil {
        vars["CODER_SUMMARY_CONTENT"] = string(b)
    }

    // DOCS_GIT_DIFF_STAT
    if out, err := exec.Command("git", "diff", "--stat", "HEAD").Output(); err == nil && len(out) > 0 {
        vars["DOCS_GIT_DIFF_STAT"] = string(out)
    } else if out, err := exec.Command("git", "diff", "--cached", "--stat").Output(); err == nil {
        vars["DOCS_GIT_DIFF_STAT"] = string(out)
    }

    // DOCS_SURFACE_SECTION (extracted from CLAUDE.md)
    rulesFile := env.String("PROJECT_RULES_FILE", "CLAUDE.md")
    if b, err := os.ReadFile(filepath.Join(req.EnvOverrides["PROJECT_DIR"], rulesFile)); err == nil {
        vars["DOCS_SURFACE_SECTION"] = extractDocResponsibilities(string(b))
    }

    // Plain pass-throughs
    vars["DOCS_README_FILE"] = env.String("DOCS_README_FILE", "README.md")
    vars["DOCS_DIRS"] = env.String("DOCS_DIRS", "docs/")
    vars["DOCS_AGENT_REPORT_FILE"] = env.String("DOCS_AGENT_REPORT_FILE", filepath.Join(env.String("TEKHTON_DIR", ".tekhton"), "DOCS_AGENT_REPORT.md"))

    return vars, nil
}
```

#### `skip.go` — port of `docs_agent_should_skip` + helpers from `lib/docs_agent.sh`

```go
// shouldSkip returns true when the docs stage can short-circuit. Mirrors
// docs_agent_should_skip in lib/docs_agent.sh: no changed files → skip; no
// CLAUDE.md section → run (false-negative skip is worse than false-positive
// run); changed files don't intersect surface patterns → skip.
func shouldSkip(ctx context.Context, log staglog.Logger) bool {
    changed, err := changedFiles()
    if err != nil || len(changed) == 0 {
        log.Info("[docs] No changed files detected. Skipping docs agent.")
        return true
    }

    rulesFile := env.String("PROJECT_RULES_FILE", "CLAUDE.md")
    raw, err := os.ReadFile(rulesFile)
    if err != nil {
        log.Info("[docs] No Documentation Responsibilities section in CLAUDE.md. Running agent.")
        return false
    }
    patterns := extractPublicSurface(string(raw))
    if len(patterns) == 0 {
        log.Info("[docs] No Documentation Responsibilities section in CLAUDE.md. Running agent.")
        return false
    }

    if filesMatchSurface(changed, patterns) {
        return false
    }
    log.Info("[docs] No public-surface files changed. Skipping docs agent.")
    return true
}

// extractDocResponsibilities, extractPublicSurface, filesMatchSurface — direct
// ports of the corresponding _docs_* bash helpers. Regex-based but the
// patterns are simple enough that pure-Go string/regexp ops suffice.
```

### Goal 4 — `staglog` helper (shared by m34.1 through m39)

The bash stage scripts use `log`, `warn`, `success`, and `header` from `lib/common.sh`, which the Go-side runner output (`internal/runner/output.go`, the home of `log.Info`/etc.) covers most of — but stage scripts also need `stage_header "$pos" "$count" "Name"` for the "[2/5] Docs" prefix. M34.1 introduces `internal/stages/staglog/` as a 50-line wrapper:

```go
package staglog

type Logger interface {
    Header(stage string)            // prints "[pos/count] StageName" matching stage_header
    Info(msg string)
    Warn(msg string)
    Success(msg string)
}

func New(req *proto.StageRequestV1) Logger { ... }
```

m35-m39 reuse this; if a future stage wants a richer API the package extends. Design call: keep it minimal in m34.1 so the API surface is small and future-evolvable.

### Goal 7 — Parity harness (`tests/test_stage_port_parity.sh`)

The harness drives `tekhton run --stage docs --project-dir <fixture>` against each scenario and diffs the result envelope (after normalization). For m34.1 it ships with two scenarios:

| Scenario | Fixture | Expected verdict | Notes |
|----------|---------|------------------|-------|
| `docs-disabled` | Empty project, `DOCS_AGENT_ENABLED=false` | skip / disabled | Asserts the early gate fires identically to bash. |
| `docs-no-surface` | Project with `CLAUDE.md` containing Documentation Responsibilities section and changed files that don't match patterns | skip / no-public-surface-change | Asserts `shouldSkip` byte-for-byte matches the bash decision. |

A third scenario (`docs-run`) requires a live agent and ships in m34.1 as a `make dogfood` target rather than CI test — running the actual docs agent in CI is too flaky (model availability, quota).

Baseline-capture protocol: before any Go work starts on m34.1, run each scenario against the v3-bash docs stage and capture the result envelope to `internal/stages/docs/testdata/golden/<scenario>.json`. After the port, the harness reads the same fixtures and diffs.

Normalization rules (shared with future stage milestones):

- `duration_sec` zeroed in both sides of diff.
- Timestamps in any reports stripped via `sed 's/[0-9]\{4\}-[0-9]\{2\}-[0-9]\{2\}T[0-9:]*Z/<TS>/g'`.
- Absolute paths normalized to `<PROJECT>` placeholders.

`Makefile` wires the harness into `dogfood`:

```make
dogfood: ... test_stage_port_parity
test_stage_port_parity:
	bash tests/test_stage_port_parity.sh
```

## Watch For

- **`BashAdapter.Run` must continue to dispatch every un-ported stage correctly.** Intake, coder, security, review, tester all stay bash. The dispatch wedge is the ONLY behavioral change to `BashAdapter.Run` in m34.1; if a stage's `GoImpl` is nil, the existing path runs untouched. Verify with a smoke test that runs intake through the modified adapter against a fixture project and asserts the bash subprocess actually spawned (e.g. via a recording `BashBin` that writes its invocation to a tempfile).
- **The docs stage is gated by `DOCS_AGENT_ENABLED=true` and is OFF by default in production.** This makes the port less risky (no production traffic on day 1) but also means unit tests + the dogfood scenario are the only signal until an operator opts in. Cover both the disabled path (`verdict=skip, exit_reason="disabled"`) and the run path (full agent invocation) in m34.1's tests; do not rely on production telemetry to surface bugs.
- **Drop `Helpers: ["lib/docs_agent.sh"]` from `DefaultStageDefs[StageDocs]` in the same commit that deletes the file.** Leaving it in the helpers slice after the file deletes would cause any future caller that bypasses the `GoImpl` dispatch (e.g. a test that explicitly sets `GoImpl: nil` for debugging) to crash with "no such file" when the BashAdapter tries to source it.
- **Keep `Script: "stages/docs.sh"` set on the docs entry in `DefaultStageDefs`.** The runtime never resolves the path because `GoImpl` short-circuits first; the path remains as an audit-trail signal. A future m40 cleanup milestone can null it once every stage has ported.
- **Capture v3-bash baselines BEFORE deleting the bash files.** Tag `v4.33.99-stage-baseline-docs` at the pre-delete commit. The parity harness's golden files in `internal/stages/docs/testdata/golden/` come from running the bash stage against the fixture projects under that tag.
- **The docs agent's "best-effort" semantics MUST be preserved.** Every branch of bash `run_stage_docs` ends with `return 0`; the Go port mirrors this with `verdict=skip` (instead of `verdict=fail`) on any internal error. A test that simulates `supervisor.Run` returning an error asserts the result's `Verdict == proto.VerdictSkip`.
- **The `prompt.Render` API takes a `promptsDir`, but the bash side just calls `render_prompt "docs_agent"` with no explicit dir.** Resolve `promptsDir` from `${TEKHTON_HOME}/prompts/` (matches the bash convention) — wire this through `req.EnvOverrides["TEKHTON_HOME"]` or fall back to `os.Getenv("TEKHTON_HOME")`. Document the fallback in `internal/stages/docs/stage.go`.
- **`internal/stages/staglog` is a tiny shared dependency — keep its API minimal in m34.1.** The bash side only uses four functions (`log`, `warn`, `success`, `header`). Don't add `error`, `debug`, or level filtering in m34.1 even if m35 might want them; let m35 extend the package when the need is concrete.

## Seeds Forward

- **m34.2 — Cleanup stage port:** Inherits every artifact from m34.1: `StageDef.GoImpl` field, `BashAdapter` dispatch wedge, `internal/stages/<name>/` layout, `staglog` helper, parity harness shape. M34.2's design narrative is mostly "apply m34.1's pattern to the cleanup stage" plus the resurrection of the four missing `internal/notes/` cleanup helpers.
- **m35-m39 — Intake / coder / security / review / tester ports:** All inherit the same pattern. Each port becomes (1) port stage logic to `internal/stages/<name>/`, (2) wire `DefaultStageDefs[<name>].GoImpl`, (3) drop the entry's `Helpers` slice, (4) delete the bash file(s), (5) extend `tests/test_stage_port_parity.sh` with new scenarios, (6) wedge-audit append. The pattern document at `docs/go-migration.md#Stage-Port-Pattern-m34` is the implementer's reference.
- **`internal/stages/staglog` evolution:** As later stages port and find the API too narrow, they extend the package. The minimal-first design lets evolution happen organically.
- **`tests/test_stage_port_parity.sh` becomes the arc's shared parity gate.** By m39 close it will exercise every stage's port; CI runs it on every PR. The harness's normalization rules (timestamp strip, duration zero, path placeholders) are designed in m34.1 to be stage-agnostic, so adding a new scenario in m35-m39 is a matter of dropping a fixture and a golden file — no harness change.
- **The retained `Script: "stages/<name>.sh"` audit-trail convention** is what lets a future m40 cleanup milestone confidently null-out the Script fields once every stage has ported. The convention is documented in m34.1's pattern doc so m40 has a clear cleanup target.
- **`BashAdapter` rename to `StageDispatcher` (m40 candidate):** Once every stage has `GoImpl` set and no bash stage files remain, the name `BashAdapter` is misleading. m40 (post-stage-port-arc cleanup) renames the type, simplifies the helper-source machinery, and removes the now-dead `DefaultLibHelpers` slice. m34.1 leaves the name in place by design so the renamer doesn't have to re-derive the rationale.
