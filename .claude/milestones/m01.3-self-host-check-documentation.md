#### Milestone 1.3: Self-Host Check + Documentation

Add the self-host smoke script that exercises the Go binary on `$PATH` (initially as a no-op observer) and write the one-page Go build doc for dev onboarding. This sub-milestone closes m01 by proving the Go binary is reachable from the bash pipeline's environment without altering any bash code path.

Files to create:
- `scripts/self-host-check.sh` (builds Go binary, prepends `bin/` to `$PATH`, asserts `tekhton --version` matches `VERSION`; gates live `tekhton.sh --dry-run` behind `TEKHTON_SELF_HOST_DRY_RUN=1`)
- `docs/go-build.md` (~80 lines: Go install, `make` targets, cross-compile layout, CI artifact location, `$PATH` wiring)

Acceptance criteria:
- `scripts/self-host-check.sh` is executable (`chmod +x`) and exits 0 in default CI-safe mode on a clean checkout.
- Script builds the Go binary via `make build`, prepends `bin/` to `$PATH`, and asserts `tekhton --version` output equals the trimmed contents of `VERSION`.
- Script is idempotent: running it twice in the same shell session succeeds both times with no state-file or lockfile leakage.
- Setting `TEKHTON_SELF_HOST_DRY_RUN=1` triggers the full `tekhton.sh --dry-run` smoke against the fixture task (skipped by default because intake/scout agents need Claude CLI auth CI cannot satisfy).
- `bash tests/run_tests.sh` produces identical output before and after this milestone (parity check archived to artifact).
- `docs/go-build.md` covers: prerequisite Go install, `make` targets (`build`, `build-all`, `test`, `clean`), cross-compile output layout under `bin/`, CI artifact location, and how the binary is wired into `$PATH` during self-host runs.
- No file under `lib/`, `stages/`, `prompts/`, or `tools/` is modified.

Watch For:
- Script must remain idempotent — no writes to lockfiles, state files, or causal logs that would fail on re-run in the same CI job.
- The `TEKHTON_SELF_HOST_DRY_RUN=1` tier must NOT run in CI by default; only humans with Claude CLI auth exercise it locally before landing.
- Keep `docs/go-build.md` to one page — this is onboarding, not a manual. Resist documenting subcommands that don't exist yet.
- Script should fail loudly (non-zero exit + clear message) if `bin/tekhton` is missing rather than silently skipping the version assertion.

Seeds Forward:
- m02's `tekhton causal emit` subcommand will be the first invocation the self-host script could meaningfully exercise beyond `--version`; structure the assertion block so subcommand checks can be appended without rewriting the harness.
- The `VERSION`-file source of truth established here remains canonical across bash and Go through the finalize-stage version bumping in later milestones.
