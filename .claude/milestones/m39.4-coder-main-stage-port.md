## Design

### Sequencing note

m39.4 is where the Phase 5 stage-port arc closes. Three deliverables that cannot be reordered:

1. **Land the Go orchestrator first** (`internal/stages/coder/`). The 8 parity fixtures pass against the Go orchestrator before any bash deletion.
2. **Rewire `internal/stagerunner/helpers.go` second.** Change `proto.StageCoder.Script` from `"stages/coder.sh"` to `""` and set `GoImpl: coder.RunStage`. Before this rewire, the bash adapter still routes `proto.StageCoder` through `stages/coder.sh`, so the bash files must stay on disk. After this rewire, the Go-adapter dispatches; the bash path is unreachable but the files are still present.
3. **Delete the bash files last.** Once the Go-adapter rewire is merged and the parity test suite passes, delete the 4 coder bash files in one commit.

The `VERSION` bump, `docs/v4-phase5-stub.md`, `docs/go-migration.md`, and `scripts/wedge-audit.sh` updates happen last, after the delete.

### Goal 1 — `RunStage` entry point

```go
// internal/stages/coder/coder.go
package coder

import (
    "context"

    "github.com/geoffgodwin/tekhton/internal/stagerunner"
)

// RunStage is the Go-native entry point for the coder stage. Wired into
// stagerunner.DefaultStageDefs[proto.StageCoder].GoImpl below.
func RunStage(ctx context.Context, req *stagerunner.StageRequest) (*stagerunner.StageResult, error) {
    o := newOrchestrator(req)
    return o.Run(ctx)
}
```

### Goal 2 — `orchestrator.go` (the `run_stage_coder` body)

```go
// internal/stages/coder/orchestrator.go
package coder

type orchestrator struct {
    req     *stagerunner.StageRequest
    cfg     *Config        // CODER_MAX_TURNS, model, tools, file paths
    prerunCfg     *prerun.Config
    scoutCfg      *scout.Config
    buildfixCfg   *buildfix.LoopConfig
    deps          *Deps          // injection for unit tests
}

// Run is the run_stage_coder body. Sequence:
//   1. Stage header (PIPELINE_STAGE_POS / PIPELINE_STAGE_COUNT).
//   2. Reset BUILD_FIX_* stats to "not_run" defaults.
//   3. Pre-run clean sweep — prerun.Run.
//   4. Scout decision — scout.ShouldScout → optionally scout.Run + scout.Apply.
//   5. Milestone-block population — set_focused_milestone_block.
//   6. Architecture / repo map / context blocks — context_blocks.Build.
//   7. Tag-specific prompt template selection — selectCoderTemplate.
//   8. Render coder prompt + invoke senior coder agent.
//   9. Post-coder validation — is_substantive_work + summary-file checks.
//   10. Null-run handling — null_run.Handle (auto-split, state save, exit).
//   11. Post-clarification re-run — tekhton clarify CLI integration.
//   12. CODER_SUMMARY.md IN PROGRESS detection → continuation loop.
//   13. Completion gate.
//   14. Build gate → buildfix.Run on failure.
//   15. Indexer task→file association recording.
func (o *orchestrator) Run(ctx context.Context) (*stagerunner.StageResult, error)
```

The 15-step sequence preserves the bash control flow byte-identically. Each step ports to a method on `orchestrator` so unit tests can exercise sub-paths in isolation.

### Goal 3 — `context_blocks.go` (the export-and-assemble block)

Mirrors `stages/coder.sh:425-650`. Builds 14 context blocks and adds them to the context compiler:

```go
// internal/stages/coder/context_blocks.go

type ContextBlocks struct {
    Architecture          string
    RepoMap               string
    Glossary              string
    Milestone             string
    HumanNotes            string
    PriorReviewer         string
    PriorProgress         string
    PriorTester           string
    PreflightTests        string
    NonBlockingNotes      string
    ScoutReport           string
    AffectedTestFiles     string
    TestBaselineSummary   string
    Clarifications        string
    TDDPreflight          string
}

// Build assembles all blocks from the orchestrator's context. Returns a typed
// ContextBlocks with each field potentially empty (the renderer's IF blocks
// short-circuit on empty strings, matching bash behavior).
func Build(ctx context.Context, env *Env, deps *Deps) (*ContextBlocks, error)
```

Each field-builder is a method on `ContextBlocks` so it can be unit-tested in isolation. The bash version's `_safe_read_file` wrapper (which catches missing files and emits a sentinel) ports as a Go helper that returns an empty string on error rather than propagating it. The `_wrap_file_content` wrapper (which adds `--- BEGIN FILE CONTENT: <NAME> ---` delimiters) ports as a typed format function.

### Goal 4 — Senior-vs-tag-template prompt selection

Bash at `coder.sh:702-705`:

```bash
local _coder_template="${NOTE_TEMPLATE_NAME:-coder}"
CODER_PROMPT=$(render_prompt "$_coder_template")
```

Where `NOTE_TEMPLATE_NAME` is set per-tag (`coder_note_bug` / `coder_note_feat` / `coder_note_polish` / empty for the default `coder` template).

The Go port:

```go
func selectCoderTemplate(notesFilter, noteTemplateName string) string {
    if noteTemplateName != "" {
        return noteTemplateName  // tag-specific override
    }
    return "coder"  // default senior-coder template
}
```

**Important: `coder_rework` is NOT in this dispatch.** `coder_rework.prompt.md` is rendered inside `stages/review.sh` (line 275) when `REVIEW_CYCLE >= 2`. It is owned by m37's review stage port, not by m39.4. A unit test asserts `selectCoderTemplate` never returns `"coder_rework"`.

### Goal 5 — `null_run.go` (the 3 escalation paths)

The bash version has three null-run escalation paths, all of which port:

1. **Null run after initial coder** (`coder.sh:744-783`). Agent died before doing meaningful work. Reset claimed notes; if milestone mode + can split, switch to sub-milestone and recurse via `run_stage_coder`. Otherwise save state with `exit_reason="null_run"` and exit.
2. **Turn-exhaustion without output** (`coder.sh:797-846`). Agent used all turns but produced no `CODER_SUMMARY.md` and no substantive work. Reset claimed notes; if milestone mode + can split, recurse. Otherwise save state with `exit_reason="turn_exhaustion_no_output"`.
3. **Continuation exhaustion** (`coder.sh:1024-1037`). Continuation loop hit `MAX_CONTINUATION_ATTEMPTS`. If milestone mode + can split, recurse. Otherwise fall through to save state.

The Go port factors these into a single `Handler` that the orchestrator calls at each escalation point:

```go
// internal/stages/coder/null_run.go

type EscalationKind int

const (
    EscalationNullRun EscalationKind = iota
    EscalationTurnExhaustion
    EscalationContinuationExhausted
)

type Handler struct {
    deps *Deps
}

// Handle attempts auto-split escalation. Returns ShouldRetry=true when the
// orchestrator should re-invoke Run for the new sub-milestone. Returns
// ShouldExit=true when state was saved and the orchestrator should exit 1.
type EscalationResult struct {
    ShouldRetry bool
    ShouldExit  bool
    ExitReason  string
    StateNotes  string
}

func (h *Handler) Handle(ctx context.Context, kind EscalationKind, info EscalationInfo) (*EscalationResult, error)
```

The recursive call to `Run` for auto-split is bounded by `MILESTONE_MAX_SPLIT_DEPTH` (default 3) — same as bash.

### Goal 6 — `continuation.go` (M14 CONTINUATION_ENABLED loop)

Bash at `coder.sh:940-1037`. When `CODER_SUMMARY.md` status is `IN PROGRESS` and `is_substantive_work` is true and `CONTINUATION_ENABLED=true`, run up to `MAX_CONTINUATION_ATTEMPTS=3` continuation passes. Each pass:

1. Build `CONTINUATION_CONTEXT` via `build_continuation_context` (lib helper).
2. Re-render `coder.prompt.md` with the new context.
3. Invoke the coder agent with budget = `EFFECTIVE_CODER_MAX_TURNS`.
4. Accumulate turns into `_cumulative_turns`.
5. Check for UPSTREAM error → save state, exit.
6. Check for missing `CODER_SUMMARY.md` → reconstruct from git state if substantive, else break.
7. Check for `Status: COMPLETE` → break with success.
8. Check for substantive progress this pass → continue, else break.

The Go port:

```go
// internal/stages/coder/continuation.go

type ContinuationConfig struct {
    Enabled                bool   // CONTINUATION_ENABLED (default true)
    MaxAttempts            int    // MAX_CONTINUATION_ATTEMPTS (default 3)
    Budget                 int    // EFFECTIVE_CODER_MAX_TURNS
    Template               string // "coder"
}

type ContinuationResult struct {
    AttemptsRun       int
    CumulativeTurns   int
    Outcome           string // "complete" | "no_more_progress" | "upstream_error" | "no_summary"
    UpstreamError     *UpstreamError
}

func RunContinuation(ctx context.Context, cfg *ContinuationConfig, deps *Deps) (*ContinuationResult, error)
```

### Goal 7 — `reconstruct.go` (git-state-to-markdown synthesizer)

Bash `_reconstruct_coder_summary` (lines 50-92) reads git tracked modifications and untracked new files, then writes a `CODER_SUMMARY.md` skeleton with status (default `COMPLETE`, overridable to `FAILED` or `INCOMPLETE` on error paths). The Go port ports verbatim — same field shape, same `## Files Modified` and `## New Files Created` sections, same exclusions (`.claude/logs/`, session dir):

```go
// internal/stages/coder/reconstruct.go

func ReconstructSummary(ctx context.Context, path, status string, deps *Deps) error
```

The function is exposed (capital R) because the orchestrator calls it from multiple paths: missing-summary-but-substantive-work (Path A), turn-exhaustion fallback (Path B, status `FAILED`), continuation-failure fallback (Path C), completion-gate-failed-substantive-work (Path D, status `COMPLETE`), and completion-gate-failed-no-work (Path E, status `INCOMPLETE`). A unit test asserts each path produces the expected `## Status` line.

Deleting bash before rewiring leaves the `BashAdapter` looking for `stages/coder.sh` and finding nothing — the stage will exit 127. Deleting bash before parity passes means the bash baseline is gone and there's no fallback for a Go bug.
- **`coder_rework.prompt.md` and `jr_coder.prompt.md` are NOT in m39.4 scope.** Both are rendered by `stages/review.sh` (m37 territory). A grep for `render_prompt "coder_rework"` or `render_prompt "jr_coder"` in the current tree returns hits only in `stages/review.sh`. The m39.4 orchestrator renders only `coder` (or its tag-specific variants `coder_note_bug` / `coder_note_feat` / `coder_note_polish`) and `build_fix` (inside the m39.3 loop). If the orchestrator suddenly grows a `coder_rework` rendering during m39.4 implementation, that's scope creep — back it out.
- **The jr-coder-by-scout-complexity routing does NOT exist in `stages/coder.sh` today.** The user-facing description of m39 mentioned "when scout estimates trivial scope, route to jr coder agent". Searching the actual bash returns no such routing in `coder.sh`. M39.4 does NOT add jr routing — porting that as part of the port would be a feature add disguised as a refactor. If the user wants jr-routing-by-scout-complexity, it lands as a post-m40 milestone (e.g., m41) with explicit design and dogfooding cycles.
- **The CONTINUATION_ENABLED loop is gated on `is_substantive_work` AND `CODER_STATUS == IN PROGRESS`.** Without substantive work, the loop never runs (the coder did nothing; continuing won't help). The Go port preserves this: `RunContinuation` is called only when the orchestrator has confirmed both predicates. A unit test asserts `RunContinuation` is not called when `is_substantive_work` returns false.
- **`MAX_CONTINUATION_ATTEMPTS=3` is the default — do NOT raise it.** The continuation loop multiplies turn budgets (each pass gets a full `EFFECTIVE_CODER_MAX_TURNS`). Raising the cap from 3 to 5 changes the per-stage worst-case turn count from 320 (4 × 80) to 480 (6 × 80). Operators tuning this should understand the multiplicative cost.
- **The `_reconstruct_coder_summary` exclusions are load-bearing.** The bash version filters `.claude/logs/` and the session-dir basename from untracked files. The Go port preserves this — operators downstream see fewer noise lines in the synthesized summary. A unit test plants files matching the exclusion patterns and asserts they're absent from the output.
- **The `trip_commit_gate` calls at lines 256-258 (milestone-block-unavailable) and 1148 (completion-gate-failed-substantive-work-only) are load-bearing.** They trip the m46 commit gate so the synthesize-fallback path doesn't rubber-stamp a COMPLETE-looking SUMMARY. The Go port preserves both calls via `deps.TripCommitGate` (no-op fallback if undefined, matching `declare -f trip_commit_gate &>/dev/null` bash check). A unit test asserts both gate-trip paths fire `TripCommitGate` with the bash-matching reason strings (`"milestone_block_unavailable_<id>"` and `"completion_gate_failed_substantive_work_only"`).
- **The auto-split recursion is bounded by `MILESTONE_MAX_SPLIT_DEPTH=3`.** Without this bound, a misconfigured project with an oversized milestone could recurse infinitely. The bash version checks `get_split_depth` before each recursion; the Go port preserves the check in `null_run.Handler.Handle`. A unit test plants a depth=3 milestone and asserts the next call returns `ShouldExit=true` without recursing.

The Go port preserves this contract: the orchestrator initializes `Stats{Outcome: OutcomeNotRun}` and either `buildfix.Run` updates them OR the orchestrator's exit path passes them through unchanged. - **The `CODER_TDD_TURN_MULTIPLIER=1.2` boost is load-bearing in TDD mode.** When `PIPELINE_ORDER=test_first` and `TESTER_PREFLIGHT_CONTENT` is non-empty, the coder turn budget is boosted by 1.2×. The Go port preserves this in `Config.TDDTurnMultiplier`. A unit test asserts the boost applies when both predicates are true.
- **The `tekhton clarify` CLI integration (m25-shipped) is NOT re-ported here.** The orchestrator calls `tekhton clarify detect` / `tekhton clarify handle` as subprocesses (matching bash `coder.sh:870-884`). The Go port uses `deps.RunCLI("clarify", "detect", ...)` and `deps.RunCLI("clarify", "handle", ...)` — same exec boundary as bash. Do NOT in-process-call into `internal/clarify` — that breaks the m25 wedge-pattern decoupling.

Document the closure in `docs/go-migration.md` so future contributors understand new stages land in `internal/stages/<name>/` from day one.

## Seeds Forward
