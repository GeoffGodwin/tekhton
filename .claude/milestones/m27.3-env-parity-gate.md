## Design

### Goal 1 — `tests/test_stage_env_setu.sh`

A pipeline-level parity test that exercises the real bash subprocesses spawned by `tekhton run`. The static audit (m27.1) catches what it can with grep; the parity test catches the rest — variables read via `eval`, dynamically-constructed names, files sourced at runtime. Setup:

```bash
# tests/test_stage_env_setu.sh
FIXTURE_ROOT=tests/testdata/env_contract
WORKDIR=$(mktemp -d)
cp -R "$FIXTURE_ROOT"/. "$WORKDIR"/
cd "$WORKDIR"

# Drive the pipeline through every stage in dry-run mode.
"$TEKHTON_BIN" run --milestone m27test --no-tui --dry-run \
    --project-dir "$WORKDIR" --tekhton-home "$TEKHTON_HOME"

# Scan every /tmp/tekhton_stage_env_<stage>_post.txt for unbound errors.
unbound=$(grep -hc 'unbound variable' /tmp/tekhton_stage_env_*_post.txt 2>/dev/null | paste -sd+ - | bc)
if (( unbound > 0 )); then
    echo "FAIL: detected ${unbound} unbound-variable trip(s) across stage subprocesses" >&2
    grep 'unbound variable' /tmp/tekhton_stage_env_*_post.txt >&2
    exit 1
fi
echo "PASS: no unbound-variable trips across stage subprocesses"
```

### Goal 2 — `tests/testdata/env_contract/` fixture

The fixture is a fake project that exercises every code path the env contract reaches. Contents:

```
tests/testdata/env_contract/
├── .claude/
│   ├── pipeline.conf            # Minimal config, every required key set
│   ├── milestones/
│   │   ├── MANIFEST.cfg          # One milestone: m27test
│   │   └── m27test-fixture.md    # Body referencing no real files
│   └── agents/
│       ├── coder.md              # Stub role
│       ├── reviewer.md
│       └── tester.md
└── CLAUDE.md                     # Stub project description
```

Stub agents need to be cheap. With `--dry-run` the supervisor short-circuits agent invocations and emits canned envelopes, so the fixture doesn't actually call out to the Anthropic API.

### Goal 3 — Makefile dogfood extension

The existing `make dogfood` target runs `make build` + `bash tests/run_tests.sh`. m27.3 adds two new gates after the existing test step:

```makefile
dogfood: build test
	@bash scripts/audit-bash-env.sh
	@bash tests/test_stage_env_setu.sh
	@echo "dogfood: all gates green"
```

Both gates fail-fast — `make dogfood` exits non-zero on the first failure. Order matters: audit runs first because it's fast (<5s) and gives a clean error message; the parity test is slower and harder to triage so it runs after.

### Goal 4 — `scripts/wedge-audit.sh` assertion

`scripts/wedge-audit.sh` already asserts the existence of various tools we built during the V4 wedge. Add an entry for `scripts/audit-bash-env.sh`:

```bash
# Existing wedge-audit checks
assert_file_exists scripts/audit-bash-env.sh "m27.1 env audit script"
assert_grep_in_file scripts/audit-bash-env.sh Makefile "make dogfood wires audit gate"
```

### Goal 5 — `docs/v4-env-contract.md`

Single-page reference. Sections:

- **Producer side** — pointer to `internal/runner/env.go:AsKV` as the canonical emitter and `internal/config/defaults.go` for pipeline.conf defaults.
- **Consumer rule** — every bash read of a contract variable MUST use `${VAR:-DEFAULT}` form. New bash files lacking this trip the CI gate added in this milestone.
- **Default table** — every variable, its contract default, and 1–2 example consumers (file:line). Generated by running `scripts/audit-bash-env.sh --emit-table > docs/v4-env-contract.md` and editing the prose around it.
- **Cross-references** — link to `MILESTONE_TEMPLATE.md` "Watch For" guidance.

Linked from `CLAUDE.md` under a new "Env Contract" subsection alongside the existing "Template Variables" reference.

### Goal 6 — VERSION bump

`VERSION` to `4.27.0` on m27.3 close. The m27.x sub-milestones don't individually bump VERSION (the parent m27 owns the version slot).

## Watch For

- **Dogfood stability invariant.** m27.3 adds gates and docs only — no runtime behavior changes. tekhton-stable rebuild after m27.3 just picks up the new CI hooks; nothing else.
- **Parity test brittleness.** `tests/test_stage_env_setu.sh` reads files under `/tmp/tekhton_stage_env_*_post.txt` which the stagerunner writes for diagnostics. These files are overwritten each run and not cleaned up between runs; the test must `rm -f /tmp/tekhton_stage_env_*_post.txt` at start to avoid stale-data false positives. Document this in the test header.
- **Fixture model size.** The fixture must be small enough that `--dry-run` completes in <10s but large enough to exercise every stage's subprocess startup. If a stage's startup path isn't exercised, the parity test won't catch a regression there. Cross-check the fixture against `internal/runner/single.go:defaultStageOrder` to confirm every stage is reached.
- **Doc drift.** `docs/v4-env-contract.md` will drift as new pipeline.conf keys land. m27.3 doesn't solve this — a follow-up M28 could automate doc regeneration. For m27.3 just commit the manual snapshot and note "regenerate when contract changes" in the doc header.

## Seeds Forward

- **m28+ (next bash port milestones):** Every new bash file in `lib/` or `stages/` is now held to the audit + parity standard. Drift caught at CI time, not at dogfood time.
- **Auto-generated doc:** `docs/v4-env-contract.md` is currently maintained by hand. A follow-up could derive it from `internal/proto/agent_v1.go` field tags + `internal/config/defaults.go` comments via a Go program. Out of scope for m27.3.
- **Wedge-audit growth:** `scripts/wedge-audit.sh` accumulates more assertions as the V4 port progresses. Worth a periodic review to ensure the assertions still match the live wedge surface.
