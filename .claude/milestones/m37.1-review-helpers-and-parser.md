### Goal 1 — Parser API surface

```go
// internal/review/parser.go
package review

import (
    "bufio"
    "fmt"
    "io"
    "os"
    "strings"
)

type Verdict string

const (
    VerdictApproved          Verdict = "APPROVED"
    VerdictApprovedWithNotes Verdict = "APPROVED_WITH_NOTES"
    VerdictChangesRequired   Verdict = "CHANGES_REQUIRED"
    VerdictReplanRequired    Verdict = "REPLAN_REQUIRED"
    VerdictUnknown           Verdict = ""
)

type ACPDecision string

const (
    ACPAccept ACPDecision = "ACCEPT"
    ACPReject ACPDecision = "REJECT"
    ACPModify ACPDecision = "MODIFY"
)

type ACPVerdict struct {
    Name      string
    Decision  ACPDecision
    Rationale string
}

type Report struct {
    Verdict           Verdict
    ComplexBlockers   []string
    SimpleBlockers    []string
    NonBlockingNotes  []string
    CoverageGaps      []string
    ACPVerdicts       []ACPVerdict
    DriftObservations []string
    SpecialistSection string  // captured if `## Specialist Blockers` is present (review_helpers.sh appends this)
    RawBody           string
}

func ParseReviewerReport(path string) (*Report, error) {
    f, err := os.Open(path)
    if err != nil { return nil, fmt.Errorf("review: open report: %w", err) }
    defer f.Close()
    return parseReader(f)
}

func parseReader(r io.Reader) (*Report, error) {
    // Implementation: single-pass scanner. State machine switches on `^## ` lines.
    // Accumulate raw body for RawBody field.
    // Post-process each section: strip "None" sentinels, trim leading "- ".
    // Verdict extraction:
    //   1. Heading anchored: find `## Verdict` line, read next non-blank line, trim whitespace,
    //      check against the four valid tokens.
    //   2. Inline fallback if (1) returns empty or "##Verdict": case-insensitive scan of body
    //      for token priority order REPLAN_REQUIRED > APPROVED_WITH_NOTES > CHANGES_REQUIRED > APPROVED.
    // ACP verdicts: parse rows matching `- ACP: <name> — <DECISION> — <rationale>`.
    //   Be lenient on em-dash (— vs -) and case.
}

func (r *Report) HasComplexBlockers() int { return len(r.ComplexBlockers) }
func (r *Report) HasSimpleBlockers() int  { return len(r.SimpleBlockers) }
func (r *Report) IsApproved() bool {
    return r.Verdict == VerdictApproved || r.Verdict == VerdictApprovedWithNotes
}
func (r *Report) AcceptedACPs() []ACPVerdict {
    out := make([]ACPVerdict, 0, len(r.ACPVerdicts))
    for _, a := range r.ACPVerdicts {
        if a.Decision == ACPAccept { out = append(out, a) }
    }
    return out
}
```

The parser is a single-pass line scanner driven by a `currentSection string` state variable. On each `^## ` line: flush the previous section's accumulator into the appropriate Report field, reset, set the new section name. On non-heading lines within a known section: accumulate.

**Verdict extraction quirks (bash parity):**

1. Bash's `grep -m1 "^## Verdict" -A1 | tail -1 | tr -d '[:space:]'` returns the second line of the matched range after stripping all whitespace. When `## Verdict` is on its own line followed by `APPROVED`, this returns `APPROVED`. When `## Verdict` is immediately followed by nothing (some agents emit `## Verdict APPROVED` on one line), this returns `##VerdictAPPROVED` — the bash code at line 218 treats `##Verdict` as a sentinel for "primary extraction failed, use fallback". The Go port matches this: if the heading-anchored extraction yields a string containing `##Verdict`, fall through to inline scan.
2. The inline scan priority is `REPLAN_REQUIRED` > `APPROVED_WITH_NOTES` > `CHANGES_REQUIRED` > `APPROVED`. Without this order, a `CHANGES_REQUIRED` report that happens to contain the word "approved" in a non-blocking note would mis-classify. Bash uses `grep -oi "REPLAN_REQUIRED\|APPROVED_WITH_NOTES\|CHANGES_REQUIRED\|APPROVED" | head -1` — the order in the alternation is the priority. Match it.

**Section "None" sentinel:** bash uses `grep -qE "^\-?\s*None\s*$"` to detect "section is empty"; if matched, the blocker count is 0. The Go port mirrors this: after extracting section lines, drop any line whose trimmed content matches `^-?\s*None\s*$`. A section consisting of only a "None" line yields an empty slice.

### Goal 2 — CycleBudget API

```go
// internal/review/cycle.go
package review

type CycleBudget struct {
    Current int  // 1-indexed; 0 means "no cycles run yet"
    Max     int
}

func (c *CycleBudget) Increment()        { c.Current++ }
func (c CycleBudget) Remaining() int     { return c.Max - c.Current }
func (c CycleBudget) IsLastCycle() bool  { return c.Current == c.Max }
func (c CycleBudget) IsExhausted() bool  { return c.Current >= c.Max }

// BumpFromUsage encapsulates review.sh lines 132-148 (>=85% usage → +25%,
// capped at REVIEWER_MAX_TURNS_CAP). Returns (newLimit, bumped). When used or
// limit is 0, returns (limit, false). When the calculated bump is <= limit
// (already at or above cap), returns (limit, false). cap defaults to 60 if
// 0 is passed (matches bash `REVIEWER_MAX_TURNS_CAP:-60`).
func (c CycleBudget) BumpFromUsage(used, limit, cap int) (newLimit int, bumped bool) {
    if used == 0 || limit == 0 { return limit, false }
    if cap == 0 { cap = 60 }
    usagePct := used * 100 / limit
    if usagePct < 85 { return limit, false }
    bumpedVal := limit * 125 / 100
    if bumpedVal > cap { bumpedVal = cap }
    if bumpedVal <= limit { return limit, false }
    return bumpedVal, true
}
```

The "current = 0 before first cycle" convention deliberately matches bash: bash initializes `REVIEW_CYCLE=0` at line 39, increments at line 44 (so the first cycle is `REVIEW_CYCLE=1`). The Go port uses the same convention so test-fixture cycle numbers line up.

### Goal 3 — Specialist helpers

```go
// internal/review/specialist.go
package review

import "strings"

// HasSpecialistBlockers mirrors bash has_specialist_blockers — true when the
// SPECIALIST_BLOCKERS env value contains at least one non-whitespace,
// non-"None" line. The bash version uses `[[ -n "$SPECIALIST_BLOCKERS" ]]`
// PLUS a content check; pure emptiness is not sufficient.
func HasSpecialistBlockers(env string) bool {
    for _, line := range strings.Split(env, "\n") {
        trimmed := strings.TrimSpace(line)
        if trimmed == "" || strings.EqualFold(trimmed, "none") { continue }
        return true
    }
    return false
}

// FormatSpecialistSection returns the block the bash version appends to the
// reviewer report. Format:
//
//   "\n## Specialist Blockers\n<env>\n"
//
// Matches stages/review_helpers.sh lines 11-17 byte-for-byte (the empty
// echo on line 12, the heading line, the env block).
func FormatSpecialistSection(env string) string {
    var b strings.Builder
    b.WriteString("\n## Specialist Blockers\n")
    b.WriteString(env)
    if !strings.HasSuffix(env, "\n") { b.WriteString("\n") }
    return b.String()
}

// SpecialistDecision is the outcome of the post-loop specialist check.
type SpecialistDecision int

const (
    SpecialistPassthrough SpecialistDecision = iota  // No blockers — proceed to tester
    SpecialistRework                                  // Blockers + cycles remain — spin senior rework
    SpecialistExhausted                               // Blockers + no cycles left — fail with specialist_blockers exit reason
)

// RouteSpecialistRework returns whether the post-loop specialist branch
// should spin a rework, exhaust, or pass through. The caller invokes the
// senior coder + reviewer pass — this helper only classifies.
func RouteSpecialistRework(env string, budget CycleBudget) SpecialistDecision {
    if !HasSpecialistBlockers(env) { return SpecialistPassthrough }
    if budget.IsExhausted() { return SpecialistExhausted }
    return SpecialistRework
}
```

## Watch For

- **Self-driving dogfood:** the implementation run is itself driven by `tekhton run --milestone m37.1 --complete`. This is the m34-onwards pattern. Surfacing it here as a Watch For rather than an acceptance predicate because it's not a testable post-condition — the milestone closes when the work lands regardless of which CLI invoked the coder.
- **Completion-gate false-halt exposure (until m45 lands):** if m45 is not yet done when m37.1 runs, the coder run may be halted by the same completion-gate transient flake that bit m36.2 and m36.3. The work will land in the tree regardless; just expect to manually flip the manifest if the false-halt fires. After m45 lands this becomes a non-issue.

- **The inline-fallback verdict priority order matters.** `grep -oi "REPLAN_REQUIRED\|APPROVED_WITH_NOTES\|CHANGES_REQUIRED\|APPROVED" | head -1` returns the FIRST matching pattern in the alternation order, NOT the first lexical hit in the body. If you naively use `strings.Contains` in the wrong order, a `CHANGES_REQUIRED` report containing "approved" in a non-blocking note mis-classifies to APPROVED. Test the priority explicitly: a fixture that contains both `APPROVED` (in body text) and `CHANGES_REQUIRED` (in body text) but no `## Verdict` heading should classify as `CHANGES_REQUIRED`.
- **The "None" sentinel is case-sensitive and shape-sensitive in bash.** The bash check is `grep -qE "^\-?\s*None\s*$"` — leading optional dash, optional whitespace, literal `None`, optional trailing whitespace. Lower-case "none" should NOT match (the agent prompt insists on the literal word `None`). A fixture with `none` (lower case) should yield a 0-blocker count via the parser's "no non-None lines" logic, but should NOT match the explicit sentinel. Match this exactly — the metrics subsystem depends on it.
- **`Report.RawBody` is load-bearing for forensics.** The bash code `cat`s the file in several places (the log statement on line 246 echoes accepted ACPs; the dashboard subsystem emits the body to JSON). Preserve the byte-for-byte file contents in `RawBody`. Use `os.ReadFile` to capture before line-scanning, OR re-build the body from accumulated scanner lines (slower, more error-prone). Prefer the former.
- **Don't import `internal/stagerunner` or `internal/orchestrate` from `internal/review/`.** Leaf-package discipline. The cycle loop in M37.2 will reach DOWN into `internal/review/`, never the other way. A `go list -deps ./internal/review/...` check at acceptance time ensures this.
- **ACP-row parsing is lenient on dash characters.** Agents emit `- ACP: foo — ACCEPT — reason` (em dash) or `- ACP: foo - ACCEPT - reason` (hyphen). Both must parse. The bash version's `awk '/ACCEPT/{print}'` is purely a presence test, but the Go port stores the decision + rationale separately, so the parser MUST handle both delimiters. A fixture row with em dash and a fixture row with hyphen are both required.
- **`CycleBudget.BumpFromUsage` returns the new limit but does NOT mutate the receiver.** The caller decides whether to apply the bump (it's "this would be the new limit, did the bump trigger?"). Tests assert that `CycleBudget` is unchanged after a `BumpFromUsage` call returning `bumped=true` — failure here means the cycle counter and the turn-budget value have gotten confused.
- **`FormatSpecialistSection` output is appended to `REVIEWER_REPORT.md`.** The bash version writes `echo ""` then `echo "## Specialist Blockers"` then `echo "$SPECIALIST_BLOCKERS"`. The Go port must produce the same trailing newline + leading newline shape — otherwise the metrics subsystem's section detection breaks on the joined output.
