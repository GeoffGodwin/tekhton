#### Milestone 1.1.2: Version Injection & Makefile Test/Clean Targets

Add the version package, wire `-ldflags "-X"` injection through the Makefile, expose `--version` on the Cobra root command, and round out Makefile with `test` and `clean` targets.

Files to create:
- `internal/version/version.go`

Files to modify:
- `cmd/tekhton/main.go` (wire `version.Version` into Cobra root `Version` field, trim trailing whitespace)
- `Makefile` (add `-ldflags "-X github.com/geoffgodwin/tekhton/internal/version.Version=$(shell cat VERSION)"`, add `test` and `clean` targets)

Acceptance criteria:
- `bin/tekhton --version` prints the trimmed contents of repo-root `VERSION`.
- Direct `go build ./cmd/tekhton` (without make) leaves `Version` at the `dev` sentinel.
- `make test` exits 0 (Go's "no tests" output is acceptable).
- `make clean` removes `bin/`.
- `make build` still produces a working `bin/tekhton` with version injected.
- No file under `lib/`, `stages/`, `prompts/`, or `tools/` is modified.

Watch For:
- Version comes from `-ldflags "-X"` injection, NOT `//go:embed` (embed cannot traverse out of source directory to reach repo-root `VERSION`).
- Trim trailing whitespace from the version string at print time — `cat VERSION` in the Makefile may preserve a trailing newline that survives into the ldflag.
- The `dev` sentinel must be the package-level default in `internal/version/version.go` so plain `go build` users see something meaningful.
- Keep `CGO_ENABLED=0` on every build invocation in the Makefile.

Seeds Forward:
- Milestone 1.2 depends on the Makefile structure to add `build-all` cross-compile target alongside `build`.
- Milestone 1.3 depends on `bin/tekhton --version` working for the self-host assertion.
