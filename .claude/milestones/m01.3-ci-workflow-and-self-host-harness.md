#### Milestone 1.3: CI Workflow and Self-Host Harness

Add the GitHub Actions workflow `.github/workflows/go-build.yml` with three jobs: (1) `make build-all` on `ubuntu-latest` uploading the five binaries as artifacts, (2) `go vet ./...` + `go test ./...`, (3) `golangci-lint` "advanced" preset against `./...`. Triggers: PR + push to `main` and `feature/GoWedges`. Then add `scripts/self-host-check.sh`: builds the Go binary via `make build`, prepends `bin/` to `$PATH`, exercises the dispatcher routing matrix, and asserts `tekhton --version` matches `VERSION`. The full `tekhton.sh --dry-run` smoke is gated behind `TEKHTON_SELF_HOST_DRY_RUN=1` (live Claude CLI agents require auth CI lacks). Idempotent — safe to run twice in the same CI job.

Files to create:
- `.github/workflows/go-build.yml`
- `scripts/self-host-check.sh`

Acceptance criteria:
- CI workflow `go-build.yml` passes on the V4 branch with all three jobs (build-all, vet+test, lint) green.
- `actions/setup-go` reads `go-version-file: go.mod` so local/CI Go versions stay aligned.
- Five binaries appear as workflow artifacts on a successful run.
- `golangci-lint run ./...` clean; `go vet ./...` clean.
- `scripts/self-host-check.sh` exits 0 in its default (CI-safe) mode: builds the Go binary, prepends `bin/` to `$PATH`, exercises the dispatcher routing matrix, asserts `tekhton --version` matches `VERSION`.
- `scripts/self-host-check.sh` re-run in the same CI job exits 0 (idempotent — no lockfile/state writes that fail on re-run).
- With `TEKHTON_SELF_HOST_DRY_RUN=1`, the script invokes `tekhton.sh --dry-run` against the fixture task; otherwise that tier is skipped.
- CI does NOT invoke `bash tests/run_tests.sh` — bash test gating is unchanged.
- `bash tests/run_tests.sh` produces identical output before and after this milestone (parity artifact archived).
- No file under `lib/`, `stages/`, `prompts/`, or `tools/` is modified.

Watch For:
- The Go binary is on `$PATH` but called by no production code path — a regression here can only manifest as a CI build break.
- Don't add subcommands; m01 ships a stub root only. `tekhton causal …`, `tekhton supervise …` belong to later wedges.
- Avoid state-file writes in the self-host script so re-runs stay safe.

Seeds Forward:
- m02 causal log will introduce `internal/causal/` and the first `tekhton causal emit` subcommand — this milestone's CI matrix and self-host harness will then exercise a real Go code path.
- m04 hardening adds the 80% coverage gate; m01 ships zero Go code paths deliberately so that gate has nothing to fail on yet.
