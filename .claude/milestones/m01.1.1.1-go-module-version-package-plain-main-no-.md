#### Milestone 1.1.1.1: Go Module + Version Package + Plain Main (No Makefile)

Establish the Go module skeleton with a version package and a minimal `main.go` that prints the version using the `dev` sentinel. Validation in this sub-milestone uses direct `go build` only; the Makefile-driven build with `-ldflags "-X"` injection lands in 1.1.1.2. Splitting the module/source work from the Makefile work keeps each sub-milestone independently testable and isolates ldflags-quoting failures from module-declaration failures.

Files to create:
- `go.mod`
- `internal/version/version.go`
- `cmd/tekhton/main.go` (plain `main` that prints version and exits 0)

Acceptance criteria:
- `go.mod` declares module `github.com/geoffgodwin/tekhton` with `go 1.23` (pinned exactly).
- `internal/version/version.go` exposes a `Version` package variable (not a const) defaulting to the `dev` sentinel string.
- `go build ./cmd/tekhton` (without make, from a clean checkout) succeeds and produces a runnable binary.
- Running that binary with no arguments prints the `dev` sentinel and exits 0.
- `cmd/tekhton/main.go` imports only the standard library and `github.com/geoffgodwin/tekhton/internal/version`.
- No `go.sum` is created (no third-party deps).
- No file under `lib/`, `stages/`, `prompts/`, or `tools/` is modified.

Watch For:
- `Version` MUST be a package-level `var`, not a `const`, or `-ldflags "-X"` injection in 1.1.1.2 will silently no-op.
- Pin `go 1.23` exactly in `go.mod`; drift causes CI flake later.
- Keep `cmd/tekhton/main.go` dependency-free so this sub-milestone produces zero `go.sum` churn.
- Do NOT use `//go:embed` for VERSION — embed cannot traverse out of the source directory, and the injection path belongs in 1.1.1.2 anyway.

Seeds Forward:
- Milestone 1.1.1.2 adds the Makefile and proves the `-ldflags "-X"` injection of the trimmed repo-root `VERSION` file overrides the `dev` sentinel.
