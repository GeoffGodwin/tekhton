## Design

### Sequencing note

m29.2 depends strictly on m29.1. The eight new `internal/detect/*.go` files implement the `Detector` interface that m29.1 defines. The parity gate compares Go output against baselines locked at m29.1 close — those baselines must NOT regenerate during m29.2 (any drift means the Go port diverged from bash, not that the baseline is stale). The CLI surface (`tekhton detect summary --json`) is already wired in m29.1; m29.2 only registers more detectors against it.

The bash deletions and caller migrations happen atomically at the end of the milestone. Order:

1. Land all eight Go detectors with passing unit tests.
2. Land the extended parity gate; confirm green against the m29.1 baselines.
3. Land the `lib/common.sh::_tk_detect_summary` helper.
4. Rewrite every bash caller in one PR-equivalent change.
5. Delete the ten `lib/detect*.sh` files in the same change.
6. Run `make dogfood` confirming green.
7. Bump `VERSION` to `4.29.0`.

Reason for the atomic step: any intermediate state where some callers go through Go and others through bash is the worst case for parity verification. The order above ensures that at every checkpoint either ALL detect calls go through bash (steps 1-3) or ALL go through Go (steps 4-7), never mixed.

### Goal 2 — Critical: `ai_artifacts.go` heuristic order preservation

The bash `detect_ai_artifacts` is the highest-risk port in the arc. The bash flow at `lib/detect_ai_artifacts.sh:59-119`:

1. `_detect_claude_dir_artifacts` — looks for `.claude/`, returns finding if present.
2. `_detect_claude_md` — looks for `CLAUDE.md`, runs `_scan_for_directive_language` on its contents.
3. `_scan_for_directive_language` — regex-scans text for prescriptive markers (`"MUST"`, `"NEVER"`, `"DO NOT"`, etc.); confidence scales with hit count.
4. `_detect_directive_markdowns` — applies the same scan to every `*.md` in the repo root.
5. `_dir_has_config_files` — looks for `.cursorrules`, `AGENTS.md`, etc.

The order matters because `classify_ai_tool` (line 121) uses the first finding to disambiguate ties. A repo with both `.claude/` and `.cursorrules` classifies as claude-primary because `_detect_claude_dir_artifacts` runs first. Reorder the steps and the classification changes — which changes the markdown — which fails the parity gate.

The Go port MUST preserve this order exactly. Encode it as a const slice + a `TestHeuristicOrder` test that fails red on reorder:

```go
var aiArtifactHeuristics = []heuristic{
    {name: "claude_dir", fn: detectClaudeDirArtifacts},        // ports :149
    {name: "claude_md", fn: detectClaudeMD},                    // ports :184
    {name: "directive_language", fn: scanForDirectiveLanguage}, // ports :205
    {name: "directive_markdowns", fn: detectDirectiveMarkdowns},// ports :231
    {name: "config_files", fn: dirHasConfigFiles},              // ports :249
}

func TestHeuristicOrder(t *testing.T) {
    want := []string{"claude_dir", "claude_md", "directive_language",
                     "directive_markdowns", "config_files"}
    got := make([]string, len(aiArtifactHeuristics))
    for i, h := range aiArtifactHeuristics { got[i] = h.name }
    if !reflect.DeepEqual(want, got) {
        t.Fatalf("heuristic order changed; parity gate will fail. want %v, got %v", want, got)
    }
}
```

The fixture `tests/testdata/detect/ai-heavy-mess/` was designed in m29.1 specifically to exercise every heuristic in order — its baseline captures the exact classification the bash produces, and the parity gate fails if the Go port diverges.

### Goal 3 — `cmd/tekhton/detect.go` detector registration

Extend `runDetectSummary` to register all nine detectors in bash report-formatter order:

```go
func runDetectSummary(cmd *cobra.Command, _ []string) error {
    dir, _ := cmd.Flags().GetString("project-dir")
    if dir == "" { dir, _ = os.Getwd() }

    e := detect.New()
    e.Register(detect.LanguagesDetector{})       // m29.1
    e.Register(detect.CommandsDetector{})        // m29.2
    e.Register(detect.WorkspacesDetector{})      // m29.2
    e.Register(detect.ServicesDetector{})        // m29.2
    e.Register(detect.CIDetector{})              // m29.2
    e.Register(detect.InfrastructureDetector{})  // m29.2
    e.Register(detect.TestFrameworksDetector{})  // m29.2
    e.Register(detect.DocQualityDetector{})      // m29.2
    e.Register(detect.AIArtifactsDetector{})     // m29.2

    s, err := e.Run(cmd.Context(), dir)
    if err != nil { return err }

    asJSON, _ := cmd.Flags().GetBool("json")
    if asJSON {
        return json.NewEncoder(cmd.OutOrStdout()).Encode(s)
    }
    fmt.Fprint(cmd.OutOrStdout(), detect.Render(s))
    return nil
}
```

The registration order is load-bearing. A `TestRegistrationOrder` test in `cmd/tekhton/detect_test.go` asserts the exact sequence above; reordering fails red.

### Goal 4 — `lib/common.sh::_tk_detect_summary` helper

Every bash caller calls one helper instead of duplicating the `tekhton detect summary --json` invocation + JSON parse:

```bash
# _tk_detect_summary — Run the Go detect engine and emit JSON to stdout.
# Args: $1 = project directory (defaults to PROJECT_DIR)
# Output: JSON Summary on stdout; non-zero exit on detect failure.
# Replaces the m29.1-era detect_languages, detect_frameworks, detect_commands,
# detect_workspaces, detect_services, detect_ci_config, detect_infrastructure,
# detect_test_frameworks, detect_doc_quality, detect_ai_artifacts functions.
_tk_detect_summary() {
    local proj_dir="${1:-${PROJECT_DIR:-.}}"
    local tekhton_bin="${TEKHTON_BIN:-${TEKHTON_HOME:-.}/bin/tekhton}"
    "$tekhton_bin" detect summary --json --project-dir "$proj_dir"
}
```

Per-domain accessors live in the same file as one-liner wrappers around `_tk_detect_summary` + `jq`:

```bash
_tk_detect_languages() {
    _tk_detect_summary "$@" | jq -r '.languages[] | "\(.name)|\(.confidence)|\(.manifest)"'
}

_tk_detect_commands() {
    _tk_detect_summary "$@" | jq -r '.commands[] | "\(.type)|\(.command)|\(.source)|\(.confidence)"'
}

# … one per domain
```

The wrappers preserve the bash pipe-delimited output shape so existing callers don't need to learn JSON. After m29.2 the wrappers ARE the bash API; the bash detect files no longer exist.

## Watch For

- **`ai_artifacts.go` is the highest-risk file in the arc.** The bash version's heuristic order is load-bearing — `classify_ai_tool` uses the first matching finding to disambiguate ties. A repo with both `.claude/` and `.cursorrules` classifies as claude-primary because `_detect_claude_dir_artifacts` runs first. Reordering the heuristics changes the classification, which changes the markdown, which fails the parity gate. Land `ai_artifacts.go` LAST among the eight detectors, and lean on `TestHeuristicOrder` + the `ai-heavy-mess` fixture's baseline as the ground truth. If parity diverges and the test fails, the answer is to fix the Go port, not to "rebaseline" — the bash captured at m29.1 close is the contract.
- **The parity-gate baselines are FROZEN.** Do not run `scripts/capture-detect-baselines.sh` during m29.2. The baselines were locked at m29.1 close; any drift between then and now means the bash detect side changed (which it shouldn't have, since m29.1 explicitly didn't touch the bash). If you find yourself wanting to regenerate, stop and figure out what changed instead.
- **The atomic caller migration is non-negotiable.** Do not partially migrate — e.g. land `lib/init.sh` on the Go path but leave `lib/express.sh` on the bash path through a separate commit. The dogfooding workflow may run init then express in the same `tekhton run`; if the two sides produce different output the run is internally inconsistent. Either ALL callers go through Go and the bash files delete in the same change, or no callers migrate. The order is: land all eight Go detectors green → land the parity gate green → land the helper in `common.sh` → atomically rewrite all six caller files + `tekhton-legacy.sh` + delete the ten bash files.
- **`command -v` guards in `health_checks*.sh` rely on bash sourcing.** Today those guards exist because health checks may run before `lib/detect*.sh` is sourced. Post-m29.2 the guard collapses (the Go binary is unconditionally available). When removing the guards, verify the `health_checks_hygiene.sh:47-49` ci_config flow still works in the pre-init path — there's no source-order to worry about, but there might be a `PROJECT_DIR` not-yet-set bug if the function is called before `lib/preflight.sh` sets it.
- **Dogfood stability invariant.** Both m29.1 and m29.2 are independently dogfood-able. m29.1 ships the Go engine + parity gate but leaves all bash callers on bash. m29.2 cuts over atomically. A tekhton-stable rebuild after m29.1 (before m29.2 starts) works because every detect call still goes through bash. A tekhton-stable rebuild after m29.2 works because every detect call goes through Go. The unsafe state is "some callers on Go, some on bash" — which the atomic migration step prevents. Do NOT push a half-migrated tekhton-stable rebuild between m29.2's intermediate commits; wait for m29.2's final commit (with all ten deletions + VERSION bump) before rebuilding.
- **JSON contract stability.** `tekhton detect summary --json` emits the `Summary` Go struct. Bash callers parse it with `jq`. If a future milestone reorders `Summary`'s fields or renames one, every bash caller breaks. Consider tagging the JSON output with a version field (`"version": "v1"`) from day one so downstream tooling can pin against it; the m29 design doesn't require this but it's a one-line addition that's much cheaper to do now than to retrofit. Out-of-scope-but-worth-mentioning: promoting `Summary` to `internal/proto/detect_summary.v1.go` is the formal version contract — flagged as a seed forward but not blocking m29.2.
- **`detect_ui_framework` is called only once outside the report formatter** (`tekhton-legacy.sh:2278`), and the call is `>/dev/null 2>&1 || true` — the result is discarded! Verify whether the call is actually load-bearing (side effects?) or if it can simply be deleted. If it's truly a no-op safe to delete, do so; if it has side effects, document them in the migration commit message because they will silently move from bash to Go and any drift will be hard to debug.

## Seeds Forward

- **Per-detector Cobra subcommands.** Now that every detector implements the `Detector` interface, adding `tekhton detect commands --json` etc. is a CLI wiring change — `cobra.Command` per detector pointing at `e.Register` of just that one. If a future caller wants only one domain, do this then. Out of scope for m29.
- **`Summary` as a versioned proto.** Move `Summary` from `internal/detect/detect.go` to `internal/proto/detect_summary.v1.go` with a `Version string` field set to `"v1"`. JSON consumers can pin against it. Future detector additions become v1.1 / v2 with a Go field-default migration. Flagged for the proto-contract cleanup arc.
- **Detect cache surfacing.** `Engine.cache` is per-`Run` today. A future milestone could persist it to `.tekhton/.detect-cache.json` keyed by a project-tree-hash. Across `init` → `rescan` → `express` invocations in the same session, the cache would skip redundant detector runs. Bash callers benefit too (the `_tk_detect_*` wrappers all hit the cache transparently).
- **V5 cloud-aware infrastructure detection.** `DESIGN_v5.md` flags AWS / GCP / Azure provider detection as a follow-up. The `InfrastructureDetector` interface is already in place; V5 extends it with cloud-provider classification without changing the `Detector` interface.
- **CI-time JSON contract test.** Add a `tests/test_detect_summary_json_contract.sh` that asserts `tekhton detect summary --json` always emits keys for every domain (even when empty: `"workspaces": []`, `"doc_quality": null`). Bash callers parse with `jq` and rely on key existence; a future Go refactor that strips empty fields would silently break them. The test pins the JSON shape against drift.
- **Bash test cleanup.** Several existing bash tests (`tests/test_detect_*.sh` if any) become Go-only after m29.2. Audit `tests/` for bash detect tests; either port them to Go (`internal/detect/*_test.go`) or delete them with a note in the closeout that the unit tests + parity gate subsume their coverage. Out of scope as a hard acceptance criterion but worth catching during the close-out review.
