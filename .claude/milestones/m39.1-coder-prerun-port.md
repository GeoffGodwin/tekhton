| Item | Detail |

## Design

### Sequencing note

m39.1 lands the `internal/coder/` package shape. Once it merges, m39.2 (helpers) and m39.3 (loop + scout) can develop in parallel against the established package conventions. The bash `stages/coder_prerun.sh` stays on disk until m39.4 — `stages/coder.sh` still sources it during m39.2 and m39.3 execution, so deleting it early would break the bash-coder path that's still serving the pipeline.

### Goal 1 — Package layout

```
internal/coder/prerun/
├── prerun.go              # Run(ctx, cfg, deps) (*Result, error)
├── prerun_test.go
├── fix_agent.go           # runFixAgent(ctx, cfg, deps, output, exit) (*FixOutcome, error)
├── fix_agent_test.go
└── types.go               # Config, Result, Status, Deps interfaces
```

### Goal 2 — `Run` entry point

```go
// internal/coder/prerun/prerun.go
package prerun

type Status string

const (
    StatusClean     Status = "clean"      // tests passed pre-coder; no agent needed
    StatusFixed     Status = "fixed"      // tests failed; fix agent succeeded
    StatusFixFailed Status = "fix_failed" // tests failed; fix agent exhausted attempts
    StatusSkipped   Status = "skipped"    // PRE_RUN_CLEAN_ENABLED=false or TEST_CMD empty
)

type Config struct {
    Enabled      bool   // PRE_RUN_CLEAN_ENABLED (default true)
    TestCmd      string // TEST_CMD
    MaxAttempts  int    // PRE_RUN_FIX_MAX_ATTEMPTS (default 1)
    MaxTurns     int    // PRE_RUN_FIX_MAX_TURNS (default 20)
    Model        string // PREFLIGHT_FIX_MODEL or CLAUDE_JR_CODER_MODEL
    AgentTools   string // AGENT_TOOLS_BUILD_FIX
    LogFile      string // LOG_FILE
    ProjectDir   string // PROJECT_DIR — for baseline re-capture path
}

type Result struct {
    Status             Status
    Attempts           int
    InitialFails       int     // count from grep -ciE '(FAIL|ERROR|error|failure)'
    FinalFails         int
    BaselineReCaptured bool
    FailureCountDelta  int     // FinalFails - InitialFails (informational)
}

// Run orchestrates the pre-coder clean sweep. Non-fatal on every path — the
// pipeline proceeds even when the fix exhausts attempts. The orchestrator
// logs the Status string and the orchestrator-side warn line.
func Run(ctx context.Context, cfg *Config, deps *Deps) (*Result, error)
```

### Goal 3 — `Deps` injection seam

```go
// internal/coder/prerun/types.go
package prerun

type Deps struct {
    RunAgent             func(ctx context.Context, inv *agent.Invocation) (*agent.Outcome, error)
    RenderPrompt         func(name string, env map[string]string) (string, error)
    CaptureTestBaseline  func(milestone string) error
    EmitEvent            func(kind, scope, desc string)
    TestDedupCanSkip     func() bool
    TestDedupRecordPass  func() error
    DeleteBaselineJSON   func() error
    Log                  func(format string, args ...any)
    Warn                 func(format string, args ...any)
    Success              func(format string, args ...any)
}
```

The `Deps` struct lets `prerun.Run` be unit-tested without a live subprocess. The m38 tester port used the same pattern (`internal/tester/.../Deps`).

### Goal 4 — Fix agent inner loop

```go
// internal/coder/prerun/fix_agent.go
package prerun

type fixOutcome struct {
    Status            Status   // StatusFixed or StatusFixFailed
    AttemptsUsed      int
    FinalFails        int
    LastVerifyOutput  string
    AbortReason       string  // "" | "introduced_new_failures" | "max_attempts"
}

// runFixAgent mirrors _run_prerun_fix_agent. Spawns the preflight_fix-template
// agent up to cfg.MaxAttempts times. After each attempt, the shell (not the
// agent) runs TEST_CMD; on pass, return StatusFixed. On the +2 failure-count
// threshold, abort with AbortReason="introduced_new_failures".
func runFixAgent(ctx context.Context, cfg *Config, deps *Deps,
    initialOutput string, initialExit int) (*fixOutcome, error)
```

The +2 failure-count threshold is load-bearing: it lets the loop tolerate noisy "0 errors" framework lines while catching real regressions. The Go port preserves it verbatim:

```go
newFailCount := countFailures(verifyOutput)
if newFailCount > initialFailCount + 2 {
    return &fixOutcome{
        Status:       StatusFixFailed,
        AttemptsUsed: attempt,
        FinalFails:   newFailCount,
        AbortReason:  "introduced_new_failures",
    }, nil
}
```

Where `countFailures` is `grep -ciE '(FAIL|ERROR|error|failure)'` ported to a single compiled regex.

### Goal 5 — Baseline re-capture on success

When the fix succeeds, the bash version deletes `.tekhton/TEST_BASELINE.json` (line 156) and calls `capture_test_baseline` so the baseline reflects the post-fix clean state, not the dirty pre-fix state. The Go port preserves this:

```go
if result.Status == StatusFixed && deps.CaptureTestBaseline != nil {
    if err := deps.DeleteBaselineJSON(); err != nil {
        deps.Warn("[coder/prerun] Failed to delete stale baseline: %v", err)
    }
    if err := deps.CaptureTestBaseline(currentMilestone); err != nil {
        deps.Warn("[coder/prerun] Baseline re-capture failed: %v", err)
    }
    result.BaselineReCaptured = true
    deps.Log("[coder/prerun] Baseline re-captured after successful fix.")
}
```

### Goal 6 — Dedup short-circuit

The bash version checks `test_dedup_can_skip` before running TEST_CMD (twice — once in `run_prerun_clean_sweep`, once in `_run_prerun_fix_agent`). When the dedup cache says tests passed with no file changes since last run, the run is short-circuited. The Go port preserves this through `deps.TestDedupCanSkip` and `deps.TestDedupRecordPass`. A unit test plants a `TestDedupCanSkip() == true` mock and asserts the run returns `StatusClean` without invoking `RunAgent`.

### Goal 7 — Parity fixtures

Three fixtures under `internal/coder/testdata/prerun/`:

1. **`clean-baseline/`** — TEST_CMD passes immediately. Expected: `Status=clean`, `Attempts=0`, no agent invocation.
2. **`fix-succeeds/`** — TEST_CMD fails, fix agent runs, post-fix TEST_CMD passes. Expected: `Status=fixed`, `Attempts=1`, `BaselineReCaptured=true`.
3. **`fix-exhausts/`** — TEST_CMD fails, fix agent runs once, post-fix TEST_CMD still fails. Expected: `Status=fix_failed`, `Attempts=1`, `BaselineReCaptured=false`. Asserts `PRE_RUN_FIX_MAX_ATTEMPTS=1` default semantics.

Each fixture has a `bash_baseline.txt` captured from the bash version against the same input, and the parity test diffs the Go log output against it after timestamp normalization.

## Watch For

- **The fix agent runs in a separate subprocess with its own context.** Bash forks `run_agent` with only the `preflight_fix` prompt template + last 120 lines of test output (`PREFLIGHT_TEST_OUTPUT`); the agent does NOT see the main coder's conversation, scratch state, or session memory. The Go port must preserve subprocess isolation — `runFixAgent` constructs a fresh `agent.Invocation` per attempt and does not share state with any other Go subsystem. A unit test injects a `RunAgent` mock that asserts no caller state leaks into the `Invocation.Env` map.
- **The +2 failure-count threshold is load-bearing — do NOT change it to +1 or +3.** It was tuned against framework-specific output noise (Vitest's "0 errors / 5 passed" lines that match `error` case-insensitively). The threshold is documented at `coder_prerun.sh:95-96` and lives at `_try_preflight_fix` for the preflight subsystem (also m22-shipped). Change requires coordinated update across both paths and re-tuning fixtures.
- **`PRE_RUN_FIX_MAX_ATTEMPTS=1` is the default — do NOT bump it.** The pre-run fix is intentionally cheap: one shot, then proceed. Operators reading the pipeline log expect "Fix attempt 1/1...". Bumping the default would compound with the M128 build-fix loop's `BUILD_FIX_MAX_ATTEMPTS=3` and balloon the per-stage agent budget. If an operator wants more attempts, they set the env var.
- **`PRE_RUN_FIX_MAX_TURNS=20` is the default — preserve it.** Same reasoning: the pre-run fix is bounded; 20 turns lets a Jr Coder fix a typical test-baseline regression without spilling into senior-coder budget.
- **Baseline re-capture order matters.** The bash version deletes `.claude/TEST_BASELINE.json` (line 156) BEFORE calling `capture_test_baseline`. This forces `_should_capture_test_baseline` to re-fire (otherwise the cached baseline would be returned). The Go port must preserve order: `DeleteBaselineJSON` then `CaptureTestBaseline`. A mock-call-order test asserts this.
- **The bash file stays on disk in m39.1.** Do NOT delete `stages/coder_prerun.sh`. The bash `stages/coder.sh` still sources it via `${TEKHTON_HOME}/stages/coder_prerun.sh` until m39.4 deletes both files together. Premature deletion breaks the bash-coder path and every other Phase 5 stage's regression suite.
- **`emit_event` is best-effort.** The bash version wraps every `emit_event` call in `> /dev/null 2>&1 || true` because event emission is a non-fatal causal-log write. The Go port preserves this via `deps.EmitEvent` returning no error — log-and-continue on any emit failure.
