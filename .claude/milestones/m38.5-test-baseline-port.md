## Design

### Goal 1 — `Baseline` struct and JSON shape

```go
// internal/test_baseline/baseline.go
package test_baseline

type Baseline struct {
    RunID        string    `json:"run_id"`
    Timestamp    time.Time `json:"timestamp"`
    Milestone    string    `json:"milestone"`
    ExitCode     int       `json:"exit_code"`
    OutputHash   string    `json:"output_hash"`
    FailureHash  string    `json:"failure_hash"`
    FailureCount int       `json:"failure_count"`
}
```

The on-disk JSON at `${PROJECT_DIR}/.claude/TEST_BASELINE.json` matches bash byte-for-byte — field names, order (run_id, timestamp, milestone, exit_code, output_hash, failure_hash, failure_count), and the ISO-8601 UTC timestamp format (`2026-05-29T14:23:45Z`). Atomic write via tmp + rename. The raw test output goes to `${PROJECT_DIR}/.claude/TEST_BASELINE_OUTPUT.txt`.

### Goal 2 — `Capture` (Tier 1 prerequisite)

```go
type CaptureOptions struct {
    Milestone     string  // _CURRENT_MILESTONE
    RunID         string  // TIMESTAMP
    ProjectDir    string
    TestCmd       string  // TEST_CMD
}

func Capture(ctx context.Context, opts CaptureOptions) (*Baseline, error)
```

Mirrors `capture_test_baseline`:

1. If `TestCmd` is empty or `"true"`, log "no TEST_CMD configured" and return nil baseline (no error).
2. Run TestCmd via `exec.CommandContext("bash", "-c", opts.TestCmd)`, capture combined stdout+stderr.
3. Write raw output to `.claude/TEST_BASELINE_OUTPUT.txt` atomically.
4. Compute output hash (normalize → md5) and failure hash (normalize → extract failure lines → sort → md5).
5. Count failure lines.
6. Write JSON to `.claude/TEST_BASELINE.json` atomically.
7. Emit `test_baseline` causal event with `exit=N, failures=M`.

### Goal 3 — `Has` (run_id-aware staleness check)

```go
func Has(milestone, projectDir string) bool
func ShouldCapture(milestone, runID, projectDir string, testBaselineEnabled bool, testCmd string) bool
```

`Has` mirrors `has_test_baseline` — true iff `.claude/TEST_BASELINE.json` exists and the embedded `milestone` field equals the argument.

`ShouldCapture` mirrors `_should_capture_test_baseline` — checks `TEST_BASELINE_ENABLED`, the `TEST_CMD` config, then run_id staleness. Same-run resume skips re-capture; different-run triggers re-capture; missing run_id (pre-M63 baseline) triggers re-capture (backward compat). The Go port preserves all three branches.

### Goal 4 — `Compare` (Tier 1 router) and `Verdict`

```go
type Verdict int
const (
    VerdictInconclusive Verdict = iota
    VerdictPreExisting
    VerdictNewFailures
)

func Compare(output string, exitCode int, projectDir string) (Verdict, error)
```

Mirrors `compare_test_with_baseline`:

1. If no baseline file → `VerdictInconclusive`.
2. If baseline exit_code == 0 → `VerdictNewFailures` (all current failures are new).
3. If current failure hash == baseline failure hash → `VerdictPreExisting`.
4. If current failure count > baseline failure count → `VerdictNewFailures`.
5. Otherwise → `VerdictInconclusive`.

### Goal 5 — Output normalization helpers

```go
// internal/test_baseline/baseline.go (file-internal package-level)
var (
    reANSI       = regexp.MustCompile(`\x1b\[[0-9;]*[mGKHJ]`)
    reTimestamp  = regexp.MustCompile(`[0-9]{4}-[0-9]{2}-[0-9]{2}[T ][0-9]{2}:[0-9]{2}:[0-9]{2}(\.[0-9]+)?Z?`)
    reFloatSec   = regexp.MustCompile(`[0-9]+\.[0-9]+s`)
    reInSeconds  = regexp.MustCompile(`in [0-9]+ seconds?`)
    reMS         = regexp.MustCompile(`[0-9]+ms`)
    reFloatSecB  = regexp.MustCompile(`[0-9]+\.[0-9]+ seconds?`)
    rePID        = regexp.MustCompile(`(?i)pid\s*[0-9]+`)
    reHexAddr    = regexp.MustCompile(`0x[0-9a-fA-F]+`)

    reFailureLines = regexp.MustCompile(
        `(^FAIL\s|^---\s*FAIL|FAILED|FAILURES?|^ERROR\s|ERROR:|AssertionError|assert.*failed|panic:|failures:)`)
)

func NormalizeTestOutput(in string) string
func ExtractFailureLines(in string) []string
```

The regexes are byte-for-byte equivalents of the `sed -E` patterns in `_normalize_test_output:44-54`. A test asserts that `NormalizeTestOutput` against a fixture containing all matched patterns produces the same output as `sed` would have.

### Goal 6 — Tier 2: stuck detection

```go
type StuckPolicy struct {
    Threshold         int   // TEST_BASELINE_STUCK_THRESHOLD=2
    PassOnStuck       bool  // TEST_BASELINE_PASS_ON_STUCK=false
    PassOnPreexisting bool  // TEST_BASELINE_PASS_ON_PREEXISTING=false (REGRESSION-CANARY M92 DEFAULT)
}

func DefaultStuckPolicy() StuckPolicy {
    return StuckPolicy{
        Threshold:         2,
        PassOnStuck:       false,
        PassOnPreexisting: false,   // CANARY — M92 flipped this from true to false
    }
}

type StuckState struct {
    LastHash          string
    IdenticalCount    int
}

type StuckResult int
const (
    StuckResultNotStuck   StuckResult = iota
    StuckResultAutoPass               // when PassOnStuck=true AND baseline had failures
    StuckResultExit                   // when stuck AND PassOnStuck=false → caller exits
)

func SaveAcceptanceOutput(output string, exitCode int, projectDir string) error
func GetAcceptanceOutputHash(projectDir string) (string, error)
func CheckAcceptanceStuck(state *StuckState, policy StuckPolicy, projectDir string) StuckResult
```

The stuck checker mirrors `_check_acceptance_stuck`:

1. Get current hash.
2. If hash matches `state.LastHash`, increment `IdenticalCount`; else reset to 1 + update `LastHash`, return `StuckResultNotStuck`.
3. If `IdenticalCount < policy.Threshold`, return `StuckResultNotStuck`.
4. Warn about identical failures.
5. If `policy.PassOnStuck` is true:
   - Read baseline exit code. If baseline was clean (exit_code == 0), all current failures are new regressions — **do NOT auto-pass**, return `StuckResultNotStuck` (matches bash safety check).
   - Otherwise return `StuckResultAutoPass`.
6. If `policy.PassOnStuck` is false, return `StuckResultExit`.

## Watch For

- **`TEST_BASELINE_PASS_ON_PREEXISTING` default is `false` — M92 flipped this. PRESERVE.** Earlier versions defaulted to true; auto-passed any pre-existing failure silently; led to operators not noticing baseline drift. M92 made the auto-pass opt-in. The Go port at M38.5 must default `false`. `TestDefaultStuckPolicy_PassOnPreexistingIsFalse` is the regression-canary.
- **`TEST_BASELINE_PASS_ON_STUCK` also defaults `false`.** Two separate flags, both default false. PASS_ON_PREEXISTING is the Tier 1 (compare-time) auto-pass; PASS_ON_STUCK is the Tier 2 (cross-attempt-identical) auto-pass. Different code paths, same conservative default.
- **The safety check inside PASS_ON_STUCK is load-bearing.** `_check_acceptance_stuck:321-333` refuses to auto-pass when baseline exit_code == 0 even if `PassOnStuck=true` — clean baseline means current failures are regressions, not pre-existing. The Go port preserves this safety check. A test that fakes baseline exit_code=0 + PassOnStuck=true + matching-hash asserts `StuckResultNotStuck` (NOT AutoPass).
- **The JSON field order matters for hash stability.** `printf` in bash emits fields in a specific order (run_id, timestamp, milestone, exit_code, output_hash, failure_hash, failure_count). Go's `encoding/json` orders by struct declaration. Define the `Baseline` struct fields in that exact order so JSON output is byte-identical. (A test that captures with Go and compares the JSON byte-for-byte to a bash-captured baseline catches this.)
- **`NormalizeTestOutput` regexes are tuned against real test-framework output.** The set covers pytest, go test, jest/mocha, cargo, JUnit. Don't simplify or "improve" the regexes — they were dogfooded into shape. Treat them as data, not code.
- **The acceptance output file is `.claude/test_acceptance_output.tmp` (lowercase, .tmp suffix).** The path is operator-visible (some operators tail it during long runs). Preserve the exact path.
- **Atomic write via tmp + rename, NEVER `os.WriteFile` directly.** The dashboard and milestone tracker may read these files concurrently. A non-atomic write produces partial reads at the worst possible moment.
- **`lib/test_baseline_cleanup.sh` STAYS bash through M38.** It provides `cleanup_stale_baselines` (called by acceptance gating in `lib/milestone_acceptance.sh`) and `get_baseline_exit_code` (a one-line wrapper). M38.5 modifies only the one function that previously sourced the deleted file; the rest of `test_baseline_cleanup.sh` stays. Its port is deferred to a future milestone (likely with the acceptance-gate port).
- **`emit_event "test_baseline" ...` causal event must be preserved.** Same shape as M38.4's `test_audit` event. The Go port calls `causal.EmitEvent` from `internal/causal`.
