#### Milestone 1.3: Self-Host Harness and Documentation

Add the self-host check script that builds the Go binary, prepends `bin/` to `$PATH`, and asserts the binary is reachable. Add the one-page dev-onboarding doc. End state: `scripts/self-host-check.sh` runs in CI-safe mode by default; the full dry-run tier is gated behind an env var; `docs/go-build.md` documents the build flow.

Files to create:
- `scripts/self-host-check.sh`
- `docs/go-build.md`

Acceptance criteria:
- `scripts/self-host-check.sh` builds the Go binary via `make build`, prepends `bin/` to `$PATH`, exercises the dispatcher routing matrix, and asserts `tekhton --version` output matches the trimmed contents of `VERSION`.
- The script exits 0 in its default (CI-safe) mode.
- The full `tekhton.sh --dry-run` smoke (which calls live Claude CLI agents) is gated behind `TEKHTON_SELF_HOST_DRY_RUN=1`.
- The script is idempotent — safe to run twice in the same CI job; no lockfile or state-file writes that fail on re-run.
- `docs/go-build.md` exists (~80 lines, one page max) and covers: prerequisite Go install, `make` targets (`build`, `test`, `build-all`, `clean`), cross-compile output layout, how the binary is wired into `$PATH` during pipeline runs, where to find CI artifacts.
- No file under `lib/`, `stages/`, `prompts/`, or `tools/` is modified.
- `bash tests/run_tests.sh` produces identical output before and after this milestone (parity check archived to artifact).

Watch For:
- The self-host check must remain idempotent across re-runs in the same CI job.
- The Go binary's presence on `$PATH` is observed but unused by the bash pipeline — do not introduce any production code path that depends on it.
- Default mode must not require Claude CLI auth; only the `TEKHTON_SELF_HOST_DRY_RUN=1` tier does.
- Documentation is dev-onboarding, not a manual — resist scope creep beyond one page.

Seeds Forward:
- m05+ supervisor introduces the first bash → Go call site (`tekhton supervise`); the harness pattern from this milestone is the template for verifying that integration.
- The `tekhton --version` parity check becomes the single source of truth across bash and Go per the VERSION file convention.
