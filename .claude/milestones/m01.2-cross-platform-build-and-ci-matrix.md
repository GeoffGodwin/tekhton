#### Milestone 1.2: Cross-Platform Build and CI Matrix

Add cross-compilation to five OS/arch targets and the GitHub Actions workflow that builds, vets, tests, and lints the Go module. End state: pushing to `main` or `feature/GoWedges` triggers `go-build.yml` with three green jobs and five binary artifacts.

Files to create:
- `.github/workflows/go-build.yml`

Files to modify:
- `Makefile` (add `build-all` target)

Acceptance criteria:
- `Makefile` exposes a `build-all` target that cross-compiles to `linux/amd64`, `linux/arm64`, `darwin/amd64`, `darwin/arm64`, `windows/amd64`. Output: `bin/tekhton-<os>-<arch>[.exe]`. CGO disabled everywhere.
- `make build-all` from a Linux host produces all five expected binaries with no CGO errors.
- `.github/workflows/go-build.yml` triggers on PR + push to `main` and `feature/GoWedges`.
- The workflow has three jobs:
  1. Build job on `ubuntu-latest` runs `make build-all` and uploads five binaries as workflow artifacts.
  2. Vet+test job runs `go vet ./...` and `go test ./...`.
  3. Lint job runs `golangci-lint` with the "advanced" preset against `./...`.
- `actions/setup-go` reads `go-version-file: go.mod` to keep local/CI Go versions aligned.
- All three jobs pass green on the V4 branch.
- `golangci-lint run ./...` is clean.
- The workflow does NOT run `bash tests/run_tests.sh`.
- No `bin/` artifact appears in `git status` after `make build-all`.

Watch For:
- CGO must stay disabled everywhere — any cgo dep breaks the static-binary promise.
- `darwin/*` cross-compile only works cleanly with CGO off; verify locally on Linux before relying on CI.
- Pin `golangci-lint` to a known version to avoid lint drift breaking CI mid-flight.
- No coverage gate yet — that lands in m04.

Seeds Forward:
- Milestone 1.3 reuses `make build` (not `build-all`) for the self-host check.
- m04 hardening lands the 80% coverage gate against this workflow.
