#### Milestone 1.3: Self-Host Check + Developer Documentation

Add `scripts/self-host-check.sh` that builds the Go binary via `make build`, prepends `bin/` to `$PATH`, exercises the dispatcher routing matrix, and asserts `tekhton --version` matches `VERSION`. The full `tekhton.sh --dry-run` smoke run (which needs live Claude CLI auth) is gated behind `TEKHTON_SELF_HOST_DRY_RUN=1` so the script stays CI-safe by default. Also add `docs/go-build.md` — a one-page (~80 lines) developer-onboarding doc covering Go install prerequisites, `make` targets, cross-compile output layout, `$PATH` wiring during pipeline runs, and CI artifact location.

Files to create:
- `scripts/self-host-check.sh`
- `docs/go-build.md`

Acceptance criteria:
- `scripts/self-host-check.sh` exits 0 in default mode on a clean checkout: builds the Go binary, prepends `bin/` to `$PATH`, exercises the dispatcher routing matrix, asserts `tekhton --version` matches `VERSION`.
- The script is idempotent — running it twice in the same shell produces the same exit code and no leftover state files.
- With `TEKHTON_SELF_HOST_DRY_RUN=1` set, the script additionally runs `tekhton.sh --dry-run` against a fixture task (locally, with auth). Default mode skips this tier.
- The script does not modify any file under `lib/`, `stages/`, `prompts/`, or `tools/`.
- `bash tests/run_tests.sh` produces identical output before and after this sub-milestone (parity check archived to artifact).
- `docs/go-build.md` exists and covers: Go install prerequisites, `make build` / `make build-all` / `make test` / `make clean` usage, cross-compile output filename layout, how `bin/` is prepended to `$PATH` by the self-host check, and where CI artifacts are downloaded from.
- Doc is one page (~80 lines max) — onboarding, not a manual.
- The Go binary's presence on `$PATH` during the self-host check is observed but invoked by no bash code path.

Watch For:
- Self-host check must remain idempotent — no lockfile or state-file writes that fail on re-run.
- The dispatcher routing-matrix exercise must not require Claude CLI auth; reserve auth-dependent paths for the gated `TEKHTON_SELF_HOST_DRY_RUN=1` tier.
- Do not couple the script to a specific working directory; resolve repo root via `git rev-parse --show-toplevel` or equivalent.
- Doc should reference `make` targets by name, not duplicate their commands — the Makefile is the source of truth.

Seeds Forward:
- m02's `tekhton causal emit` will be the first bash-invoked Go call site; the `$PATH` plumbing proven here is what makes that invocation reachable.
- m05+ supervisor wedge will extend this self-host check with assertions on `tekhton supervise` behavior.
- Versioning convention (`tekhton --version` as single source of truth across bash and Go) is locked in by the assertion added here.
