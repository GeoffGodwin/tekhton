## Design

### Sequencing note

m27.2 depends strictly on m27.1 — without `.tekhton/M27_INVENTORY.md` there is no canonical work list. Operators can re-run `scripts/audit-bash-env.sh` to regenerate the inventory at any time if the original is stale or accidentally deleted.

### Goal 1 — Mechanical sweep

For each entry in the inventory, edit the file to wrap the variable read in a default expansion:

```bash
# Before (the inventory shows the line + varname)
echo "$MILESTONE_MODE"

# After
echo "${MILESTONE_MODE:-false}"
```

Use the canonical default for each variable. The canonical defaults live in two places:

- `internal/config/defaults.go` — pipeline.conf keys (e.g. `CODER_MAX_TURNS=40`, `MILESTONE_DAG_ENABLED=true`, `CONTEXT_BUDGET_PCT=50`).
- `internal/proto/agent_v1.go` and `internal/runner/env.go:AsKV` — StageEnvV1 fields (e.g. `MILESTONE_MODE=false`, `AUTO_ADVANCE=false`, `HUMAN_NOTES_TAG=""`).

A canonical-default table goes in `docs/v4-env-contract.md` (created in m27.3) but for m27.2 the implementer copies values directly from the Go source comments.

### Goal 2 — Verify after sweep

Run `bash scripts/audit-bash-env.sh` against the full tree. Expected output: nothing. Expected exit: 0. If any site still flags, the sweep is incomplete — either the implementer missed a site, or the `${VAR:-default}` form does not match the script's "guarded" pattern (rare; would mean editing the audit's regex to be more permissive, not the consumer code).

### Goal 3 — Spot-check changed files still parse and run

Each edited file must still pass `bash -n <file>` (syntax check). The `BUILD_CHECK_CMD` setting in `.claude/pipeline.conf` already enforces this for the whole pipeline; m27.2 just adds a "check before commit" step.

The full test suite (`bash tests/run_tests.sh`) must continue to pass — the sweep is a strict improvement under `set -u` and should not break any test that wasn't already broken.

### Goal 4 — Delete the inventory

On close, `git rm .tekhton/M27_INVENTORY.md`. The inventory was a transient working artifact; the canonical record going forward is `scripts/audit-bash-env.sh` (which returns nothing once the sweep is complete) plus m27.3's CI gate.

## Watch For

- **Dogfood stability invariant.** Every edit in m27.2 is strictly safer under `set -u` than the original. tekhton-stable can be safely rebuilt at any point during or after the sweep — partial sweeps are still net improvements. **However**: each rebuild should happen at a clean commit, not mid-edit, to avoid the `bash -n` mismatch between source and binary.
- **Default-value drift.** Do not invent defaults. Use the contract-defined value from `internal/config/defaults.go` or the StageEnvV1 zero value. A wrong default (e.g. `${CODER_MAX_TURNS:-100}` when the contract says 40) silently changes pipeline behavior. When in doubt, run `tekhton config defaults --emit shell | grep VARNAME` to see the actual value.
- **`${VAR:?...}` is also acceptable.** For variables that genuinely should never be empty (e.g. `${TEKHTON_HOME:?TEKHTON_HOME required}`), the assertion form is appropriate. The audit treats both `${VAR:-...}` and `${VAR:?...}` as guarded.
- **Files exempt from the sweep.** Anything under `lib/_archive/`, `lib/*_test.sh`, `tools/` (Python), and `tests/testdata/` is out of scope. The audit script already excludes these; if a file shows up in the inventory that shouldn't be in scope, fix the audit script's exclusion list as part of this milestone (not a separate one).

## Seeds Forward

- **m27.3 (Parity Gate + CI Wiring):** Will assume `bash scripts/audit-bash-env.sh` returns clean on the m27.2 close commit. The CI gate verifies that every PR keeps it clean. Without m27.2 the gate would fail immediately on the existing tree.
- **Future bash subsystems:** Any new bash file landing in `lib/` or `stages/` after m27 closes is held to the same audit standard via the CI gate. New code can't reintroduce unguarded reads silently.
