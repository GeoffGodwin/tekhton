## Design

### Sequencing note

m32.2 is the heart of the diagnose port. It's also the most-rules-touched milestone in Phase 5: 18 separate match-function bodies, each with its own input-signal vocabulary and confidence calibration. Two non-obvious sequencing constraints:

1. **Port the registry first, the rules second.** `registry.go` declares the priority order and the `Register()` API. The first rule (`_rule_unknown` — the simplest, always-matches fallback) ports next as a smoke test that the registry wiring works. Then the rest in priority order, top-down. Top-down because if a higher-priority rule short-circuits a fixture, lower-priority rules don't need to be tested against that fixture — the test matrix is smaller.

2. **Resilience rules port LAST.** They are the highest-stakes parity surface (M133 operator vocabulary) and have the most input signals (LAST_FAILURE_CONTEXT primary/secondary cause slots, raw log evidence patterns, RUN_SUMMARY signal correlation). Porting them late means the engine + simpler rules are already passing v3 baselines, so any baseline diff during resilience-rule work is localized to that rule.

### Goal 2 — Rule implementation pattern

Every rule follows the same shape:

```go
// internal/diagnose/rules/core.go
type MaxTurns struct{}

func (MaxTurns) Name() string { return "_rule_max_turns" }

func (MaxTurns) Match(c *diagnose.Context) (diagnose.Diagnosis, bool) {
    // Reproduce lib/diagnose_rules.sh::_rule_max_turns logic:
    //   1. Check _DIAG_LAST_CLASSIFICATION == "MAX_TURNS_EXHAUSTED"  → high confidence
    //   2. Check terminal event type=error reason="max_turns"        → high
    //   3. Check exit_reason field contains "max_turns"              → medium
    //   4. Fallthrough → no match
    if c.Classification == "MAX_TURNS_EXHAUSTED" {
        return diagnose.Diagnosis{
            Classification: "MAX_TURNS_EXHAUSTED",
            Confidence:     diagnose.ConfidenceHigh,
            Stage:          c.Stage,
            Suggestions: []string{
                "Coder stage hit max-turns ceiling — increase CODER_MAX_TURNS in pipeline.conf,",
                "or break the task into smaller milestones via `tekhton plan --split`.",
            },
        }, true
    }
    // ... (sources 2-3)
    return diagnose.Diagnosis{}, false
}
```

Each rule's `Match` function is a direct port of the bash function body, with:
- `_DIAG_LAST_CLASSIFICATION` → `c.Classification`
- `_DIAG_PRIMARY_SIGNAL` → `c.PrimarySignal`
- `_DIAG_PIPELINE_STAGE` → `c.Stage`
- `_DIAG_PIPELINE_OUTCOME` → `c.Outcome`
- ...etc.

Regex patterns the bash version anchors as `_RULE_FOO_REGEX='...'` move into `errors.Patterns` via `internal/errors/patterns.go` (m17's home) if they're new. If a pattern already exists there, the rule calls `errors.MatchPattern("FOO", input)` instead of declaring its own.

### Goal 3 — Resilience-arc rules (the high-stakes set)

```go
// internal/diagnose/rules/resilience.go

type UIGateInteractiveReporter struct{}

func (UIGateInteractiveReporter) Name() string { return "_rule_ui_gate_interactive_reporter" }

func (UIGateInteractiveReporter) Match(c *diagnose.Context) (diagnose.Diagnosis, bool) {
    // Bash version checks 4 sources in priority order:
    //   1. LAST_FAILURE_CONTEXT primary_signal == "ui_timeout_interactive_report" → high
    //   2. LAST_FAILURE_CONTEXT classification == "UI_INTERACTIVE_REPORTER"       → high
    //   3. Raw log evidence: BUILD_RAW_ERRORS or .claude/logs match
    //      `Serving HTML report at https?://`                                      → medium
    //   4. RUN_SUMMARY primary_signal + route_taken correlation                    → medium
    // Source 3 is anchored — Playwright's stderr always emits a URL on that line;
    // agent-authored markdown that *quotes* the marker doesn't have the URL.
    // Combined with the .log/.jsonl filter on the logs_dir scan, this prevents
    // the rule from self-triggering when tekhton dogfoods on its own codebase.

    if c.PrimarySignal == "ui_timeout_interactive_report" {
        return d(diagnose.ConfidenceHigh, c.Stage), true
    }
    if c.Classification == "UI_INTERACTIVE_REPORTER" {
        return d(diagnose.ConfidenceHigh, c.Stage), true
    }
    if matchedInRawLogs(c, regexUIGateInteractive) {
        return d(diagnose.ConfidenceMedium, c.Stage), true
    }
    // Source 4
    if c.PrimarySignal == "html_reporter_timeout" &&
       c.SecondarySource == "preflight_route_taken=ui_gate_interactive" {
        return d(diagnose.ConfidenceMedium, c.Stage), true
    }
    return diagnose.Diagnosis{}, false
}

var regexUIGateInteractive = regexp.MustCompile(`Serving HTML report at https?://`)
// NOTE: this regex lives in resilience.go because it's not a *classification*
// regex (it doesn't categorize an unknown log); it's a *match-evidence*
// regex (it confirms the route the rule already suspects). The wedge-audit's
// no-regexp rule has an allowlist exception for *_match.go suffix... wait no,
// review this — the simpler answer is: this regex should move to
// internal/errors/patterns.go under a new pattern name UI_GATE_INTERACTIVE_HTML
// and resilience.go calls errors.MatchPattern("UI_GATE_INTERACTIVE_HTML", input).

func d(conf diagnose.Confidence, stage string) diagnose.Diagnosis {
    return diagnose.Diagnosis{
        Classification: "UI_GATE_INTERACTIVE_REPORTER",
        Confidence:     conf,
        Stage:          stage,
        Suggestions: []string{
            "Playwright opened an interactive HTML reporter — set `reporter: 'list'` or",
            "let preflight auto-patch via PREFLIGHT_UI_CONFIG_AUTO_FIX=true.",
            "See docs/v4-resilience.md#ui-gate for the full recovery path.",
        },
    }
}
```

The "wait no" inline note above is intentional — it documents the canonical decision: **all classification + match regexes live in `internal/errors/patterns.go` (m17 home).** Rules import them by pattern name via `errors.MatchPattern(...)`. The `wedge-audit.sh` extension enforces this. Resolution before m32.2 close: every regex in the design draft moves to `patterns.go`.

### Goal 4 — Per-rule + cross-rule tests

Each rule file gets a sibling `_test.go` with table-driven scenarios:

```go
// internal/diagnose/rules/core_test.go
func TestMaxTurns_Match(t *testing.T) {
    cases := []struct {
        name string
        ctx  *diagnose.Context
        want bool
        wantConf diagnose.Confidence
    }{
        {"primary_signal_match",
            &diagnose.Context{Classification: "MAX_TURNS_EXHAUSTED"},
            true, diagnose.ConfidenceHigh},
        {"exit_reason_fallback",
            &diagnose.Context{ExitReason: "coder max_turns reached"},
            true, diagnose.ConfidenceMedium},
        {"no_signal",
            &diagnose.Context{Outcome: "failure"},
            false, ""},
    }
    for _, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            d, ok := MaxTurns{}.Match(tc.ctx)
            if ok != tc.want { t.Fatalf("match: want %v got %v", tc.want, ok) }
            if ok && d.Confidence != tc.wantConf { t.Errorf("confidence: want %s got %s", tc.wantConf, d.Confidence) }
        })
    }
}
```

## Watch For

- **Resilience-arc rules are the highest-stakes parity surface.** M133 vocabulary — `UI_GATE_INTERACTIVE_REPORTER`, `BUILD_FIX_EXHAUSTED`, `PREFLIGHT_INTERACTIVE_CONFIG` — is operator-facing and consumed by downstream CI hooks. A whitespace change in a suggestion-text string is a parity-gate failure. The 15-baseline test catches this — do not "fix" mismatched output by editing the baseline; fix the rule.
- **Match-evidence regexes belong in `internal/errors/patterns.go`, not the rule files.** The m17 boundary forbids rule files from importing `regexp`. If a rule needs a new regex pattern, add it to `patterns.go` with a `MatchPattern` API call. The `wedge-audit.sh` extension enforces this — a regression test in `scripts/test_wedge_audit.sh` plants a violation to verify the audit catches it.
- **The bash registry has 18 entries but `diagnose_rules.sh` defines 8 functions, `diagnose_rules_extra.sh` defines 6 (NOT 7) — one of the entries in the "extra" file is a shared helper, not a rule.** Cross-check `diagnose_rules_registry.sh` line-by-line against the function definitions before declaring the count "18". The acceptance criterion enumerates 18 by name; if the actual count differs, fix this milestone's design before opening it.
- **`MixedClassification` rule is the only LOW-confidence rule in the registry.** Bash returns `confidence=low` for this match because it explicitly captures the M127 "we don't know which kind of failure this is" case. Operators have grep-pipelines that ignore low-confidence diagnoses; the Go port must preserve `ConfidenceLow`, not "upgrade" it to medium because the rule matched.
- **Source-ordering inside each rule is load-bearing.** The resilience rules check sources 1→4 in priority order (primary_signal → classification → raw log → run_summary correlation). The first source that fires wins, even if a later source would have produced a different confidence. Do not "consolidate" the sources into a single check — the priority is the contract.
- **`registry.go`'s slice initialization order MUST exactly match `diagnose_rules_registry.sh:DIAGNOSE_RULES`.** The order-mismatch test in `registry_test.go` is the canary, but the test itself stores the expected order as a hardcoded string slice — make sure THAT slice was copy-pasted from the bash file at m32.2 open, not regenerated from the Go side (which would make the test self-referential).
- **`_rule_unknown` always matches.** It's the always-true fallback. The Go port (`Unknown{}.Match`) must return `(Diagnosis{Classification: "UNKNOWN", Confidence: ConfidenceLow, ...}, true)` unconditionally. Tests that exercise the no-match path of any OTHER rule must populate a `Context` that *also* skips `Unknown` — easy to get wrong; use `eng.Run` against a fixture instead of calling `Match` directly when testing fallthrough behavior.
- **Do NOT modify `lib/diagnose*.sh` files in m32.2.** They stay on disk through close. Bash callers (`tekhton --diagnose` early-check) continue to route through bash. M32.3 owns the delete + rewire. Premature delete here breaks the inline classifier path in `stages/coder_buildfix.sh` because the m17 `tekhton diagnose classify` surface routes through the bash classifier, not the m32 engine.
