# m28.1 — Serena Template + Resolver Fix

## Overview

| Item | Detail |
|------|--------|
| **Arc motivation** | First of three subtasks in [m28](m28-serena-mcp-template-and-validation.md). Fixes the actual broken invocation so a fresh `tekhton --setup-indexer --with-lsp` against an empty project produces a config that boots Serena correctly. After this subtask the *generation* path is correct; pre-existing broken configs are still in place (handled in 28.3) and the runtime still trusts the resolver without probing (handled in 28.2). Each of those is non-fatal — claude already tolerates a broken MCP server — so tekhton remains dogfoodable between subtasks. |

(3) Add `{{SERENA_BIN}}` substitution to `_resolve_mcp_config` and `tools/setup_serena.sh`; remove `{{SERENA_PYTHON}}` substitution from both. ## Design

### Goal 1 — New template shape

Replace the template body with:

```json
{
  "mcpServers": {
    "serena": {
      "command": "{{SERENA_BIN}}",
      "args": [
        "start-mcp-server",
        "--project", "{{PROJECT_DIR}}",
        "--transport", "stdio",
        "--log-level", "ERROR"
      ],
      "cwd": "{{SERENA_PATH}}",
      "env": {
        "SERENA_LANGUAGE_SERVERS": "{{LANGUAGE_SERVERS}}"
      }
    }
  }
}
```

`{{SERENA_PYTHON}}` is removed entirely — no consumer outside this template substitutes it. `{{SERENA_BIN}}` takes its place and points at the console-script entrypoint.

`--context` is deliberately omitted. Serena's default `desktop-app` works and is the conservative choice; `ide-assistant` is documented as the recommended context for CLI agents but the surface delta hasn't been validated against Claude Code's tool-discovery flow. If a follow-up reveals a real ergonomics gap, switching is a one-line change with no schema impact.

### Goal 2 — `_resolve_serena_paths` extension

Add at module scope alongside the existing `_SERENA_PYTHON=""` declaration (currently `lib/mcp.sh:24`):

```bash
_SERENA_BIN=""
```

Inside `_resolve_serena_paths`, after `_SERENA_DIR="$serena_path"` (currently line 97):

```bash
# Resolve the console-script entrypoint. Serena's package ships no
# __main__, so `python -m serena` fails at import time; the binary is
# the only supported invocation surface.
if [[ -f "${venv_dir}/bin/serena" ]]; then
    _SERENA_BIN="${venv_dir}/bin/serena"
elif [[ -f "${venv_dir}/Scripts/serena.exe" ]]; then
    _SERENA_BIN="${venv_dir}/Scripts/serena.exe"
else
    return 1
fi
```

The dual lookup mirrors the existing `_SERENA_PYTHON` resolution one level above (POSIX `bin/python` vs Windows `Scripts/python.exe`) — same layout, same fallback shape.

### Goal 3 — Template substitution paths

`lib/mcp.sh::_resolve_mcp_config` sed block (currently lines 132–137):

```bash
sed \
    -e "s|{{SERENA_BIN}}|${_SERENA_BIN}|g" \
    -e "s|{{PROJECT_DIR}}|${PROJECT_DIR}|g" \
    -e "s|{{SERENA_PATH}}|${_SERENA_DIR}|g" \
    -e "s|{{LANGUAGE_SERVERS}}|${lang_servers}|g" \
    "$template" > "$default_config"
```

`{{SERENA_PYTHON}}` substitution is removed. `tools/setup_serena.sh` (lines 232–237) receives the same change; additionally, after the venv-creation step in `setup_serena.sh`, set:

```bash
SERENA_BIN="${SERENA_DIR}/.venv/bin/serena"
[ -x "$SERENA_BIN" ] || SERENA_BIN="${SERENA_DIR}/.venv/Scripts/serena.exe"
```

## Watch For

- **Existing project configs are NOT touched in this subtask.** The `_resolve_mcp_config` short-circuit on `[[ -f "$default_config" ]]` is intentional for now — m28.3 handles stale-config migration. Don't try to be helpful here; you'd be reaching into 28.3's scope and the stale-detection logic doesn't exist yet.
- **POSIX vs Windows path resolution.** `_SERENA_PYTHON` already handles both — `_SERENA_BIN` must follow the same dual lookup. Skipping the Windows branch breaks Windows CI silently because `_resolve_serena_paths` returns 1 and the resolver moves on to template-generation without `_SERENA_BIN` set.
- **No probe added yet.** This subtask only fixes generation. A correctly-generated config can still fail at runtime if rust-analyzer is missing or the venv is corrupt. m28.2 adds the probe; do not pre-empt it.
- **`SERENA_LANGUAGE_SERVERS=auto` semantics are unchanged.** Serena interprets the env var; the template just passes it through. Don't rename it or "improve" the default.

## Seeds Forward

- **m28.2** needs the resolved `_SERENA_BIN` to drive its probe. Make sure `_SERENA_BIN` is set on every successful `_resolve_serena_paths` exit — if 28.2 has to fall back to deriving the path from `_SERENA_DIR`, the abstraction has leaked.
- **m28.3**'s stale-config detector keys on the pre-28.1 broken shape that this subtask is replacing. Cross-reference the exact substring `"args": [` followed by `"-m", "serena"` so the detector matches what 28.1 used to emit, and only that.
