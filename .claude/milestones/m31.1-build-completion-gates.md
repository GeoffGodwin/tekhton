## Design

### Sequencing note

m31.1 ships a *partial* `internal/gates/` package. The `UIPhase` interface is defined and registered, but the concrete implementation returns Skip when `UI_TEST_CMD` is unset (which is the common case in all built-in fixtures and the m31.1 dogfood run). When `UI_TEST_CMD` *is* set, the build gate's UIPhase step delegates back to the bash `_run_ui_test_phase` through a temporary `internal/gates/ui_bash_shim.go` that execs `bash -c "source lib/gates_ui.sh; source lib/gates_ui_helpers.sh; _run_ui_test_phase '$stage_label'"`. The shim deletes in m31.2 when `internal/gates/ui.go` lands the native implementation.

Reason for the shim: the build gate's phase-ordering invariant must hold the moment `lib/gates.sh` deletes. If m31.1 deleted `lib/gates.sh` but left `lib/gates_ui.sh` orphaned (no bash caller), m31.2 would inherit a half-broken state where the UI phase silently never fires. The shim keeps the UI phase wired through the bash files until m31.2's port replaces them.

### Goal 1 — `internal/gates/build.go` — `BuildGate` orchestrator

Port `lib/gates.sh:run_build_gate`. Five phases in fixed order:

```go
type Phase interface {
    Name() string
    Run(ctx context.Context, in *PhaseInput) PhaseResult
}

type BuildGate struct {
    Env        *proto.StageEnvV1
    Phases     []Phase  // analyze, compile, constraints, ui_test, ui_validation
    Timeout    time.Duration
    Errors     ErrorsWriter
    Remediator Remediator
    Clock      func() time.Time
}

func (g *BuildGate) Run(ctx context.Context, stageLabel string) error {
    g.Errors.Reset()  // rm -f BUILD_ERRORS_FILE + BUILD_RAW_ERRORS_FILE
    g.Remediator.Reset()
    deadline := g.Clock().Add(g.Timeout)
    for _, p := range g.Phases {
        if g.Clock().After(deadline) {
            g.Errors.WriteTimeout(stageLabel, g.Timeout)
            return ErrGateTimeout
        }
        remaining := deadline.Sub(g.Clock())
        result := p.Run(ctx, &PhaseInput{StageLabel: stageLabel, Remaining: remaining})
        if result.Status == Fail {
            return fmt.Errorf("build gate: %s: %w", p.Name(), result.Err)
        }
    }
    g.Errors.ClearOnPass()
    return nil
}
```

Order matches `lib/gates.sh:106-208`:

1. `AnalyzePhase` (always)
2. `CompilePhase` (only when `BUILD_CHECK_CMD` is non-empty — gated by phase's own short-circuit)
3. `ConstraintsPhase` (only when `DEPENDENCY_CONSTRAINTS_FILE` is set and exists)
4. `UIPhase` (m31.1 ships a bash-shim implementation; m31.2 replaces with native)
5. `UIValidationPhase` (only when the M29 runtime symbol `run_ui_validation` is registered — preserved via the Go `Remediator` interface)

A `TestBuildGate_PhaseOrder` test asserts the registered order via reflection on the `Phases` slice; reordering trips the test red.

### Goal 2 — `internal/gates/phases.go` — `AnalyzePhase` and `CompilePhase`

Port `_gate_phase_analyze` and `_gate_phase_compile` from `lib/gates_phases.sh`. Each phase:

1. Computes effective timeout = min(phase_timeout, remaining_gate_time).
2. Execs the command (`ANALYZE_CMD` or `BUILD_CHECK_CMD`) via `exec.CommandContext` with the effective timeout. `context.DeadlineExceeded` maps to exit 124 — treated as pass with warning (matches bash `timeout 124` semantics).
3. Greps output for `ANALYZE_ERROR_PATTERN` / `BUILD_ERROR_PATTERN` matches.
4. On error: attempts M54 remediation via the `Remediator` interface; if remediation succeeds, re-runs the phase once.
5. Writes the raw stream (`BUILD_RAW_ERRORS_FILE`) and annotated section (`BUILD_ERRORS.md`) using `ErrorsWriter`.

Critical byte-identity points:

| Bash behavior | Go equivalent |
|---------------|---------------|
| `printf '%s\n' "$analyze_errors" > "$BUILD_RAW_ERRORS_FILE"` | `os.WriteFile(rawPath, append([]byte(errs), '\n'), 0o644)` — single trailing newline only |
| `printf '%s\n' "$compile_errors" >> "$BUILD_RAW_ERRORS_FILE"` | `os.OpenFile(rawPath, O_APPEND\|O_CREATE\|O_WRONLY, 0o644)` — append mode on the compile phase |
| `echo "# Build Errors — $(date '+%Y-%m-%d %H:%M:%S')"` | `fmt.Fprintf(w, "# Build Errors — %s\n", clock().Format("2006-01-02 15:04:05"))` |
| `echo "## Stage"` / `echo "${stage_label}"` | `fmt.Fprintf(w, "## Stage\n%s\n\n", stageLabel)` |
| Per-section: `echo "## Analyze Errors"` / fenced code block | Identical Markdown structure, identical fence ``` ``` markers |

`internal/gates/phases_test.go` table-drives every combination of (phase, ANALYZE_ERROR_PATTERN value, command output) and asserts byte-equality against captured bash baselines.

### Goal 3 — `internal/gates/completion.go` — `CompletionGate`

Port `run_completion_gate` from `lib/gates_completion.sh`. Five behavioral branches preserved:

```go
func (g *CompletionGate) Run(ctx context.Context) error {
    status := g.parseStatus(g.SummaryFile)  // awk-equivalent parse of ## Status
    switch {
    case strings.Contains(status, "IN PROGRESS"):
        return ErrInProgress
    case strings.Contains(status, "COMPLETE"):
        g.warnSummaryDrift()  // M21 drift check
        return g.runTestCmd(ctx)
    case g.isSubstantiveWork():  // M86: substantive work check
        return ErrSubstantiveNoStatus
    default:
        return ErrNoStatus
    }
}
```

Test enforcement path (M63 + M92):

```go
func (g *CompletionGate) runTestCmd(ctx context.Context) error {
    if !g.testEnabled() { return nil }
    if g.Dedup.CanSkip() {
        g.Dedup.RecordEvent()
        return nil
    }
    out, exit := g.execTestCmd(ctx)
    if exit == 0 {
        g.Dedup.RecordPass()
        return nil
    }
    if g.Baseline.HasBaseline() {
        if g.Baseline.Compare(out, exit) == BaselinePreExisting {
            if g.preExistingPassEnabled() { return nil }
            return ErrCompletionPreExisting
        }
    }
    return ErrCompletionNewFailure
}
```

The M27.2 read-from-/dev/tty hang is now fixed at the prompt level, but the completion gate's `exec.CommandContext` for TEST_CMD MUST explicitly set `cmd.Stdin = nil` (or `os.DevNull`) so a regression at the prompt level doesn't re-surface here. A test in `completion_test.go` runs the gate with `stdin=os.DevNull` and asserts no blocking.

The summary-drift auto-append (`_warn_summary_drift`) and the M86 substantive-work check call into shared helpers in `internal/coder/` if those exist by m31.1 land; otherwise the helpers live in `internal/gates/completion_helpers.go` and migrate later.

### Goal 6 — Parity gate

`tests/test_gates_parity.sh` drives `tekhton gate build` and `tekhton gate completion` against captured baselines under `tests/testdata/gates/`. Eight scenarios, each a self-contained fixture directory:

| Scenario | Fixture | Asserts |
|----------|---------|---------|
| analyze-pass | `analyze_clean/` | exit 0, no `BUILD_ERRORS.md`, no `BUILD_RAW_ERRORS.txt` |
| analyze-fail | `analyze_dirty/` | exit 1, `BUILD_ERRORS.md` H1 + `## Stage` + `## Analyze Errors` sections byte-identical to baseline (after timestamp normalization) |
| compile-pass | `compile_clean/` | exit 0, no error files |
| compile-fail | `compile_dirty/` | exit 1, `BUILD_ERRORS.md` `## Compile Errors` section byte-identical |
| completion-pass | `completion_pass/` | exit 0, TEST_CMD invoked exactly once |
| completion-fail-tests | `completion_test_fail/` | exit 1, "TEST_CMD exited" warning |
| completion-fail-status | `completion_no_status/` | exit 1, "no clear Status field" warning |
| gate-timeout | `gate_timeout/` | exit 1, synthetic `# Build Errors — <ts>` H1 with `## Gate Timeout` section |

Each scenario runs the captured bash baseline first (against the deleted-but-recoverable `git show HEAD~1:lib/gates.sh` if necessary) and the Go gate second, then diffs the outputs. Pass requires byte-equality on the raw stream and structural equality on the markdown after timestamp normalization.

## Watch For

- **The bash `set -e` semantics differ subtly from Go error propagation.** `run_build_gate` uses early-return on phase failure but `_phase_end "build_gate"` MUST still fire (see `gates.sh:107-108`). Mirror with `defer g.phaseEnd("build_gate")` in the Go `Run` so a phase failure still emits the phase-end event the M58 telemetry consumer expects.
- **`_warn_summary_drift` auto-appends to `CODER_SUMMARY_FILE`.** The Go port mutates the file too — preserve the exact `## Files Modified (auto-detected)` section header and the `` `${f}` `` list bullet format. The downstream review-stage prompt template greps for this section.
- **The M54 remediation re-run is bounded to ONE retry per phase.** Look at `_gate_phase_analyze:91-103` — after one successful remediation the phase re-runs once; if it fails again, no further retries. The Go port preserves the "one retry max" invariant; an off-by-one here is the kind of bug that surfaces as flaky pipeline behavior, not a hard failure.
- **`BUILD_RAW_ERRORS.txt` is append-mode for compile after truncate-mode for analyze.** `_gate_write_analyze_errors:20` uses `>` (truncate); `_gate_write_compile_errors:116` uses `>>` (append). The Go port must do the same — a regression that truncates the compile phase loses the analyze stream and the m17 classifier sees only compile errors, missing the full picture.
- **The completion gate's TEST_CMD invocation is the M27.2 hang site.** Set `cmd.Stdin = bytes.NewReader(nil)` (or `os.DevNull`) explicitly. Do NOT rely on the parent process having no controlling TTY — under `tekhton run` the parent is a Go process with stdin still connected to the user's terminal, and TEST_CMD's `read < /dev/tty` would still hang.
- **The bash shim must use absolute paths.** `TEKHTON_BIN` may be unset on developer machines. Default to `${TEKHTON_HOME:-.}/bin/tekhton`; if the binary is missing, the shim emits a clear error and exits 127 — matching the `lib/finalize.sh` `finalize_run` fallback shape.
- **`BUILD_GATE_CONSTRAINT_TIMEOUT` is a real timeout but `bash -c "$validation_cmd"` is the exec form.** `gates.sh:146` uses `bash -c` deliberately (the comment cites "avoid arbitrary code execution" — the validation_cmd is from a constraints manifest the user controls). The Go port uses `exec.CommandContext("bash", "-c", validationCmd)` rather than parsing the command into argv, preserving the exact same shell-execution semantics.
- **Don't expand to UI gate in this milestone.** The shim that delegates `UIPhase` back to bash is the deliberate seam; m31.2 replaces it. Pulling `lib/gates_ui.sh` content into m31.1 doubles the LOC and re-introduces the cascade risk m31's split was designed to avoid.

## Seeds Forward

- **m31.2 (UI Gates):** Will delete `lib/gates_ui.sh` and `lib/gates_ui_helpers.sh`, replacing the bash-shim `UIPhase` in `internal/gates/build.go` with a native `internal/gates/ui.go` implementation. The `UIPhase` interface defined in m31.1's `build.go` is the seam — m31.2 just swaps the concrete implementation.
- **m32 (Milestone DAG runtime port):** `lib/milestones.sh:milestone_acceptance.sh` calls `run_build_gate`. After m31.1 those calls execute through the shim; m32 can swap to in-process `gates.BuildGate.Run` once it has a Go-side milestone runtime.
- **m33 (Stages port):** The eight `run_build_gate` call sites and the one `run_completion_gate` call site in `stages/*.sh` go away when `stages/` is ported. m31.1's CLI surface (`tekhton gate <subcommand>`) is the only invocation path during the m32→m33 transition window.
- **Parity-gate framework:** `tests/test_gates_parity.sh` should reuse `tests/lib/parity.sh` (if it exists from m22's seed) or extract a shared driver here. Either way, m31.2 reuses the same eight-scenario harness for UI parity, so designing for reuse pays off.
- **Errors writer interface:** The `ErrorsWriter` interface on `BuildGate` is what m31.2's UI gate writes through too. Designing it as a shared dependency (not a build-gate-private helper) makes the m31.2 port mechanical — UI failures append a `## UI Test Failures` section through the same interface.
