#### Milestone 1.1.2: Cobra Root Command & Main Entry Point

Wire up the Cobra root command and `main.go` so the binary builds and prints help/version. Version injection still uses the `dev` sentinel because the Makefile lands in 1.1.3.

Files to create:
- `cmd/tekhton/main.go`
- `go.sum` (populated as a side effect of `go mod tidy` adding Cobra)

Files to modify:
- `go.mod` (add `github.com/spf13/cobra` dependency)

Acceptance criteria:
- `go build -o bin/tekhton ./cmd/tekhton` produces a working binary on a clean checkout.
- `bin/tekhton --version` prints `dev` (the sentinel, since no `-ldflags` injection yet).
- `bin/tekhton --help` produces standard Cobra output listing available flags.
- Bare invocation of `bin/tekhton` exits non-zero and prints help.
- `cmd/tekhton/main.go` imports `internal/version` from 1.1.1 to source the version string.
- `go test ./...` exits 0.
- `go.sum` is committed and matches the dependencies in `go.mod`.
- No file under `lib/`, `stages/`, `prompts/`, or `tools/` is modified.

Watch For:
- Use `cobra.Command.Version` field and `SetVersionTemplate` to control `--version` output formatting if needed.
- Bare invocation exiting non-zero requires either `RunE` returning an error or explicit `Args` validation — Cobra's default `Run` exits 0.
- Do NOT add a `build` target to a Makefile yet — that is 1.1.3's scope.
- Do NOT use `//go:embed` for the version string; embed cannot traverse out of the source directory to reach repo-root `VERSION`.

Seeds Forward:
- Milestone 1.1.3 depends on `cmd/tekhton/main.go` existing and on the `internal/version.Version` symbol path for `-ldflags` injection.
