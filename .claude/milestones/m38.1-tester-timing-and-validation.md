## Design

### Goal 1 — `TesterTiming` struct and parse modes

```go
// internal/tester/timing.go
package tester

type ParseMode int
const (
    ParseModeReplace ParseMode = iota   // overwrite values with parsed numbers
    ParseModeAccumulate                  // add to running totals (continuations)
)

type TesterTiming struct {
    ExecCount     int   // -1 = unset (matches bash sentinel)
    ExecApproxS   int   // -1 = unset
    FilesWritten  int   // -1 = unset
    WritingS      int   // -1 = unset; computed by ComputeWritingTime
}

// ParseTesterTiming reads the ## Timing section of reportPath and populates
// the returned TesterTiming. Missing file or missing section returns the
// zero-sentinel struct (all -1). Numeric fields validate via regex; unparseable
// values stay at -1. Mode controls whether fields replace or accumulate.
//
// Matches lib/tester_timing.sh::_parse_tester_timing behavior including the
// regex shapes:
//   - "Test executions:\s*([0-9]+)"
//   - "Approximate total test execution time:\s*~?([0-9]+)"
//   - "Test files written:\s*([0-9]+)"
//
// Accumulate-mode rules: if the running total is -1 (unset) and the parsed
// value is non-empty, replace; otherwise add the parsed value to the running total.
func ParseTesterTiming(reportPath string, mode ParseMode) TesterTiming { ... }
func (t TesterTiming) Merge(other TesterTiming, mode ParseMode) TesterTiming { ... }

// ComputeWritingTime returns the writing-time estimate (agent duration minus
// reported execution time), clamped to zero. Returns -1 if either input is -1
// or non-positive.
func ComputeWritingTime(agentDuration int, timing TesterTiming) int { ... }
```

### Goal 2 — `ValidationDecision` enum and router

```go
// internal/tester/validation.go
package tester

type RoutingKind int
const (
    RoutingClean RoutingKind = iota
    RoutingCompilationErrors
    RoutingTestFailures
    RoutingPartialRun
    RoutingNoReportButTestsCreated
    RoutingNoReportNoTests
)

type ValidationDecision struct {
    Routing            RoutingKind
    Remaining          int       // count of `^- \[ \]` lines in TESTER_REPORT.md
    CompilationPaths   []string  // for RoutingCompilationErrors
    SynthesizedReport  string    // for RoutingNoReportButTestsCreated
    ResumeMessage      string    // pipeline-state message for non-clean cases
}

// ValidateOutput inspects the tester report and log file, returns the routing
// decision. Mirrors stages/tester_validation.sh::_validate_tester_output
// branches:
//   1. report missing + test files created via git diff → NoReportButTestsCreated
//      (trips commit gate, synthesizes a minimal report)
//   2. report missing + no test files → NoReportNoTests
//   3. compilation errors in log → CompilationErrors (also flips affected test
//      file checkboxes back to unchecked in the report)
//   4. negative-number test-failure lines in log (`^\s+-[0-9]+:` or ` -[1-9]...`)
//      → TestFailures
//   5. REMAINING > 0 → PartialRun
//   6. clean → Clean
func ValidateOutput(ctx context.Context, req *Request, agentResult *AgentResult) ValidationDecision
```

### Goal 3 — Fixture replay tests

Both Go files get table-driven tests with bash-captured fixtures:

- `testdata/timing/{empty,partial,full,malformed}.md` — TESTER_REPORT.md fixtures with varying `## Timing` sections.
- `testdata/validation/{clean,partial,compilation-errors,test-failures,no-report-with-tests,no-report-no-tests}/` — each fixture directory has a TESTER_REPORT.md + a LOG_FILE; tests load them, call `ValidateOutput`, assert the returned `ValidationDecision`.

### Goal 4 — Bash call-site preservation

M38.1 does NOT delete the bash files. `stages/tester.sh:190` continues to call `_parse_tester_timing`; `stages/tester.sh:232` continues to call `_validate_tester_output`. The Go functions are available for M38.2-M38.6 to consume but live in parallel. M38.6 is the milestone that does the cutover and bash deletion.

### Goal 5 — Compilation-error checkbox-flipping subtlety

`_validate_tester_output:64-72` extracts compilation-failed test file basenames from the log and uses `sed -i` to flip `[x]` back to `[ ]` for matching report lines. The Go port preserves this exact behavior — but reads the report into memory, applies the flip, and writes it back atomically (tmp + rename), not in-place. This is the same pattern as `internal/test_baseline/baseline.go::Capture` (M38.5) — atomic-write is the project convention.

### Goal 6 — `trip_commit_gate` call (no-report-but-tests-created branch)

`_validate_tester_output:33` calls `trip_commit_gate "tester_did_not_produce_report"` — a bash function from `lib/gates.sh`. The gates subsystem ported in M31; the Go equivalent is `gates.TripCommitGate(ctx, "tester_did_not_produce_report")` (already available since M31.1). The Go port at M38.1 wires this call.

## Watch For

- **Bash uses `-1` as the unset sentinel for timing fields.** The Go port preserves `-1` (not `0`, not a `*int` nil) for round-trip parity with anything that reads the JSON envelope. Tests assert the sentinel explicitly.
- **`_parse_tester_timing` uses `grep -oP` + `tail -1`** — Go regex must match the bash behavior of picking the last occurrence of each field, not the first. If a fixture has two `Test executions:` lines, the parser must pick the latter.
- **The accumulate mode is for continuations.** When the tester runs multiple times in one stage (turn-exhaustion continuation loop in M38.3), each continuation parses the report in accumulate mode so the per-continuation count adds onto the running total. The Go merge logic must replicate this: if the running total is `-1` (never set), the first parse replaces; subsequent parses add. A test that calls accumulate twice and asserts the total guards this.
- **Validation's checkbox-flipping is destructive.** `_validate_tester_output:71` uses `sed -i` to mutate the TESTER_REPORT.md in place. The Go port mutates via read-into-memory + tmp-write + rename. **Do not use `os.WriteFile` directly on the report path** — that breaks atomic-write conventions and races with concurrent readers (the dashboard, the resume detector, etc.).
- **The negative-number regex is fragile.** `_validate_tester_output:74` matches `^\s+-[0-9]+:` and ` -[1-9][0-9]*:` to detect test-failure summary lines (pytest's `-1: ...` style). The Go port must use the same regex shapes — these were tuned against real test-framework output and changing them silently breaks the test-failure-routing branch. Add a comment in `validation.go` linking to the original bash line numbers as a forensic anchor.
- **`trip_commit_gate` is the no-report-with-tests-created safety valve.** It prevents the pipeline from rubber-stamping a "milestone-complete" commit when the tester never confirmed what it tested. The Go port at M38.1 must wire this call — a missing wire is the same M23/M28 regression that motivated the gate.
- **Helper-first sequencing rule (inherited from M35).** M38.1 ports HELPERS, M38.2-M38.5 port more helpers and one sub-stage, M38.6 ports the main stage. Resist the temptation to land everything in one decimal — six children is the minimum survivable split given the cross-call graph between tester.sh, tester_validation.sh, tester_continuation.sh, tester_fix.sh, and the test_audit + test_baseline subsystems.
