# m33.1 — Dashboard Emitters

## Overview

| Item | Detail |
|------|--------|
| **Arc motivation** | First of two children of the m33 dashboard arc. m33 ports the Watchtower data layer — the bash files that write `.claude/dashboard/data/*.js` for the static web UI. ## Design

### Sequencing note

Lands strictly before m33.2. The proto structs authored here are what m33.2's StatusReader unmarshals into; freezing them is the precondition for the read-side port. Lands after m27 because the env contract m27 hardened is what the emitters consume.

The Python sidecar's tick reader and the static Watchtower site both keep working through m33.1 — the JSON file *contents* stay byte-for-byte identical (the parity gate enforces this), only the *producer* changes. No coordinated change required on the Python/JS side.

The seam looks like:

```go
// During m33.1 only. Removed in m33.2 when parsers move to StatusReader.
func (e *Emitter) bashParseSecurity(reportFile string) (proto.DashboardSecurityV1, error) {
    cmd := exec.Command("bash", "-c",
        `source "${TEKHTON_HOME}/lib/dashboard_parsers.sh"; _parse_security_report "$1"`,
        "_", reportFile)
    out, err := cmd.Output()
    if err != nil { return proto.DashboardSecurityV1{}, err }
    var findings []proto.DashboardFinding
    if err := json.Unmarshal(out, &findings); err != nil { ... }
    return proto.DashboardSecurityV1{Findings: findings}, nil
}
```

The transition seam is a documented temporary measure — the parity gate exercises it as the "bash parser via Go emitter" path. m33.2 deletes the seam and substitutes `e.reader.ParseSecurity(reportFile)`.

### Goal 3 — `internal/dashboard/jsfile.go` — atomic write

Mirrors `_write_js_file` from `lib/dashboard_parsers.sh:31`. The Python sidecar tick reader polls these files on a tick interval; a partial write would crash the JSON parse on the Python side. Use the same tempfile-rename pattern `internal/tui/state.go:SaveAtomic` uses:

```go
// WriteJSFile marshals payload to JSON, wraps it in the JS scaffold
// (window.<varname> = <json>;), and writes via tempfile + os.Rename so a
// reader on the Python side never observes a partial file.
func WriteJSFile(path, varname string, payload any) error {
    data, err := json.Marshal(payload)
    if err != nil { return err }
    var buf bytes.Buffer
    fmt.Fprintf(&buf, "// Generated by Tekhton Watchtower — do not edit\n")
    fmt.Fprintf(&buf, "// Updated: %s\n", time.Now().UTC().Format("2006-01-02T15:04:05Z"))
    fmt.Fprintf(&buf, "window.%s = %s;\n", varname, data)
    tmp := path + ".tmp." + randSuffix()
    if err := os.WriteFile(tmp, buf.Bytes(), 0o644); err != nil { return err }
    return os.Rename(tmp, path)
}
```

The function injectable timestamp source (`time.Now`) becomes `e.Now()` for tests; the parity gate normalizes the `// Updated:` line before diffing.

### Goal 8 — Parity gate

`tests/test_dashboard_emit_parity.sh` runs three scenarios against captured pre-m33.1 bash baselines under `internal/dashboard/testdata/`:

1. **Single-milestone success.** Fixture project with a completed pipeline run (full `.tekhton/` reports tree, populated `metrics.jsonl`, `.claude/HEALTH_BASELINE.json`, no parallel teams). Expected: all 10 JS files diff byte-identical (after `// Updated:` timestamp normalization) between bash baseline and Go emitter output.
2. **Multi-stage failure.** Fixture with a pipeline that failed at the security stage (partial reports tree, `_STAGE_STATUS[security]=failed`, populated `LAST_FAILURE_CONTEXT.json`). Expected: run_state.js shows `pipeline_status: "failed"`, `current_stage: "security"`, diagnosis.js available, security.js findings populated.
3. **Parallel teams M37 mode.** Fixture with `_PARALLEL_TEAMS=(t1 t2)` and per-team report files (`INTAKE_REPORT_t1.md`, etc.). Expected: run_state.js `parallel_mode: true`, `teams` map populated with both team entries; reports.js `teams` map populated. This is the exotic shape; tolerate baseline gaps if `_PARALLEL_TEAMS` isn't fully exercised on the dogfood project but include the fixture so the path is tested.

Each scenario:
- Captures the bash baseline once at fixture-creation time (committed under `testdata/<scenario>/expected/data/*.js`).
- Runs `tekhton dashboard emit <each-kind>` against the fixture project.
- Diffs the Go output against the baseline, ignoring the `// Updated:` header line.
- Fails red on any other byte difference.

## Watch For

- **Atomic-write discipline is load-bearing.** The Python sidecar tick reader and the browser polling the static site both read these files on a sub-second cadence. A non-atomic write (open, write, close without rename) will cause the reader to see a partial JSON document and either crash or render garbage. Use the tempfile-rename pattern (`internal/tui/state.go:SaveAtomic`) for every write — there is no "this one's small enough to write directly" exception.
- **The `// Updated:` timestamp normalization in the parity gate.** Every JS file has a `// Updated: <ISO timestamp>` header line that changes per write. The parity gate diff must strip that line before comparing. Don't blindly `diff -q` — write a normalizer step. Same trap m21 hit and documented.
- **The transition seam to bash parsers is temporary.** `bashParseSecurity` and friends shell out to `bash -c "source ...; _parse_X"` during m33.1. This is ugly but bounded. m33.2 deletes the seam. Do NOT make the seam permanent by "improving" it — it's a stepping stone, not an interface.
- **Parallel-mode fields (M37 reference at `lib/dashboard.sh:213`).** The bash code's `_PARALLEL_TEAMS` / `_TEAM_*` arrays are read in two places (emit_run_state and emit_reports). The Go port must preserve the *exact* JSON shape — `"teams": {}` when no teams, `"teams": {"<team_id>": {...}}` when present, `parallel_mode: false` / `true` mirrors. The parity gate scenario 3 fixture is the contract; if the dogfood project never exercises parallel mode, hand-craft the fixture.
- **The Python sidecar reads JSON wrapped in JS.** Each `data/*.js` file is `window.TK_<KIND> = <json>;`, not bare JSON. The Python reader strips the wrapper before parsing. Don't switch the file format to bare JSON "because it's cleaner" — `templates/watchtower/index.html` loads these as `<script>` tags. The wrapper stays; the proto envelope discussion in the parent file's Goal 3 covers this.
