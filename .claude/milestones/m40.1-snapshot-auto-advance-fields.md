# m40.1 — Snapshot Proto: Auto-Advance Fields

## Overview

| Item | Detail |
|------|--------|
| **Arc motivation** | First of two narrow envelope-parity fixes that close the gap exposed by the m34.1 auto-advance dogfood. Without this fix, `tekhton --resume` after a halt always rebuilds the run request with `AutoAdvance=false` regardless of how the operator started the arc — they have to re-pass `--auto-advance --auto-advance-limit N` on every resume or the loop silently stops at one milestone. |
| **Gap** | `internal/proto/state_v1.go::StateSnapshotV1` lacks `auto_advance` (bool) and `auto_advance_limit` (int) fields. `internal/runner/resume.go::requestFromSnapshot` has nothing to read for them, so `req.AutoAdvance` is always the zero-value `false` post-resume. The bash writer `lib/state_helpers.sh::write_pipeline_state` likewise never emits these fields. The resume-to-task-mode fall-through (`requestFromSnapshot` sets `req.Mode = RunModeTask` when `snap.MilestoneID == ""`) also bypasses the cmd/tekhton/run.go auto-advance loop entry condition. |
| **m40.1 fills** | (a) Widens `StateSnapshotV1` with `auto_advance` (`omitempty`) and `auto_advance_limit` (`omitempty`). (b) Updates `requestFromSnapshot` to copy them onto the rebuilt `RunRequestV1`. (c) Updates the bash writer to emit both when set, keyed off `AUTO_ADVANCE` and `AUTO_ADVANCE_LIMIT` env vars (already populated by the m26 env builder for milestone-mode runs). (d) Adds Go + shell tests proving the round-trip. |
| **Depends on** | m33 |
| **Files changed** | `internal/proto/state_v1.go`, `internal/runner/resume.go`, `internal/runner/resume_test.go`, `lib/state_helpers.sh`, `tests/test_state_writer_resume_fields.sh` (new), `cmd/tekhton/run.go` (only `--auto-advance-limit` flag help), `VERSION`, `CHANGELOG.md`. |

## Design

### Goal 1 — Widen `StateSnapshotV1`

Two new fields, both `omitempty`-tagged so the on-disk envelope stays backward-compatible with state files written before m40.1:

```go
type StateSnapshotV1 struct {
    // ... existing fields ...
    AutoAdvance      bool `json:"auto_advance,omitempty"`
    AutoAdvanceLimit int  `json:"auto_advance_limit,omitempty"`
    // ... existing fields ...
}
```

Keep the JSON keys in alphabetical-within-section order so the manual `tekhton state validate` round-trip matches. The proto version stays at `tekhton.state.v1` — additive optional fields don't require a v2 bump.

### Goal 2 — Read into `requestFromSnapshot`

```go
func (r *Runner) requestFromSnapshot(snap *proto.StateSnapshotV1) *proto.RunRequestV1 {
    req := &proto.RunRequestV1{
        // ... existing assignments ...
        AutoAdvance:      snap.AutoAdvance,
        AutoAdvanceLimit: snap.AutoAdvanceLimit,
    }
    // ... existing logic ...
}
```

The CLI flag override behavior in `cmd/tekhton/run.go::buildRunRequest` already wins over snapshot values because the request is built from flags before resume reads the snapshot. Operators who want to cap the post-resume tail just pass `--auto-advance-limit N` explicitly.

### Goal 3 — Emit from `write_pipeline_state`

Update `lib/state_helpers.sh::write_pipeline_state` to emit the two fields when their env vars are set. The bash writer uses sequential `printf` calls into a temp file; new fields go right after `notes` and before the `extra` block:

```bash
# Auto-advance carry-over (m40.1)
if [[ -n "${AUTO_ADVANCE:-}" ]] && [[ "${AUTO_ADVANCE}" == "true" ]]; then
    printf ',\n  "auto_advance": true' >> "$tmp"
fi
if [[ -n "${AUTO_ADVANCE_LIMIT:-}" ]] && [[ "${AUTO_ADVANCE_LIMIT}" =~ ^[0-9]+$ ]]; then
    printf ',\n  "auto_advance_limit": %d' "${AUTO_ADVANCE_LIMIT}" >> "$tmp"
fi
```

Match the indentation of surrounding fields (2 spaces). Both fields are conditional on their env var being set so non-milestone task runs don't emit dead config.

### Goal 4 — Tests

- `internal/runner/resume_test.go`: extend `TestResume_ReadsSnapshot` (or add a sibling) to cover a snapshot with `auto_advance: true, auto_advance_limit: 4` and assert `req.AutoAdvance && req.AutoAdvanceLimit == 4` after `requestFromSnapshot`.
- `tests/test_state_writer_resume_fields.sh` (new): drive `write_pipeline_state` with `AUTO_ADVANCE=true AUTO_ADVANCE_LIMIT=4` set and grep the produced JSON for both fields. Validate the JSON parses via `tekhton state validate` (already exists from m03).
- No CLI/flag-help text change needed beyond noting in the `--auto-advance-limit` help that "the value is persisted in state and restored on --resume."

## Acceptance Criteria

- [ ] `StateSnapshotV1` has `AutoAdvance bool` + `AutoAdvanceLimit int` fields tagged with `omitempty`.
- [ ] `requestFromSnapshot` copies both fields onto the rebuilt `RunRequestV1`.
- [ ] A state file written WITHOUT `auto_advance` / `auto_advance_limit` keys still loads cleanly (backward compat — existing fixtures must keep passing).
- [ ] A state file written with `auto_advance: true, auto_advance_limit: 4` round-trips through `Read → requestFromSnapshot` and produces `req.AutoAdvance == true && req.AutoAdvanceLimit == 4`.
- [ ] `lib/state_helpers.sh::write_pipeline_state` emits both fields when `AUTO_ADVANCE=true` and `AUTO_ADVANCE_LIMIT=N` are in the env at write time.
- [ ] Output JSON validates with `tekhton state validate` (no schema errors).
- [ ] New test `tests/test_state_writer_resume_fields.sh` passes.
- [ ] Existing `tekhton state validate` and `state` round-trip tests pass with no regression.
- [ ] `bash tests/run_tests.sh` shows zero regressions.

## Watch For

- **Bash writer field ordering.** `write_pipeline_state` builds the JSON by sequential `printf`. Inserting in the wrong place produces valid JSON but breaks the parity gate's "envelope diff" test. Match the existing pattern: section comments delineate `## State header`, `## Run identity`, `## Resume hints`, `## Extra` — new fields go in `## Resume hints` (where `resume_flag` lives).
- **Backward compat with existing `.md` state files.** The `omitempty` tag is load-bearing: state files written by pre-m40.1 code DON'T have these keys. Loading must succeed with zero-values populated. The Go side does this automatically via Go's JSON decoder; bash side must not require the keys.
- **AUTO_ADVANCE env carrier.** `internal/runner/env.go::AsKV` emits `AUTO_ADVANCE=true|false` and `AUTO_ADVANCE_LIMIT=N` (lines 167-173) — the writer reads from process env which the m26 builder fed. Don't add a second source of truth.
- **Out of scope:** restoring `milestone_id` (that's m40.2). m40.1 only handles the auto-advance fields.

## Seeds Forward

- **m40.2** picks up the `milestone_id` writer + tests with the file conventions m40.1 establishes.
- **Future envelope fields** follow the same pattern: add struct field with `omitempty`, copy in `requestFromSnapshot`, emit in `write_pipeline_state` keyed off the corresponding env var.
- **Eventual bash → Go writer port** can reuse `tests/test_state_writer_resume_fields.sh` as its parity baseline.
