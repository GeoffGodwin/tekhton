#### Milestone 1.3: CI, Self-Host Harness, and Documentation

Add the GitHub Actions workflow that runs build/vet/test/lint on PRs, the self-host smoke script that proves the Go binary is reachable on `$PATH` during a bash pipeline run, and the developer documentation. This is the final layer that makes the Go foundation observable in CI and exercised by the existing self-host harness — without changing any bash code path.

Files to create:
- `.github/workflows/go-build.yml` (build job, vet+test job, golangci-lint job)
- `scripts/self-host-check.sh` (builds Go binary, prepends `bin/` to `$PATH`, asserts `tekhton --version` matches `VERSION`, exercises dispatcher routing matrix)
- `docs/go-build.md` (one-page dev onboarding: prerequisites, `make` targets, cross-compile layout, CI artifact location)

Acceptance criteria:
- `.github/workflows/go-build.yml` triggers on PRs and pushes to `main` and `feature/GoWedges`.
- Build job runs `make build-all` on `ubuntu-latest` and uploads all five binaries as workflow artifacts.
- Vet+test job runs `go vet ./...` and `go test ./...` (no coverage gate).
- Lint job runs `golangci-lint` with the "advanced" preset against `./...` and is clean.
- `actions/setup-go` uses `go-version-file: go.mod` so local and CI Go versions stay aligned.
- `scripts/self-host-check.sh` in default (CI-safe) mode: builds the Go binary, prepends `bin/` to `$PATH`, exercises the dispatcher routing matrix, asserts `tekhton --version` matches `VERSION`, and exits 0.
- The full `tekhton.sh --dry-run` smoke (which calls live Claude CLI agents) is gated behind `TEKHTON_SELF_HOST_DRY_RUN=1` and is NOT exercised in CI.
- `scripts/self-host-check.sh` is idempotent — runs twice in the same job without error.
- `docs/go-build.md` covers: prerequisite install, all four `make` targets, cross-compile output layout, CI artifact location.
- `bash tests/run_tests.sh` produces identical output before and after this milestone (parity check archived to CI artifact).
- No file under `lib/`, `stages/`, `prompts/`, or `tools/` is modified.

Watch For:
- The self-host script must not write lockfiles or state files that fail on re-run — keep all writes inside an ephemeral temp dir.
- CI does NOT run `bash tests/run_tests.sh` in `go-build.yml`; the bash test suite stays on its existing CI rules. Phase 0 only adds Go CI.
- `golangci-lint` version drift between local and CI causes flake — pin the action to a specific minor version.
- The `TEKHTON_SELF_HOST_DRY_RUN` gate must default to off so unauthenticated CI runs cannot accidentally call live Claude agents.
- `docs/go-build.md` is dev-onboarding, not a manual — one page max, no API surface area documented (there is none yet).

Seeds Forward:
- m02 (`tekhton causal emit`) is the first real subcommand and the first call site bash code will actually invoke; the self-host harness's dispatcher routing matrix is the test surface that will catch regressions when that wedge lands.
- m04's 80% coverage gate plugs into the vet+test job created here — leave a TODO comment in `go-build.yml` marking where the coverage step will be inserted.
- The `VERSION` file's role as single source of truth across bash and Go is cemented here; finalize-stage version bumping continues to work unchanged so long as future milestones do not introduce a second version source.
