#### Milestone 1.2: Build System + CI
Add the Makefile cross-compile targets and the GitHub Actions workflow that builds, vets, tests, and lints the Go module on every PR. Wires ldflags injection so `tekhton --version` reflects repo-root `VERSION` for `make`-driven builds. After this sub-milestone the binary builds for all five OS/arch targets and CI gates the Go code, but the bash self-host harness still does not invoke the Go binary.

Files to create:
- `Makefile` (`build`, `test`, `build-all`, `clean` targets; CGO disabled; ldflags inject `internal/version.Version` from `VERSION`)
- `.github/workflows/go-build.yml` (three jobs: `build-all`, `vet+test`, `golangci-lint`)

Acceptance criteria:
- `make build` produces `bin/tekhton`; `bin/tekhton --version` prints the contents of repo-root `VERSION` (trimmed).
- `make build-all` produces `bin/tekhton-linux-amd64`, `bin/tekhton-linux-arm64`, `bin/tekhton-darwin-amd64`, `bin/tekhton-darwin-arm64`, `bin/tekhton-windows-amd64.exe`.
- `make test` exits 0 (Go's "no test files" output is acceptable).
- `make clean` removes `bin/`.
- CI workflow `go-build.yml` runs on PR + push to `main` and `feature/GoWedges`; all three jobs (build-all, vet+test, lint) green.
- `actions/setup-go` reads `go-version-file: go.mod` so local and CI Go versions cannot drift.
- `golangci-lint run ./...` clean with the "advanced" preset.
- `bin/` does not appear in `git status` after `make build-all` (verifies 1.1's `.gitignore` entry).

Watch For:
- ldflags symbol path must be the fully-qualified import path: `-X github.com/geoffgodwin/tekhton/internal/version.Version=$(shell cat VERSION)`. A wrong path silently leaves `Version` at `dev`.
- `darwin/*` cross-compile only succeeds with `CGO_ENABLED=0` — set it explicitly in the Makefile, do not rely on the host default.
- No coverage gate yet — that lands in m04. Resist the urge to add one here.
- The bash test suite (`bash tests/run_tests.sh`) is NOT invoked from `go-build.yml`; that suite stays gated by its existing CI rules.

Seeds Forward:
- Milestone 1.3's self-host check shells out to `make build` and depends on ldflags injection working correctly here.
- m04 will add the 80% coverage gate on top of this workflow's `vet+test` job.
