#### Milestone 1.2: Makefile Build System with Cross-Compile
Add the Makefile that drives local builds, the test target, and the five-target cross-compile (`linux/amd64`, `linux/arm64`, `darwin/amd64`, `darwin/arm64`, `windows/amd64`), all with CGO disabled. End state: developers can build and cross-compile locally with `make`; CI wiring still lands in 1.3.

Files to create:
- `Makefile` (targets: `build`, `test`, `build-all`, `clean`)

Acceptance criteria:
- `make build` on a clean checkout produces `bin/tekhton`; `bin/tekhton --version` prints the contents of repo-root `VERSION` (trimmed).
- `make build-all` produces five binaries named `bin/tekhton-<os>-<arch>[.exe]` covering linux/amd64, linux/arm64, darwin/amd64, darwin/arm64, windows/amd64.
- `file bin/tekhton-*` confirms each binary matches its target OS/arch.
- `make test` exits 0 (Go's "no tests" output is acceptable).
- `make clean` removes `bin/`.
- All targets export `CGO_ENABLED=0`.
- `bin/` does not appear in `git status` after `make build-all` (verifies 1.1's `.gitignore` change).
- No file under `lib/`, `stages/`, `prompts/`, or `tools/` is modified.

Watch For:
- CGO must stay disabled everywhere — the static-binary promise depends on it. `darwin/*` cross-compile from Linux only works with CGO off.
- `build` and `build-all` must both inject the version via `-ldflags "-X main.version=$(cat VERSION)"`; otherwise binaries ship as `dev`.
- Use `-trimpath -ldflags="-s -w"` to keep release builds reproducible and small.
- Verify darwin cross-compile locally on Linux before relying on CI in 1.3.

Seeds Forward:
- Milestone 1.3's CI workflow invokes `make build-all`, `make test`, and `golangci-lint`; the Makefile contract here is the surface area CI exercises.
- Milestone 1.3's `scripts/self-host-check.sh` calls `make build` to get the binary onto `$PATH`.
