## Design

### Goal 1 — Stale-config detection

Add to `lib/mcp.sh`, after `_resolve_serena_paths` and before `_resolve_mcp_config`:

```bash
# --- Detect pre-m28.1 stale Serena config ------------------------------------

# Returns 0 if the config at $1 matches the pre-m28.1 broken shape
# (`"args": ["-m", "serena", …]`). Returns 1 for any other shape,
# including a non-existent file or a parse failure.
#
# Match is intentionally narrow: must have args[0]=="-m" && args[1]=="serena".
# A user with a custom MCP config that happens to name a server "serena"
# but uses a different command/args layout is not affected.
_is_stale_serena_config() {
    local config="$1"
    [[ -f "$config" ]] || return 1
    python3 -c "
import json, sys
try:
    cfg = json.load(open('$config'))
    args = cfg.get('mcpServers', {}).get('serena', {}).get('args', [])
    sys.exit(0 if (len(args) >= 2 and args[0] == '-m' and args[1] == 'serena') else 1)
except Exception:
    sys.exit(1)
" 2>/dev/null
}
```

`python3` is the JSON parser of record across the matrix — already shelled to from other parts of `lib/`. `jq` is not present on every CI runner; not worth a dependency add for one call site.

### Goal 2 — Resolver rewires

In `_resolve_mcp_config`, the "config exists" branch (currently `lib/mcp.sh:113-117`):

```bash
local default_config="${PROJECT_DIR}/.claude/serena_mcp_config.json"
if [[ -f "$default_config" ]]; then
    if _is_stale_serena_config "$default_config"; then
        local backup="${default_config}.bak.$(date +%Y%m%d%H%M%S)"
        cp "$default_config" "$backup"
        log_verbose "[mcp] Stale Serena config detected — backed up to $backup, regenerating."
        rm "$default_config"
        # Fall through to template-generation block below.
    else
        _MCP_CONFIG_PATH="$default_config"
        return 0
    fi
fi
```

The fall-through reuses the existing template-substitution block — no duplication. The `rm` is what makes the existing block trigger (it checks `[[ -f "$default_config" ]]` implicitly by writing to it).

### Goal 3 — New test: template substitution

`tests/test_serena_template_substitution.sh` — a black-box test that:

1. Sources `lib/common.sh` and `lib/mcp.sh`, stubs `_SERENA_BIN`, `_SERENA_DIR`, `PROJECT_DIR`, and `TEKHTON_HOME` to fixture values in a `tempdir`.
2. **Fresh-generation:** no pre-existing config. Calls `_resolve_mcp_config`. Asserts the generated file parses as JSON, has `mcpServers.serena.command == _SERENA_BIN`, `args[0] == "start-mcp-server"`, `args` contains `--project` with the right value.
3. **No-overwrite-when-correct:** pre-place `tests/fixtures/serena_configs/correct.json` at the default path. Calls `_resolve_mcp_config`. Asserts the file is unchanged (md5 match before/after), no `.bak.*` file exists.
4. **Regenerate-when-stale:** pre-place `tests/fixtures/serena_configs/stale.json` at the default path. Calls `_resolve_mcp_config`. Asserts the file is replaced (md5 differs), one `.bak.*` file exists with the original contents.

Follow the existing `tests/test_mcp.sh` shape — `assert_exit_code` helper, top-level `PASS`/`FAIL` counters, trap-based cleanup.

### Goal 4 — Extend `tests/test_mcp.sh`

Append three scenarios at the bottom of the existing file:

```bash
# =============================================================================
echo "=== Test: _probe_serena_startup with empty _SERENA_BIN ==="

_SERENA_BIN=""
_probe_serena_startup || result=$?
result=${result:-0}
assert_exit_code "_probe_serena_startup returns 1 when _SERENA_BIN empty" 1 "$result"

# =============================================================================
echo "=== Test: _probe_serena_startup with failing binary ==="

_SERENA_BIN="/usr/bin/false"
_probe_serena_startup || result=$?
result=${result:-0}
assert_exit_code "_probe_serena_startup returns 1 when binary fails" 1 "$result"

# =============================================================================
echo "=== Test: _probe_serena_startup with passing binary ==="

_SERENA_BIN="$(command -v echo)"
_probe_serena_startup
result=$?
assert_exit_code "_probe_serena_startup returns 0 when binary exits 0" 0 "$result"
```

`echo` ignores its args and exits 0 — exercises the success path without a real Serena install.

## Watch For

- **`python3` is the only JSON parser available across the matrix.** Don't use `jq` — not all CI runners have it. The existing `lib/` already shells to `python3`; staying consistent is the right call.
- **Backup filename uses second resolution (`%Y%m%d%H%M%S`).** Two pipeline runs that both hit the stale-config path within the same second would clobber each other's backups. This is acceptable: backups are a courtesy, not durable state. Don't add nanosecond precision, don't add a counter — extra surface for a one-shot migration.
- **Both fixtures must be hand-written, not generated.** A future reader debugging the detection regex needs to see the exact shape we matched against. Don't programmatically derive `correct.json` from `setup_serena.sh` output — divergence between the test fixture and the generation path is exactly what this test exists to catch.
- **Don't add a `tekhton --repair-mcp-config` subcommand.** The auto-repair-on-next-run path is enough. A subcommand adds Cobra surface, docs, completion entries, and tests for a one-time migration. Out of scope.
- **The stale-detection narrow match is the safety property.** If you "improve" the regex to match anything with `serena` in it, a user who legitimately writes their own Serena MCP wrapper script (`{"command": "/usr/local/bin/my-serena-wrapper.sh", …}`) loses their config to silent regeneration. Stay narrow.
- **CHANGELOG consolidation happens at close.** While the arc is in progress, each subtask adds its own bullet under `[Unreleased]`. On m28.3 close, the three bullets move into a single `[4.28.0]` block with a date — this is the project's existing convention, mirrored from m22 close.

## Seeds Forward

- After m28.3, the whole m28 arc closes. Downstream proof: sdivi-rust's M29 dogfooded run picks up a regenerated config on its first post-m28 invocation and logs `[mcp] Serena MCP integration enabled (probe passed).` rather than the silent pre-m28 line.
- Backup files accumulate over time at one-per-machine on first post-m28 run. If the accumulation becomes a real maintenance pain (multiple users have reported it), a future task can sweep `.bak.*` older than 30 days. Don't pre-build that — wait for the actual complaint.
- The fixture pair in `tests/fixtures/serena_configs/` is a natural attachment point for future MCP-server shapes if more servers join. The `serena_configs/` subdirectory name leaves room without further restructuring.
