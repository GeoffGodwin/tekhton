#### Milestone 1.3: CI Workflow + Self-Host Check + Docs

Add the GitHub Actions workflow, the self-host smoke script, and the dev-onboarding doc. Closes out the foundation: binaries ship as CI artifacts, the harness proves the Go binary is reachable on `$PATH`, and a single docs page covers install/build/CI.

Files to create:
- `.github/workflows/go-build.yml`:
  - Triggers: PR + push to `main` and `feature/GoWedges`.
  - Job 1 (`build`): `make build-all` on `ubuntu-latest`, upload all five binaries as artifacts.
  - Job 2 (`test`): `go vet ./...` and `go test ./...`.
  - Job 3 (`lint`): `golangci-lint run ./...` with the "advanced" preset.
  - All jobs use `actions/setup-go` with `go-version-file: go.mod`.
- `scripts/self-host-check.sh`:
  - Runs `make build`, prepends `bin/` to `$PATH`.
  - Asserts `tekhton --version` output matches trimmed `VERSION` contents.
  - Default mode (CI-safe): exercises dispatcher routing matrix only.
  - Behind `TEKHTON_SELF_HOST_DRY_RUN=1`: runs `tekhton.sh --dry-run` against a fixture task.
  - Idempotent: safe to re-run in the same job.
- `docs/go-build.md` (~80 lines): Go install prerequisites, `make` target reference, cross-compile output layout, CI artifact location.

Acceptance criteria:
- `go-build.yml` passes on the V4 branch with all three jobs (build, test, lint) green.
- Five binary artifacts appear on the workflow run page after a successful build job.
- `scripts/self-host-check.sh` exits 0 in default CI-safe mode on a clean checkout.
- Running `scripts/self-host-check.sh` twice in succession both exit 0 (idempotency).
- `TEKHTON_SELF_HOST_DRY_RUN=1 scripts/self-host-check.sh` exits 0 in an authenticated local environment.
- `docs/go-build.md` covers: prerequisite install, `make` targets, cross-compile output layout, CI artifact location.
- `bash tests/run_tests.sh` produces identical output before and after this milestone (parity check, archived to artifact).
- No file under `lib/`, `stages/`, `prompts/`, or `tools/` is modified.

Watch For:
- CI does NOT run `bash tests/run_tests.sh` here — that suite stays gated by its existing rules.
- `actions/setup-go` with `go-version-file: go.mod` prevents Go-version drift between local and CI.
- The self-host script must not write lockfiles or state files that fail on re-run.
- `golangci-lint` "advanced" preset must be pinned to a specific version in the workflow to avoid surprise rule additions breaking CI.
- The live `tekhton.sh --dry-run` path requires Claude CLI auth (intake, scout agents) — gate it behind the env var so CI never invokes it.

Seeds Forward:
- m04 hardening adds the 80% coverage gate to job 2; m01 deliberately ships zero Go code paths so the gate has nothing to fail on yet.
- m02 will be the first wedge to actually exercise `bin/tekhton` from a real code path (`tekhton causal emit`), making the `$PATH` plumbing in this script load-bearing.
- The version-assertion pattern here becomes the template for every future self-host check that proves a new subcommand is wired.
