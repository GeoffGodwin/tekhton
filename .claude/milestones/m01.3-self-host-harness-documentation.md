#### Milestone 1.3: Self-Host Harness & Documentation

Add the self-host smoke script that prepends `bin/` to `$PATH` and verifies the Go binary is reachable during a bash pipeline run. Ship the developer-onboarding doc.

Files to create:
- `scripts/self-host-check.sh`
- `docs/go-build.md`

Acceptance criteria:
- `scripts/self-host-check.sh` exits 0 in default (CI-safe) mode.
- Default mode builds the Go binary via `make build`, prepends `bin/` to `$PATH`, exercises the dispatcher routing matrix, and asserts `tekhton --version` matches `VERSION`.
- Full `tekhton.sh --dry-run` smoke (which calls live Claude CLI agents requiring auth) is gated behind `TEKHTON_SELF_HOST_DRY_RUN=1`.
- Script is idempotent: running it twice in the same CI job succeeds both times. No lockfile or state-file writes.
- The bash pipeline runs identically — the Go binary's presence on `$PATH` is observed but unused.
- `docs/go-build.md` exists, is ~80 lines max, and covers: Go install prerequisites, `make` targets, cross-compile output layout, CI artifact location, how the binary is wired into `$PATH` during pipeline runs.
- No file under `lib/`, `stages/`, `prompts/`, or `tools/` is modified.

Watch For:
- Don't add subcommands here — `tekhton causal`, `tekhton supervise`, etc. are wired by their respective wedges (m02+).
- Keep the doc one-page max; this is dev onboarding, not a manual.
- The `TEKHTON_SELF_HOST_DRY_RUN=1` tier is for humans with auth to run locally before landing — CI never sets it.

Seeds Forward:
- m02's `tekhton causal emit` will be the first runtime call from bash into the Go binary; this harness proves the wiring works first.
- m05+ `tekhton supervise` becomes the first production-path Go subcommand invoked by bash.
- Versioning convention (`tekhton --version` as single source of truth across bash and Go) is preserved for finalize-stage version bumping.
