#### Milestone 1.1.1.1: Go Module Skeleton + Version Package

Establish the Go module declaration and the version package in isolation, with no executable or build tooling yet. This sub-milestone creates the minimum scaffolding so that 1.1.1.2 has a stable import path and `Version` symbol to wire into `main` and `-ldflags`.

Files to create:
- `go.mod`
- `internal/version/version.go`

Acceptance criteria:
- `go.mod` declares module `github.com/geoffgodwin/tekhton` with `go 1.23` (pinned exactly, not `1.23.0` or `1.23.x`).
- `internal/version/version.go` declares `package version` and exposes a package-level `Version` string variable defaulting to the literal `dev` sentinel.
- `go build ./internal/version` succeeds from the repo root with no errors.
- `go vet ./internal/version` exits 0.
- No `go.sum` file exists yet (no third-party imports introduced).
- No file under `lib/`, `stages/`, `prompts/`, `tools/`, `cmd/`, or repo root other than `go.mod` is created or modified.
- `internal/version/version.go` has no imports beyond what is strictly required (ideally zero imports).

Watch For:
- The `Version` identifier must be exported (capital V) so `-ldflags "-X github.com/geoffgodwin/tekhton/internal/version.Version=..."` can target it in 1.1.1.2.
- Use `var Version = "dev"`, not `const`, because `-X` cannot rewrite constants.
- Pin `go 1.23` exactly in `go.mod`; do not let `go mod tidy` rewrite it to a patch version.
- Keep the package import-free to guarantee zero `go.sum` churn at this stage.

Seeds Forward:
- Milestone 1.1.1.2 imports `github.com/geoffgodwin/tekhton/internal/version` from `cmd/tekhton/main.go` and depends on the exact `Version` symbol name and `dev` default established here.
- Milestone 1.1.1.2 relies on the module path declared in `go.mod` for the `-ldflags -X` target expression.
