# m34.2 — Cleanup Stage Port

## Overview

| Item | Detail |
|------|--------|
| **Arc motivation** | Second and final child of the m34 stage-port arc. Applies the Go-native stage pattern m34.1 established (`StageDef.GoImpl` field, `internal/stages/<name>/` layout, `staglog` helper, parity harness) to a second stage — `stages/cleanup.sh`, the success-path debt sweep (M70 lineage). The point of m34.2 is **dogfood the pattern**: prove that porting a second stage is a mostly mechanical translation that does not require redesigning the pattern. If m34.2 surfaces a pattern-redesign-needing bug, m35-m39 are blocked until it's resolved. ## Design

### Sequencing note

Three landings within m34.2, ordered:

1. **Add the four exported helpers to `internal/notes/cleanup.go` first.** The cleanup stage cannot port until these exist. Source them from the git blob of `lib/notes_cleanup.sh` at the commit before its m24 deletion (`git log --all --diff-filter=D -- lib/notes_cleanup.sh` finds the deletion commit; `git show <commit>^:lib/notes_cleanup.sh` reads the pre-delete content).
2. **Land `internal/stages/cleanup/` second, with `GoImpl` still unwired.** The package compiles and tests pass against fixtures using the notes helpers added in step 1.
3. **Flip the dispatch (set `GoImpl: cleanup.RunStage`) third.** From this commit, the cleanup stage runs in Go.
4. **Tag baseline + delete bash file fourth.** `git tag v4.34.0-stage-baseline-cleanup` against the tree with `stages/cleanup.sh` still present, then `git rm stages/cleanup.sh`.
5. **Wire parity scenarios + wedge-audit + retro fifth.** Bump VERSION last.

### Goal 1 — Resurrect `internal/notes/` cleanup helpers

The four functions deleted with `lib/notes_cleanup.sh` need Go equivalents. Their pre-delete signatures (from git history):

```bash
# lib/notes_cleanup.sh (deleted in m24)
count_unresolved_notes()                            # echos integer count of [ ] notes
select_cleanup_batch <batch_size> <modified_files>  # echos newline-separated notes
mark_note_resolved <text>                           # mutates ${NON_BLOCKING_LOG_FILE}, returns 0 on hit
mark_note_deferred <text>                           # mutates ${NON_BLOCKING_LOG_FILE}, returns 0 on hit
```

Ported as Go methods on the existing `internal/notes.Document`:

```go
// internal/notes/cleanup.go (additions)

// UnresolvedCount returns the number of Pending-state notes — i.e. notes
// matching `[ ]` in the on-disk markdown. Ports lib/notes_cleanup.sh::count_unresolved_notes.
func UnresolvedCount(d *Document) int {
    if d == nil { return 0 }
    n := 0
    for _, note := range d.Notes {
        if note.State == Pending {
            n++
        }
    }
    return n
}

// SelectCleanupBatch picks up to size unresolved notes, prioritizing notes whose
// associated file paths overlap with modifiedFiles (a recent-pipeline-touch
// signal). Ports lib/notes_cleanup.sh::select_cleanup_batch.
func SelectCleanupBatch(d *Document, size int, modifiedFiles []string) []*Note {
    if d == nil || size <= 0 { return nil }
    var prioritized, rest []*Note
    modSet := map[string]struct{}{}
    for _, f := range modifiedFiles { modSet[f] = struct{}{} }
    for _, n := range d.Notes {
        if n.State != Pending { continue }
        if noteMentionsFile(n, modSet) {
            prioritized = append(prioritized, n)
        } else {
            rest = append(rest, n)
        }
    }
    out := append(prioritized, rest...)
    if len(out) > size { out = out[:size] }
    return out
}

// MarkResolved finds the first Pending note whose body contains text and
// transitions it to Done. Returns true on hit. Ports lib/notes_cleanup.sh::mark_note_resolved.
func MarkResolved(d *Document, text string) bool {
    n := findFirstPendingByText(d, text)
    if n == nil { return false }
    n.SetState(d, Done)
    return true
}

// MarkDeferred is the same shape as MarkResolved but transitions to Deferred.
// Ports lib/notes_cleanup.sh::mark_note_deferred.
func MarkDeferred(d *Document, text string) bool {
    n := findFirstPendingByText(d, text)
    if n == nil { return false }
    n.SetState(d, Deferred)
    return true
}
```

(`State` constants `Pending`, `Done`, `Deferred` already exist in `internal/notes/state.go`; if `Deferred` is absent it needs adding — verify in implementation.)

Each helper gets table tests in `internal/notes/cleanup_test.go`:

- `TestSelectCleanupBatch_PrioritizesFileOverlap` / `TestSelectCleanupBatch_RespectsSize`
- `TestMarkResolved_HitsFirstMatch` / `TestMarkResolved_NoMatch`
- `TestMarkDeferred_HitsFirstMatch` / `TestMarkDeferred_NoMatch`

#### `stage.go` — entry point

```go
// Package cleanup implements the m70-lineage post-success debt-sweep stage.
// M34.2 ports it from stages/cleanup.sh.
package cleanup

func RunStage(ctx context.Context, req *proto.StageRequestV1) (*proto.StageResultV1, error) {
    log := staglog.New(req)
    log.Header(req.Stage)

    // Trigger gate.
    doc, err := notes.LoadDocument(notesFile(req))
    if err != nil {
        log.Warn(fmt.Sprintf("[cleanup] load notes: %v", err))
        return skip(req, "notes-load-failed"), nil
    }
    if !shouldRun(doc) {
        log.Info("[cleanup] Trigger conditions not met. Skipping.")
        return skip(req, "no-trigger"), nil
    }

    batchSize := env.Int("CLEANUP_BATCH_SIZE", 5)
    unresolved := notes.UnresolvedCount(doc)
    threshold := env.Int("CLEANUP_TRIGGER_THRESHOLD", 5)
    log.Info(fmt.Sprintf("Unresolved non-blocking notes: %d (threshold: %d)", unresolved, threshold))
    log.Info(fmt.Sprintf("Selecting up to %d items for cleanup...", batchSize))

    modified := readModifiedFilesFromCoderSummary(req)
    batch := notes.SelectCleanupBatch(doc, batchSize, modified)
    if len(batch) == 0 {
        log.Warn("No eligible notes for cleanup sweep.")
        return skip(req, "no-eligible-notes"), nil
    }
    log.Info(fmt.Sprintf("Selected %d item(s) for cleanup sweep.", len(batch)))

    // Render prompt.
    vars := map[string]string{
        "CLEANUP_ITEMS":      formatBatchForPrompt(batch),
        "CLEANUP_ITEM_COUNT": fmt.Sprintf("%d", len(batch)),
    }
    promptText, err := prompt.Render(promptsDir(req), "cleanup", vars)
    if err != nil {
        log.Warn(fmt.Sprintf("[cleanup] render prompt: %v", err))
        return skip(req, "prompt-failed"), nil
    }

    // Snapshot pre-cleanup git state for selective revert on build-gate failure.
    preCleanupFiles, _ := gitDiffNameOnly()

    // Invoke the cleanup agent (JR coder).
    log.Info(fmt.Sprintf("Invoking cleanup agent (jr coder, max %d turns)...", env.Int("CLEANUP_MAX_TURNS", 15)))
    agentRes, agentErr := invokeAgent(ctx, req, promptText)
    if agentErr != nil {
        log.Warn(fmt.Sprintf("[cleanup] agent invocation failed: %v", agentErr))
    }
    log.Info("Cleanup agent finished.")

    // Null-run detection (mirrors was_null_run from lib/agent_helpers.sh).
    if isNullRun(agentRes) {
        log.Warn("Cleanup agent was a null run — no debt items addressed.")
        return skip(req, "null-run"), nil
    }

    // Build gate (failure = warning, not pipeline failure).
    buildPass := true
    if err := runBuildGate(ctx, "post-cleanup"); err != nil {
        log.Warn(fmt.Sprintf("Build gate FAILED after cleanup sweep — reverting cleanup changes."))
        log.Warn(fmt.Sprintf("Cleanup changes may have introduced issues. Review %s.", env.String("BUILD_ERRORS_FILE", ".tekhton/BUILD_ERRORS.md")))
        buildPass = false
        revertCleanupOnlyFiles(preCleanupFiles)
    }

    // Process results — updates the notes document in-place.
    res := processResults(doc, batch, buildPass, req)

    if res.Resolved > 0 || res.Deferred > 0 {
        log.Success(fmt.Sprintf("Cleanup sweep: %d resolved, %d deferred.", res.Resolved, res.Deferred))
    } else {
        log.Info("Cleanup sweep: no items conclusively resolved or deferred.")
    }

    return &proto.StageResultV1{
        Proto: proto.StageResultProtoV1, Stage: req.Stage,
        Verdict: proto.VerdictPass,
        ExitReason: fmt.Sprintf("resolved=%d deferred=%d", res.Resolved, res.Deferred),
        AgentCalls: 1,
    }, nil
}
```

The cleanup stage **never returns verdict=fail** (matches bash: every branch ends with `return 0` or `success`). Build-gate failure becomes a warning + selective revert, not a stage failure.

#### `results.go` — port of result-processing trio

```go
type Result struct { Resolved, Deferred int }

func processResults(doc *notes.Document, batch []*notes.Note, buildPass bool, req *proto.StageRequestV1) Result {
    res := Result{}
    if !buildPass {
        // Mirrors bash: build failed → no items marked resolved.
        return res
    }
    if reportPath := cleanupReportPath(req); fileExists(reportPath) {
        res = parseReport(doc, batch, reportPath)
        // Archive the report (bash mv to LOG_DIR with timestamp prefix).
        archiveReport(reportPath, req)
        return res
    }
    return resolveByFileChanges(doc, batch)
}

func parseReport(doc *notes.Document, batch []*notes.Note, reportPath string) Result {
    res := Result{}
    raw, err := os.ReadFile(reportPath)
    if err != nil { return res }
    resolvedLines := extractMarkdownSection(string(raw), "## Resolved")
    deferredLines := extractMarkdownSection(string(raw), "## Deferred")
    // ## Not Attempted is deliberately NOT parsed (matches bash comment lines 191-194).

    for _, line := range resolvedLines {
        text := strings.TrimPrefix(strings.TrimPrefix(line, "- "), "[x] ")
        if matchesBatch(text, batch) && notes.MarkResolved(doc, text) {
            res.Resolved++
        }
    }
    for _, line := range deferredLines {
        text := strings.TrimPrefix(strings.TrimPrefix(line, "- "), "[DEFERRED] ")
        text = strings.SplitN(text, ":", 2)[0]
        if matchesBatch(text, batch) && notes.MarkDeferred(doc, text) {
            res.Deferred++
        }
    }
    return res
}

func resolveByFileChanges(doc *notes.Document, batch []*notes.Note) Result {
    res := Result{}
    modified, _ := gitDiffNameOnly()
    if len(modified) == 0 { return res }
    for _, n := range batch {
        for _, f := range modified {
            base := filepath.Base(f)
            if strings.Contains(n.Body, base) {
                if notes.MarkResolved(doc, n.Body) {
                    res.Resolved++
                }
                break
            }
        }
    }
    return res
}
```

### Goal 3 — Build-gate call (in-process)

The bash cleanup stage shells back to `tekhton gate build` (post-m31.1 shim). M34.2's Go port can either preserve that pattern (call `tekhton-legacy.sh`-style exec) or call `internal/gates.Build()` directly in-process. Design call: **call in-process**. Rationale: the whole arc point is to remove subprocess hops; reaching back to bash defeats that. Direct call requires `internal/stages/cleanup/` to import `internal/gates`, which it already needs for the build-failure revert path.

```go
import "github.com/geoffgodwin/tekhton/internal/gates"

func runBuildGate(ctx context.Context, label string) error {
    return gates.Build(ctx, &gates.BuildRequest{
        Label: label,
        // … threading PROJECT_DIR / BUILD_ERRORS_FILE from env
    })
}
```

(Verify `gates.Build` signature in implementation — m31.1 ported the function but the exact API may need a thin wrapper.)

### Goal 4 — Selective git-revert preserved verbatim

Bash lines 119-132 are subtle: revert only files cleanup TOUCHED, not files the primary pipeline already had modified. The Go port preserves the snapshot-and-diff semantics:

```go
func revertCleanupOnlyFiles(preCleanup []string) {
    post, err := gitDiffNameOnly()
    if err != nil { return }
    preSet := map[string]struct{}{}
    for _, f := range preCleanup { preSet[f] = struct{}{} }
    for _, f := range post {
        if _, alreadyDirty := preSet[f]; alreadyDirty {
            continue
        }
        _ = exec.Command("git", "checkout", "--", f).Run()
    }
}
```

A test (`TestRevertCleanupOnlyFiles_PreservesPriorChanges`) plants a pre-existing dirty file, runs the revert against a post-snapshot that includes both that file and a new one, and asserts the pre-existing file is untouched while the new file is reverted.

### Goal 9 — `was_null_run` Go port

The bash `was_null_run` (lib/agent_helpers.sh:131) detects "agent died before accomplishing meaningful work" via heuristics on the agent log. Two options for m34.2:

- **(A) Port to `internal/supervisor.AgentResult.IsNullRun() bool`** — proper home, available to all future stages.
- **(B) Inline in `internal/stages/cleanup/stage.go`** as a private helper.

Choose (A). Rationale: m35-m39 stages will each need null-run detection; adding it to `supervisor` is the right home. M34.2 lands the API; later stages use it without reimplementing.

The bash heuristic (lines 128-145 of agent_helpers.sh) detects null run when the agent's reported tools-used count is zero AND the agent didn't write to any of the stage's `expected_file` outputs. Port preserves both checks.

## Watch For

- **The `BashAdapter` must continue to dispatch every un-ported stage correctly throughout m34.2.** Intake, coder, security, review, tester remain bash; only cleanup flips. Re-run the m34.1 smoke test (intake via the bash path) to verify no regression.
- **The cleanup stage runs only on the success-path finalize.** It triggers when (a) `CLEANUP_ENABLED=true`, AND (b) `UnresolvedCount > CLEANUP_TRIGGER_THRESHOLD` (default 5), AND (c) the primary pipeline reached finalize without failure. The Go port preserves all three conditions. Test coverage must exercise both the no-trigger short-circuit and the triggered path.
- **`stages/cleanup.sh` is currently broken bash code.** The four functions it calls (`select_cleanup_batch`, `mark_note_resolved`, `mark_note_deferred`, `count_unresolved_notes`) have no definitions anywhere in the tree (deleted in m24, never restored). Production runs that crossed the trigger threshold pre-m34.2 hit "command not found" the moment cleanup launched. M34.2 fixes the latent bug as part of the port — the four helpers MUST be added to `internal/notes/cleanup.go` BEFORE `internal/stages/cleanup/stage.go` lands, or the new Go stage will simply move the breakage from bash to Go.
- **Source the helper semantics from git history, not from imagination.** Run `git log --all --diff-filter=D -- lib/notes_cleanup.sh` to find the m24 deletion commit; `git show <commit>^:lib/notes_cleanup.sh` reads the pre-delete content. Translate that file's four functions, not a guess at what they should have done.
- **The selective git-revert on build-gate failure is subtle.** Bash lines 119-132 snapshot the modified-file list BEFORE the cleanup agent runs, then after build-gate failure reverts only files NOT in that snapshot. The Go port preserves this semantics: a pre-existing dirty file (modified by the primary pipeline before cleanup ran) MUST NOT be reverted. Cover with `TestRevertCleanupOnlyFiles_PreservesPriorChanges`.
- **The `## Not Attempted` section of CLEANUP_REPORT.md is deliberately NOT parsed.** Bash comment at lines 191-194 documents this — items the agent did not attempt remain `[ ]` and re-surface in future sweeps. The Go port preserves this. Add a parser-test case `TestParseReport_IgnoresNotAttempted` asserting Not-Attempted lines do not mutate the notes document.
- **The build-gate call goes in-process (`gates.Build(ctx, …)`), not via subprocess.** Reaching back to `tekhton gate build` would re-introduce a subprocess hop the stage-port arc is meant to remove. Verify `internal/gates.Build` API at implementation time — m31.1 ported the function but the exact API may need a thin wrapper.
- **The cleanup-stage's "post-success" semantics are pipeline-runner enforced, not stage-internal.** The stage itself does not check whether the prior stages passed — the runner decides whether to invoke cleanup at all. Do not add a "pipeline succeeded" precondition inside `cleanup.RunStage`; trust the runner.
- **`Deferred` may need adding to `internal/notes/state.go`.** Verify whether the State enum already includes `Deferred`; if not, add it as part of m34.2 (it's needed by the new `MarkDeferred` helper). If it's already there, no change.

A significant retro (multiple entries describing API gaps in `staglog`, `prompt`, or `supervisor`) signals m35 should pause for a pattern-redesign milestone. Capture friction honestly; do not understate.

## Seeds Forward

- **m35-m39 inherit both m34.1's pattern AND m34.2's helper API on `internal/notes/`.** Future stages that consume notes (coder, review, tester all reference the non-blocking-notes log) can reuse `UnresolvedCount`, `SelectCleanupBatch`, `MarkResolved`, `MarkDeferred` directly.
- **`internal/supervisor.AgentResult.IsNullRun()` is the canonical null-run check for the rest of the arc.** Bash `was_null_run` (lib/agent_helpers.sh) deletes when the last stage that uses it (probably coder, m35-ish) ports.
- **`gates.Build` in-process call pattern set in m34.2** is what every future stage that runs a build gate (coder build-fix loop, review, …) will follow. M35's coder port specifically inherits this — its build-fix loop currently shells back to `tekhton gate build`; m35 changes it to an in-process call by reading m34.2's example.
- **The parity harness's hand-authored golden for `cleanup-batch-resolved`** sets a precedent for handling fixtures whose bash baseline is broken. M35+ may hit similar cases (a bash stage that has latent bugs we're fixing as part of the port). The convention: hand-author the golden, comment-header the reason, file a tracking note that the parity assertion is "intended behavior" not "bash-baseline replica".
- **Cleanup-stage policy tuning (V5 candidate):** `CLEANUP_BATCH_SIZE`, `CLEANUP_TRIGGER_THRESHOLD`, `CLEANUP_MAX_TURNS` are environment-driven today. A V5 feature could let `pipeline.conf` declare per-project cleanup policies (`cleanup.batch_size: 10`, `cleanup.disabled_categories: [security]`). The `shouldRun` and `SelectCleanupBatch` signatures both have room for a policy struct — m34.2 leaves the shape simple (env-driven) so the V5 extension can land cleanly when the demand surfaces.
