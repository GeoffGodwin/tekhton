## Design

### Sequencing note

m35.3 is the lightweight cleanup tail. It has no new logic — every deliverable is a safety net or a documentation update. The single sequencing constraint: capture pre-M35 baselines for the parity gate BEFORE m35.1 starts (under tag `v4.34.99-security-baseline`). If that capture didn't happen, m35.3 must reconstruct from git history — possible but lossy.

The order within m35.3 is:

1. Residual scan first — confirms nothing was missed. Surface any escapees as work to do BEFORE the audit ban lands.
2. Wedge-audit ban second — formalizes that the bash files cannot return.
3. Parity gate third — replays the baselines, wires into `make dogfood`.
4. CHANGELOG + docs fourth — captures the close.
5. `VERSION` bump last — signals the milestone is done.

### Goal 1 — `scripts/wedge-audit.sh` ban block

Append at the end of the existing audit:

```bash
# m35.3: forbid re-introduction of the security bash subsystem.
if [[ -f lib/security_helpers.sh ]] || [[ -f stages/security.sh ]]; then
    echo "FAIL: lib/security_helpers.sh and stages/security.sh were ported to internal/security/ and internal/stages/security/ in m35." >&2
    echo "  Re-introducing them breaks the Phase 5 closeout. See docs/go-migration.md (M35 Closeout)." >&2
    exit 1
fi

# m35.3: forbid re-introduction of the deleted bash function names anywhere
# under lib/ or stages/. Catches an accidental copy-paste from git history.
sec_fns='_parse_security_findings|_severity_meets_threshold|_build_fixable_block'
sec_fns+='|_build_unfixable_block|_build_notes_block|_handle_unfixable_findings'
sec_fns+='|_write_security_notes|_security_is_docs_only|_has_blocking_findings'
if grep -rEl "($sec_fns)" lib stages 2>/dev/null | grep -v -- '--m35-allowlist'; then
    echo "FAIL: a deleted m35 bash function name appeared under lib/ or stages/." >&2
    echo "  Use tekhton security <sub> from cmd/tekhton/security.go instead." >&2
    exit 1
fi
```

A regression test (`tests/test_wedge_audit_m35.sh`) plants `stages/security.sh` with a `:` body, runs the audit, asserts exit 1, then cleans up.

### Goal 2 — `tests/test_security_parity.sh`

Three scenarios diff Go-emitted artifacts against pre-M35 bash baselines captured under `tests/baselines/m35-security/`:

| Scenario | Source | What it exercises |
|----------|--------|-------------------|
| `pass-no-findings` | Empty SECURITY_REPORT.md, no agent calls | Stage returns Pass; `[security] No structured findings...` log line; no `data/security_notes.md` written |
| `fixable-cycle-1-resolved` | Fixable HIGH on cycle 1, empty on cycle 2 | Pass verdict; `SECURITY_REWORK_CYCLES_DONE=1`; rework agent role line `Security Rework (cycle 1)` |
| `unfixable-escalate` | HIGH unfixable, policy=escalate | Pass verdict + HumanAction=true; `HUMAN_ACTION_REQUIRED.md` row sourced `security` with prefix `Unfixable security findings require human review:` |

Each scenario's baseline is the bash-emitted output (stdout, notes file, human-action file) under `tests/baselines/m35-security/<scenario>/`. The harness normalizes timestamps, PIDs, and absolute paths before diffing.

```bash
#!/usr/bin/env bash
# tests/test_security_parity.sh — m35.3 parity gate.
set -euo pipefail

BASELINE_DIR="${TEKHTON_HOME}/tests/baselines/m35-security"
FIXTURE_DIR="${TEKHTON_HOME}/internal/stages/security/testdata/fixtures"
scenarios=(pass-no-findings fixable-cycle-1-resolved unfixable-escalate)

for s in "${scenarios[@]}"; do
    echo "Scenario: $s"
    workdir=$(mktemp -d)
    cp -r "${FIXTURE_DIR}/${s}/." "${workdir}/"
    pushd "${workdir}" >/dev/null

    # Run the Go stage. The fixture seeds env + files; the fake supervisor binary
    # is wired via TEKHTON_AGENT_BINARY.
    "${TEKHTON_BIN:-tekhton}" stage run security --project-dir . \
        --result-file ./.tekhton/security_result.json > stdout.txt 2> stderr.txt || true

    # Normalize and diff each artifact.
    for artifact in stdout.txt .tekhton/SECURITY_NOTES.md .tekhton/HUMAN_ACTION_REQUIRED.md; do
        [[ -f "$artifact" ]] || continue
        normalized=$(_normalize "$artifact")
        baseline=$(_normalize "${BASELINE_DIR}/${s}/$(basename "$artifact").baseline")
        diff -u <(echo "$baseline") <(echo "$normalized") || {
            echo "FAIL: parity diff in $s / $artifact"
            popd >/dev/null
            exit 1
        }
    done

    popd >/dev/null
    rm -rf "${workdir}"
done
echo "All m35 parity scenarios pass."
```

`_normalize` strips `YYYY-MM-DD HH:MM:SS` timestamps and `/tmp/...` path prefixes.

Wires into `make dogfood`:

```makefile
# Makefile (m35.3)
dogfood: \
    test_diagnose_parity \
    test_security_parity \
    # ... other dogfood gates ...

test_security_parity:
	@bash tests/test_security_parity.sh
```

## Watch For

- **Severity-classification thresholds must match bash byte-for-byte.** The parity gate is the enforcement seam — every diff must pass after timestamp normalization. If a scenario starts flaking, suspect a normalization rule before suspecting the Go code; the m32.3 retro called out that timestamp normalization is the most-frequent parity-gate footgun.
- **`SECURITY_AGENT_ENABLED=false` is not in the parity scenarios.** Skip-stage runs produce no notes file and no human-action file — there's nothing meaningful to diff. The three parity scenarios deliberately exercise the engaged-stage paths. Don't add an `agent-disabled` scenario to the parity gate; assert agent-disabled behavior in the M35.2 fixture suite instead.
- **The prompt template paths stay the same.** The parity gate must NOT re-render the templates as part of the diff — that would test the m15 prompt engine, not the security stage. The fake supervisor binary fixtures pre-canned outputs; the gate diffs only the stage's post-agent processing.
- **HUMAN_ACTION_REQUIRED.md format is the operator-facing contract.** The `unfixable-escalate` parity scenario asserts the row text byte-for-byte. If the m25 `drift.HumanAction.Append` format ever changes (timestamp shape, source-discriminator placement, indentation), this gate catches it. Treat a failure here as a contract violation, not a security-stage bug — back the drift change out.
- **The audit-ban block uses `grep -v -- '--m35-allowlist'`.** This is a deliberate escape hatch for the audit script itself, which has to reference the forbidden function names in its own pattern strings. Other files using the same escape hatch is allowed but discouraged — if you find yourself adding `# --m35-allowlist` to a non-audit file, you're probably about to commit a residual.
- **Baseline capture happens BEFORE m35.1 starts, not in m35.3.** If you're reading this and the baselines under `tests/baselines/m35-security/` don't exist, that's a meta-failure — the m35 parent should have specified a baseline-capture gate. Recover by running the bash stage from git history (`git checkout v4.34.99-security-baseline -- stages/security.sh lib/security_helpers.sh`), capturing outputs, then re-deleting. Lossy but workable.
- **The `4.35.0` bump only happens if m35.3 closes clean.** A failing parity gate during the m35.3 dogfood run means a patch bump (`4.34.x+1`), not a minor bump. The minor bump signals "Phase 5 security row done"; reserve it for the closing commit.
- **`docs/go-migration.md` Phase 5 closeout section is operator-facing.** Operators read it to understand migration velocity. Write it as a retro, not a marketing post — name the patch-bump count, name the surprises, name any drift entries opened during the run.
- **`tekhton-legacy.sh` does NOT need a rewire in m35.3.** M35.2's `DefaultStageDefs.GoImpl` change is what diverts the dispatch. There is no `tekhton --security` early-check analogous to `tekhton --diagnose` — the security stage is always reached via `stages/` dispatch, never invoked standalone. Do not invent a CLI entry point here.

The patch-bump series within each milestone (4.35.x) captures dogfood-discovered fixes. Once Phase 5 closes, the cadence resets to whatever Phase 6 establishes.
