# m32.1 — Diagnose Engine

## Overview

| Item | Detail |
|------|--------|
| **Arc motivation** | First of three children porting the diagnose subsystem (m32 parent). Lands the *engine framework* — the orchestrator that reads pipeline-state / causal-log / RUN_SUMMARY / LAST_FAILURE_CONTEXT, builds the cause chain, detects recurring failures, and dispatches to a rule registry. Until this lands, every child further down the arc has nothing to plug into. The engine port is also where the `Rule` and `Diagnosis` interfaces get defined and the `internal/proto/diagnosis_v1.go` dashboard envelope ships — both consumed by M32.2 (rules) and M32.3 (output + dashboard). Done correctly, m32.1 is invisible to operators: the bash rule registry continues to drive classification via a `BashRuleAdapter` shim, so `tekhton --diagnose` output is byte-identical to v4.31.x. The Go engine just owns the surrounding orchestration. |
| **Gap** | `lib/diagnose.sh` (270 LOC) hand-rolls the engine in bash: `run_diagnose()` checks for the presence of any state file (PIPELINE_STATE / RUN_SUMMARY / CAUSAL_LOG / LAST_FAILURE_CONTEXT, or a `MIGRATION_BACKUP_DIR/pre-*` pattern), then calls `_read_diagnostic_context` (populates 20+ `_DIAG_*` module-state vars by `grep`-ing JSON), then `classify_failure_diag` (walks `DIAGNOSE_RULES` array, applies first match), then `generate_diagnosis_report` + `print_diagnosis_summary` (output). `lib/diagnose_helpers.sh` (182 LOC) holds `_collapse_cause_chain`, `_detect_recurring_failures`, and `_collect_agent_log_tails`. ## Design

### Sequencing note

m32.1 is the seam-introduction child. The wedge pattern (m20 dispatcher precedent): ship the Go engine seam, keep the bash rule files sourced through the `BashRuleAdapter` so behavior is identical. After m32.1 lands, `lib/diagnose.sh` still exists on disk (engine body collapsed to a one-line note pointing at `tekhton diagnose run`, the rule-loading and helper functions still resident for the adapter to call into). M32.2 replaces the adapter with a Go-native registry. M32.3 deletes the bash files.

The 15 v3 baselines MUST be captured at the start of m32.1 work — once the engine starts shipping behavior differences (even invisible ones via the adapter shim), the baselines drift. Capture commit: tag `v4.31.99-diagnose-baseline` precedes any m32.1 commit.

### Goal 1 — `Engine`, `Rule`, `Diagnosis`, `Context` types

```go
// internal/diagnose/types.go
package diagnose

type Confidence string

const (
    ConfidenceHigh   Confidence = "high"
    ConfidenceMedium Confidence = "medium"
    ConfidenceLow    Confidence = "low"
)

type Diagnosis struct {
    Classification string       // e.g. "BUILD_FAILURE", "MAX_TURNS_EXHAUSTED", "UI_GATE_INTERACTIVE_REPORTER"
    Confidence     Confidence
    Stage          string       // intake | coder | reviewer | tester | finalize | unknown
    Suggestions    []string     // operator-facing recovery suggestions, ordered most-relevant-first
    Recurring      RecurringInfo
    CauseChain     string       // human-readable collapsed chain, max 5 links
    RuleName       string       // for the [diag] rule= emit line
}

type RecurringInfo struct {
    Count int
    Note  string
}

type Context struct {
    ProjectDir       string
    TekhtonHome      string

    // Aggregated from PIPELINE_STATE / RUN_SUMMARY / LAST_FAILURE_CONTEXT
    Outcome          string   // success | failure | timeout | stuck | ""
    Stage            string
    Task             string
    Milestone        string
    ExitReason       string
    Classification   string   // last-run classification (from LAST_FAILURE_CONTEXT)
    SchemaVersion    int

    // m17-classifier-derived (set by helpers via internal/failure_context)
    PrimaryCategory     string
    PrimarySubcategory  string
    PrimarySignal       string
    PrimarySource       string
    SecondaryCategory   string
    SecondarySubcategory string
    SecondarySignal     string
    SecondarySource     string

    // Causal log aggregates
    CausalEvents     []string // raw JSONL lines, in order
    TerminalEvent    string
    ErrorEvents      []string
    ReviewCycles     int
    CauseChain       string   // pre-collapse
    CauseChainShort  string   // collapsed, max 5 links

    // Migration detection
    MigrationBackups []string  // paths under MIGRATION_BACKUP_DIR/pre-*

    // Build-error file presence (used by core + resilience rules)
    BuildErrorsFile     string // resolved absolute path; empty if absent
    BuildRawErrorsFile  string
    BuildFixReportFile  string

    // Agent log tails (for cause-chain rendering)
    AgentLogTails    map[string]string  // agent name -> last 20 lines
}

type Rule interface {
    Name() string                       // e.g. "_rule_max_turns" (matches bash for parity)
    Match(c *Context) (Diagnosis, bool)
}

type RuleProvider interface {
    Rules() []Rule                      // priority-ordered, top-down
}

type Engine struct {
    Provider RuleProvider
    Helpers  *Helpers
    Logger   io.Writer                  // for the [diag] rule-emit one-liner
}

func (e *Engine) Run(ctx context.Context, in *Context) Diagnosis {
    // Step 1: short-circuit on success.
    if in.Outcome == "success" {
        return Diagnosis{Classification: "SUCCESS", Confidence: ConfidenceHigh,
            Suggestions: []string{"Last run completed successfully. No issues found."}}
    }
    // Step 2: walk the rule registry top-down, first match wins.
    for _, r := range e.Provider.Rules() {
        if d, ok := r.Match(in); ok {
            d.RuleName = r.Name()
            d.Recurring = e.Helpers.DetectRecurring(in, d.Classification)
            e.emitRuleMatch(r, d)
            return d
        }
    }
    // Step 3: should never reach — last rule (_rule_unknown) always matches.
    return Diagnosis{Classification: "UNKNOWN", Confidence: ConfidenceLow,
        Suggestions: []string{"No specific failure pattern identified."}}
}
```

### Goal 2 — Context reader (`engine.go::ReadContext`)

`_read_diagnostic_context` ports as `Engine.ReadContext(in *Input) *Context`. The bash version `grep -oP`s JSON fields out of the four state files; the Go port uses `encoding/json` with `json.RawMessage` for forward-compatibility (a future LAST_FAILURE_CONTEXT v3 should not break m32.1 parsing).

Fallback order (preserved from bash):
1. `LAST_FAILURE_CONTEXT.json` v2 `primary_cause` / `secondary_cause` nested objects.
2. Top-level alias keys (writer compat layer).
3. Legacy `AGENT_ERROR_CATEGORY` / `AGENT_ERROR_SUBCATEGORY` env vars (read inside individual rules in M32.2 — not in the reader).

The reader emits the populated `*Context` ready for rule dispatch. If no state file exists, it returns `nil` and the engine prints the "no pipeline runs found" message (matching bash `run_diagnose`'s `has_state=false` branch).

### Goal 3 — Helpers (`helpers.go`)

Three helpers port from `lib/diagnose_helpers.sh`:

type Helpers struct {

### Goal 4 — `BashRuleAdapter` transition shim

Because M32.2 hasn't shipped yet at m32.1 close, the engine needs a way to call the still-bash rule registry. The adapter is intentionally ugly — it's transitional code that deletes in M32.2:

```go
// internal/diagnose/bash_rule_adapter.go
type BashRuleAdapter struct {
    TekhtonHome string
}

func (a *BashRuleAdapter) Rules() []Rule {
    // The bash registry order is read once from lib/diagnose_rules_registry.sh.
    return []Rule{
        &bashRule{name: "_rule_ui_gate_interactive_reporter", home: a.TekhtonHome},
        &bashRule{name: "_rule_preflight_interactive_config", home: a.TekhtonHome},
        // ... 16 more entries, hand-mirrored from diagnose_rules_registry.sh
    }
}

type bashRule struct {
    name string
    home string
}

func (b *bashRule) Name() string { return b.name }
func (b *bashRule) Match(c *Context) (Diagnosis, bool) {
    // Exec a tiny bash wrapper that:
    //   1. Sources lib/diagnose_helpers.sh + lib/diagnose_rules.sh + companions.
    //   2. Sets _DIAG_* globals from the Context fields (round-trip via env vars).
    //   3. Calls the named rule function.
    //   4. Prints DIAG_CLASSIFICATION / DIAG_CONFIDENCE / DIAG_SUGGESTIONS on stdout.
    // Parse stdout, return Diagnosis.
}
```

The adapter pays an exec-per-rule cost (18 bash invocations per diagnose run in the worst case — but typical case is <5 because rules short-circuit on first match). This is acceptable for the transition window because diagnose runs are not hot-path. M32.2 collapses it back to zero-exec by making the rules native Go.

### Goal 6 — `tekhton diagnose run` Cobra subcommand

Mirror m21's `tekhton finalize` shape:

```go
// cmd/tekhton/diagnose.go (append to existing m17 surface)
func newDiagnoseRunCmd() *cobra.Command {
    cmd := &cobra.Command{
        Use:    "run",
        Short:  "Run the diagnose engine and print the diagnosis report",
        Hidden: true,
        RunE: func(cmd *cobra.Command, _ []string) error {
            home := os.Getenv("TEKHTON_HOME")
            proj := projectDirFlag(cmd) // existing helper
            eng := diagnose.NewEngine(&diagnose.BashRuleAdapter{TekhtonHome: home})
            in, err := eng.ReadContext(cmd.Context(), &diagnose.Input{ProjectDir: proj, TekhtonHome: home})
            if err != nil { return err }
            if in == nil {
                fmt.Fprintln(cmd.ErrOrStderr(), "No pipeline runs found. Nothing to diagnose.")
                return nil
            }
            d := eng.Run(cmd.Context(), in)
            // m32.1 prints a minimal report; M32.3 ports the full generate_diagnosis_report.
            fmt.Fprintf(cmd.OutOrStdout(), "Classification: %s\nConfidence: %s\nStage: %s\n",
                d.Classification, d.Confidence, d.Stage)
            return nil
        },
    }
    return cmd
}
```

Hidden because the standalone invocation is a developer/debug lever — operators reach it transitively via `tekhton --diagnose`. The early-check at `tekhton-legacy.sh:657-659` is NOT rewired in m32.1 — that wait until M32.3 lands the full output port.

## Watch For

- **Capture baselines BEFORE writing any Go code.** Once m32.1 ships, the `BashRuleAdapter` exec-roundtrip path could surface a subtle stderr-line-ordering difference vs pure-bash. Tag `v4.31.99-diagnose-baseline` is the single source of truth for what "v3 parity" means; if you skip the tag step and capture later, the baselines will already be drifted.
- **The bash module-state globals (`_DIAG_*`) are the contract M32.2 inherits.** The Go `Context` struct field set must be a strict superset of the `_DIAG_*` globals enumerated in `lib/diagnose.sh:46-73`. If you skip a slot (`_DIAG_PRIMARY_SIGNAL` was added in M129 — easy to miss), a future m32.2 rule that depends on it silently fails to match. The acceptance criterion that enumerates the 6 exported types is the canary; review the bash global list against `types.go::Context` field-by-field before m32.1 close.
- **`BashRuleAdapter` round-tripping `_DIAG_*` globals via env vars has length limits.** `_DIAG_CAUSAL_EVENTS` can be hundreds of KB on a long run. Pass it via a tempfile + env-var-pointer pattern (`_DIAG_CAUSAL_EVENTS_FILE=/tmp/...`) rather than the raw value. The adapter test must cover the >128KB case.
- **`tekhton --diagnose` early-check at `tekhton-legacy.sh:657-659` is NOT rewired in m32.1.** Operator behavior continues to flow through bash. The Go entry exists only via the Hidden `tekhton diagnose run` subcommand. Premature rewiring would surface the m32.1 minimal-report output (no `generate_diagnosis_report` yet) to operators — a regression. The rewire is M32.3's responsibility.
- **The `[diag] rule=...` one-liner format must be byte-identical.** The adapter routes rule matches through the engine's `emitRuleMatch` helper, which must produce the same `[diag] rule=NAME confidence=LEVEL classification=CLASS stage=STAGE\n` line bash emits. The `rule-emit-format` parity scenario in `testdata/fixtures_v3/` enforces this.
- **Do NOT port any `_rule_*` functions in m32.1.** Even rules that look trivially-portable (`_rule_unknown` is a 4-line fallback) stay bash. M32.2 owns the rule port; mixing in m32.1 blows scope and risks drift between the adapter and the eventual Go-native registry.

## Seeds Forward

- **m32.2 — Rule registry + 18 rules:** Replaces the `BashRuleAdapter` with a Go-native `internal/diagnose/rules/Registry`. Each rule file (`core.go`, `extra.go`, `migration.go`, `resilience.go`, `resilience_preflight.go`) registers via a `Register()` call into the m32.1-defined `RuleProvider` interface. m32.1's `BashRuleAdapter` file deletes.
- **m32.3 — Output + remediation + crash + dashboard:** Ports `generate_diagnosis_report` to `internal/diagnose/output.go`, `print_crash_first_aid` to `crash.go`, `emit_dashboard_diagnosis` to `dashboard.go` (consuming the m32.1-shipped `proto.DiagnosisV1` envelope), and `lib/remediation.sh` to `remediation.go`. Deletes all 10 `lib/diagnose*.sh` files + `lib/remediation.sh`. Rewires `tekhton-legacy.sh:657-659` to exec `tekhton diagnose run`. Bumps `VERSION` to `4.32.0`.
- **Engine integration in stage-failure paths:** After M32.3, `stages/coder_buildfix.sh`, `hooks_final_checks.sh`, `lib/finalize_commit.sh` exec `tekhton diagnose classify` (m17 surface) instead of sourcing `lib/diagnose.sh`. The m32.1 `Engine` type is the in-process equivalent for any future Go stage-failure path.
- **`Helpers.DetectRecurring` cross-run history seam:** Currently reads `RUN_MEMORY.jsonl`. A V5 feature could replace this with a SQLite-backed run-history store; the `Helpers` type's method signature is the seam.
- **`proto.DiagnosisV1` versioning:** When the Watchtower dashboard learns to render multi-cause diagnoses, a `DiagnosisV2` ships alongside V1. The bash-side `_write_js_file` is JSON-version-agnostic, so dashboard evolution is purely additive.
