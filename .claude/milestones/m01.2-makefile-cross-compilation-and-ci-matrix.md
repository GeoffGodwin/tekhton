#### Milestone 1.2: Makefile, Cross-Compilation, and CI Matrix
Wrap the m1.1 build incantation in a `Makefile` with the four canonical targets, extend to five OS/arch cross-compile targets, and stand up the GitHub Actions workflow that runs build + vet + test + lint on every PR. End state: green CI on the V4 branch with five binaries uploaded as artifacts.

Files to create:
- `Makefile` (targets: `build`, `test`, `build-all`, `clean`; CGO_ENABLED=0 everywhere; ldflags inject `internal/version.Version` from `VERSION`)
- `.github/workflows/go-build.yml` (three jobs: `make build-all` + artifact upload, `go vet ./... && go test ./...`, `golangci-lint run ./...` with the "advanced" preset; triggers on PR + push to `main` and `feature/GoWedges`; `actions/setup-go` reads `go-version-file: go.mod`)

Acceptance criteria:
- `make build` produces `bin/tekhton` whose `--version` matches `VERSION`.
- `make build-all` produces all five binaries: `bin/tekhton-linux-amd64`, `bin/tekhton-linux-arm64`, `bin/tekhton-darwin-amd64`, `bin/tekhton-darwin-arm64`, `bin/tekhton-windows-amd64.exe`. CGO disabled on all.
- `file bin/tekhton-*` confirms the architecture/OS of each binary.
- `make test` exits 0 (Go's "no tests" output is acceptable).
- `make clean` removes `bin/` cleanly.
- `go vet ./...` clean; `golangci-lint run ./...` clean.
- `go-build.yml` passes on the V4 branch with all three jobs green; five binaries appear as workflow artifacts.
- After `make build-all`, no `bin/` artifact appears in `git status` (validates m1.1 `.gitignore`).
- No file under `lib/`, `stages/`, `prompts/`, or `tools/` is modified.

Watch For:
- CGO must stay disabled. Any future dep that pulls cgo (e.g., `mattn/go-sqlite3`) breaks the single-static-binary promise. If SQLite is ever needed, the chosen path is `modernc.org/sqlite`.
- `darwin/*` cross-compile from `ubuntu-latest` works only with CGO off — verify locally on Linux before relying on CI.
- The ldflags `-X` target must match m1.1's fully-qualified symbol (`github.com/geoffgodwin/tekhton/internal/version.Version`). A wrong path silently leaves the binary at `dev`.
- `actions/setup-go` must use `go-version-file: go.mod` to keep local/CI Go versions in lockstep.
- The `golangci-lint` "advanced" preset is opinionated — expect lint cleanup before green.
- CI does NOT run `bash tests/run_tests.sh` here; bash tests stay on their existing CI rules.

Seeds Forward:
- Milestone 1.3 uses `make build` to produce the binary the self-host check exercises.
- m04 hardening will add the 80% coverage gate to the `vet+test` job — m1.2 deliberately omits it because the codebase ships zero production Go paths.
