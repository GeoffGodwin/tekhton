#### Milestone 1.2: Cross-Compile + CI Workflow

Extend the Makefile with `build-all` to cross-compile to five OS/arch targets, then stand up the GitHub Actions workflow that runs build, vet/test, and golangci-lint. CGO stays disabled. No production code path consumes the binary yet — this sub-milestone proves the binary builds and lints cleanly across platforms in CI.

Files to modify:
- `Makefile` (add `build-all` target for `linux/amd64`, `linux/arm64`, `darwin/amd64`, `darwin/arm64`, `windows/amd64`; update `clean`)

Files to create:
- `.github/workflows/go-build.yml` (three jobs: build-all + artifact upload, vet+test, golangci-lint)

Acceptance criteria:
- `make build-all` produces all five expected binaries under `bin/` with names `bin/tekhton-<os>-<arch>[.exe]`.
- Each cross-compiled binary passes a `file bin/tekhton-*` shape check matching its target.
- `make build-all` runs with `CGO_ENABLED=0` set explicitly.
- CI workflow `go-build.yml` runs on PR + push to `main` and `feature/GoWedges`.
- Build job uploads all five binaries as workflow artifacts.
- Vet+test job runs `go vet ./...` and `go test ./...` green.
- Lint job runs `golangci-lint` with the "advanced" preset against `./...` green.
- `actions/setup-go` reads `go-version-file: go.mod` (no version drift between local and CI).
- The bash test suite (`bash tests/run_tests.sh`) is NOT invoked by this workflow.

Watch For:
- `darwin/*` targets cross-compile cleanly only with CGO off — verify locally on Linux before relying on CI.
- Pinning Go version via `go-version-file` (not a hardcoded string) prevents drift when `go.mod` is bumped.
- Lint preset choice ("advanced") may surface findings in m01's stub code — fix or configure exclusions rather than weakening the preset.
- CI must not gate the bash suite here; phase 0 only adds Go CI alongside existing bash CI rules.

Seeds Forward:
- Milestone 1.3's self-host check assumes `make build` (from 1.1) is available; cross-compile is not required by 1.3 but landing it here keeps the CI surface complete.
- m04 hardening will add the 80% coverage gate to this workflow; structure jobs so a coverage job can be appended cleanly.
