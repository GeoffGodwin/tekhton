#### Milestone 1.1.1: Go Module Skeleton & Version Package

Create the Go module declaration and the standalone version package that exposes the build-injected version string. This sub-milestone produces no binary yet; it establishes the importable package surface and gitignore hygiene.

Files to create:
- `go.mod`
- `internal/version/version.go`

Files to modify:
- `.gitignore` (add `bin/` and `*.test`)

Acceptance criteria:
- `go.mod` declares module `github.com/geoffgodwin/tekhton` with `go 1.23` pinned exactly.
- `internal/version/version.go` exports a `Version` package-level variable defaulting to the `dev` sentinel string.
- `internal/version/version.go` exports a function that returns the version with trailing whitespace trimmed.
- `go build ./...` succeeds on a clean checkout (no main package yet, but the version package compiles).
- `go test ./...` exits 0 (Go's "no tests" output is acceptable).
- `.gitignore` contains `bin/` and `*.test` entries.
- No file under `lib/`, `stages/`, `prompts/`, `tools/`, or `cmd/` is created or modified.
- `go.sum` is absent or empty (no external dependencies introduced yet).

Watch For:
- Pin `go 1.23` exactly in `go.mod`; do not use `go 1.23.0` or higher minor versions.
- The `Version` variable MUST be a package-level `var` (not `const`) so `-ldflags "-X"` injection can overwrite it in 1.1.3.
- Trim trailing whitespace at print/accessor time, not at injection time — the VERSION file may contain a trailing newline.

Seeds Forward:
- Milestone 1.1.2 depends on the `internal/version` package import path being stable.
- Milestone 1.1.3 depends on `Version` being a `var` (not `const`) for `-ldflags` injection.
