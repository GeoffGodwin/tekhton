# m38.3 — Tester Fix and Continuation Orchestrators

## Overview

| Item | Detail |
|------|--------|
| **Arc motivation** | Third decimal of m38. Ports the two orchestrator scripts that drive recursive agent invocations within the tester stage: `stages/tester_fix.sh` (192 LOC — M64 inline fix loop, depth-1 capped) and `stages/tester_continuation.sh` (129 LOC — turn-exhaustion continuation, default 3 attempts). These are the two highest-risk-of-runaway-cost code paths in the tester family: an unbounded fix loop or an unbounded continuation loop burns through quota in seconds. The bounds — `TESTER_FIX_MAX_DEPTH=1`, `MAX_CONTINUATION_ATTEMPTS=3` — are operator-tuned safety rails that the Go port must preserve verbatim. Also: the fix loop integrates with `test_dedup` (skip TEST_CMD re-runs when no source changed) and with `test_baseline` (skip fix entirely when all failures are pre-existing). Both integrations are critical optimizations. |
| **Gap** | At M38.2 close, the Go side has helpers (timing, validation) and one sub-stage (TDD) ported. M38.3 ports both orchestrators while leaving the cross-call dependencies as bash-shim calls; `lib/test_baseline.sh` ports in M38.5, `lib/test_dedup.sh` stays bash through M38 (its port is deferred to the build-fix-loop milestone). |

## Design

### Goal 1 — `RunInlineFix` and `FixOptions`

```go
// internal/tester/fix.go
package tester

type FixOptions struct {
    MaxDepth       int    // TESTER_FIX_MAX_DEPTH=1 (regression-canary default)
    OutputLimit    int    // TESTER_FIX_OUTPUT_LIMIT=4000
    MaxTurns       int    // TESTER_FIX_MAX_TURNS=26
    Model          string // CLAUDE_CODER_MODEL=claude-sonnet-4-6 (NOTE: coder model, not tester)
    AgentTools     string // AGENT_TOOLS_BUILD_FIX
    BaselineCheck  bool   // TEST_BASELINE_ENABLED=true
    DedupCheck     bool   // implicit: always call test_dedup_can_skip if available
}

func DefaultFixOptions() FixOptions {
    return FixOptions{
        MaxDepth:      1,                          // CANARY
        OutputLimit:   4000,
        MaxTurns:      26,
        Model:         "claude-sonnet-4-6",
        AgentTools:    "Read Glob Grep Write Edit Bash",
        BaselineCheck: true,
    }
}

type FixResult struct {
    AttemptCount   int
    ResolvedFailures bool   // true if final TEST_CMD passed
    DedupSkipped   bool
    BaselineSkipped bool   // true if pre-existing failures skipped the fix
}

func RunInlineFix(ctx context.Context, req *Request) (*FixResult, error)

// SmartTruncateTestOutput extracts failure-relevant lines from raw test output.
// Splits at failure markers (FAIL, FAILED, ERROR, AssertionError, TypeError, etc.),
// keeps first 5 + last 5 lines per block, caps at limit chars. If no failure
// markers, falls back to tail -80 of input.
func SmartTruncateTestOutput(output string, limit int) string
```

### Goal 3 — Baseline-aware short-circuit

`tester_fix.sh:108-118`:

```bash
if [[ "${TEST_BASELINE_ENABLED:-true}" == "true" ]] \
   && declare -f has_test_baseline &>/dev/null \
   && declare -f compare_test_with_baseline &>/dev/null \
   && has_test_baseline 2>/dev/null; then
    local _tfix_comparison
    _tfix_comparison=$(compare_test_with_baseline "$_failure_output" "1")
    if [[ "$_tfix_comparison" == "pre_existing" ]]; then
        log "All test failures are pre-existing — skipping tester fix."
        return
    fi
fi
```

Go equivalent at M38.3:

```go
if opts.BaselineCheck && test_baseline.Has(req.Milestone, req.ProjectDir) {
    verdict, err := test_baseline.Compare(failureOutput, 1, req.ProjectDir)
    if err == nil && verdict == test_baseline.PreExisting {
        log.Info("All test failures are pre-existing — skipping tester fix.")
        return &FixResult{BaselineSkipped: true}, nil
    }
}
```

**At M38.3 close, `internal/test_baseline` does NOT yet exist** (that ports in M38.5). The cross-call uses a small interface that M38.3 defines locally and M38.5 implements:

```go
// internal/tester/fix.go
type BaselineChecker interface {
    Has(milestone, projectDir string) bool
    Compare(output string, exitCode int, projectDir string) (BaselineVerdict, error)
}

// During M38.3-M38.4, a bash-shim implementation of BaselineChecker calls into
// lib/test_baseline.sh via subprocess. At M38.5 close, the shim swaps for the
// native Go implementation.
```

This is the same shim pattern M32.1 used with `BashRuleAdapter`.

### Goal 4 — Test dedup integration

`tester_fix.sh:162-176`:

```bash
if declare -f test_dedup_can_skip &>/dev/null && test_dedup_can_skip; then
    log "[dedup] Tests passed with no file changes since last run — skipping"
    _retest_exit=0
else
    eval "${TEST_CMD:-true}" >> "${LOG_FILE:-}" 2>&1 || _retest_exit=$?
    if [[ "$_retest_exit" -eq 0 ]] && declare -f test_dedup_record_pass &>/dev/null; then
        test_dedup_record_pass
    fi
fi
```

**`lib/test_dedup.sh` stays bash through M38.** The Go port at M38.3 calls a `TestDedup` interface that is implemented by a bash shim. Future build-fix-loop port retires the shim.

```go
type TestDedup interface {
    CanSkip() bool
    RecordPass()
}
```

A test asserts: two consecutive `RunInlineFix` calls with no source change record exactly one `TEST_CMD` invocation. This is the M38-parent-flagged optimization preservation.

### Goal 5 — Smart truncation port

`_smart_truncate_test_output:18-61` walks the input line by line, opens a "failure block" when a marker line is hit, accumulates following lines, emits first-5 + last-5 of each block joined by `\n---\n`, falls back to `tail -80` when no markers were hit, caps at `limit` chars.

The Go port walks via `bufio.Scanner` with the same regex (`FAIL|FAILED|ERROR|AssertionError|TypeError|...`). `truncateBlock` is internal — keeps first 5 + last 5 of a block, or all if ≤10 lines. Unit-tested against `testdata/fix/*.txt` fixtures (one large pytest fail, one jest fail, one no-markers tail-fallback).

### Goal 6 — Continuation loop git-diff gate

`tester_continuation.sh:36-46`:

```bash
local _test_files_created=0
if ! git diff --quiet 2>/dev/null || ! git diff --cached --quiet 2>/dev/null; then
    _test_files_created=$(git diff --stat HEAD 2>/dev/null | grep -c '|' || echo "0")
    _test_files_created=$(echo "$_test_files_created" | tr -d '[:space:]')
fi

if [[ "$_test_files_created" -lt 1 ]]; then
    return
fi
```

Go equivalent uses `os/exec` to run `git diff` (preserving the bash subprocess pattern, since `git` itself is not Go-native in tekhton). The gate is: if the tester wrote zero test files in the primary invocation, the continuation loop is skipped — there's nothing to "continue from".

### Goal 7 — Continuation accumulates timing

The continuation loop calls `_parse_tester_timing ... accumulate` after each iteration. The Go port calls `tester.ParseTesterTiming(reportPath, tester.ParseModeAccumulate)` and merges into the running `TesterTiming` struct. The accumulate logic is what M38.1 ships.

### Goal 8 — Continuation UPSTREAM short-circuit

`tester_continuation.sh:86-98`: UPSTREAM during continuation writes pipeline state and SKIP_FINAL_CHECKS=true and `return` (NOT `exit 1`). Continuation is non-fatal — if the API fails mid-continuation, the partial work stays committed and the operator resumes. The Go port preserves this: continuation UPSTREAM returns `nil` error with `Result.UpstreamErrored=true`. Different from TDD UPSTREAM (M38.2 returns non-nil error).

**This is a subtle but load-bearing semantic difference between TDD (fatal) and continuation (recoverable).** Acceptance criteria explicitly assert both behaviors.

## Watch For

- **`TESTER_FIX_MAX_DEPTH=1` default is load-bearing.** Going deeper than 1 was tried in V3 and led to runaway agent invocations that exhausted quota in seconds. The `TestDefaultFixOptions_MaxDepthIs1` test is the canary. If a future operator wants deeper fix recursion, they set the option explicitly — never change the default.
- **`MAX_CONTINUATION_ATTEMPTS=3` default similarly bounded.** Three attempts is what operators have validated in dogfooding; going higher invites cost overrun on the long-tail tester runs.
- **Fix vs continuation UPSTREAM semantics differ.** TDD UPSTREAM = fatal (M38.2 returns non-nil error). Continuation UPSTREAM = recoverable (M38.3 returns nil error, SkipFinalChecks=true). This is intentional — TDD is a pre-flight that the rest of the pipeline depends on, so its failure halts; continuation is a "tester didn't finish in time" recovery loop, and an API failure mid-recovery means the operator just resumes the run.
- **`test_dedup` stays bash through M38.** The interface-shim pattern (M38.3 defines `TestDedup` interface, M38.3-implementation calls into bash via subprocess) is the same wedge pattern M32.1 used with `BashRuleAdapter`. Do NOT port test_dedup as part of M38 — it's a separate optimization concern that travels with the build-fix-loop port.
- **`test_baseline` integration is via interface, not direct import.** `internal/test_baseline` does not exist at M38.3 close (M38.5 ships it). The fix.go BaselineChecker interface is defined locally; the bash-shim implementation lives in fix.go alongside the interface. At M38.5, the shim swaps for the native Go implementation.
- **The fix loop's TEST_CMD is `eval "${TEST_CMD:-true}"` in bash.** Go-side, this is `os/exec.CommandContext("bash", "-c", req.TestCmd)` — the test command is shell-evaluated, so users can configure it with pipes, env-var expansion, etc. Don't try to parse TEST_CMD into argv — keep the shell.
- **The fix agent uses `CLAUDE_CODER_MODEL`, not `CLAUDE_TESTER_MODEL`.** The fix agent is doing code-fixing work (tests AND source), so it gets the coder model and the build-fix tool set. The continuation agent uses the tester model (it's still writing tests, just more of them). Easy to swap by accident.
- **The continuation loop builds a `tester_resume` prompt, NOT a fresh tester prompt.** The resume prompt has different context expectations (it reads the partial TESTER_REPORT.md and continues from the unchecked items). Make sure the prompt rendering wires CONTINUATION_CONTEXT (already provided by `internal/context.BuildContinuationContext`).
