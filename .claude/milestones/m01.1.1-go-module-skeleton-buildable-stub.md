#### Milestone 1.1.1: Go Module Skeleton & Buildable Stub

Stand up the bare Go module with a minimal `main.go` stub and a Makefile capable of building, testing, and cleaning. No Cobra or version logic yet — this sub-milestone proves the toolchain wiring and produces a `bin/tekhton` binary that does nothing useful but builds cleanly with CGO disabled.

Files to create:
- `go.mod`
- `go.sum`
- `cmd/tekhton/main.go` (minimal `package main` with an empty `main()` — no Cobra, no flags)
- `Makefile` (with `build`, `test`, `clean` targets only)

Files to modify:
- `.gitignore` (add `bin/` and `*.test`)

Acceptance criteria:
- `go.mod` declares module `github.com/geoffgodwin/tekhton` with `go 1.23` pinned exactly.
- `go.sum` exists (may be empty until Cobra lands in 1.1.2).
- `make build` on a clean checkout produces `bin/tekhton`.
- `bin/tekhton` invoked bare exits 0 (placeholder behavior — Cobra arrives in 1.1.2).
- `make test` exits 0 (Go's "no tests" output is acceptable).
- `make clean` removes `bin/`.
- Makefile sets `CGO_ENABLED=0` for all build targets.
- `.gitignore` contains `bin/` and `*.test` on their own lines.
- No file under `lib/`, `stages/`, `prompts/`, `tools/`, or `internal/` is created or modified.

Watch For:
- Pin `go 1.23` exactly — drift causes CI flake later.
- CGO must stay disabled (`CGO_ENABLED=0`) — required for the static-binary promise.
- Do NOT add Cobra as a dependency yet; that lands in 1.1.2 along with `go.sum` population.
- Keep `main.go` truly minimal so that 1.1.2 can replace it wholesale without ambiguity about what's load-bearing.

Seeds Forward:
- Milestone 1.1.2 depends on the Makefile structure to add `-ldflags "-X"` version injection.
- Milestone 1.1.2 will replace the stub `cmd/tekhton/main.go` with a Cobra root command.
- Milestone 1.2 (parent's seed) depends on this Makefile structure to add the `build-all` cross-compile target.
