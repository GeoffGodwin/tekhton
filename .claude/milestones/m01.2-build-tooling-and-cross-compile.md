#### Milestone 1.2: Build Tooling and Cross-Compile

Add the Makefile that drives local builds, the test target, cross-compilation to five OS/arch targets, and clean-up. This wires the ldflags injection so `bin/tekhton --version` reads the repo-root `VERSION` file. No CI or self-host harness yet — those land in Milestone 1.3.

Files to create:
- `Makefile` with targets `build`, `test`, `build-all`, `clean`

Acceptance criteria:
- `make build` on a clean checkout produces `bin/tekhton`; `bin/tekhton --version` prints the trimmed contents of repo-root `VERSION`.
- `make test` exits 0 (Go's "no test files" output is acceptable since no test files exist yet).
- `make build-all` produces `bin/tekhton-linux-amd64`, `bin/tekhton-linux-arm64`, `bin/tekhton-darwin-amd64`, `bin/tekhton-darwin-arm64`, and `bin/tekhton-windows-amd64.exe`.
- All cross-compiled binaries pass a `file bin/tekhton-*` shape check (correct OS/arch reported).
- `make clean` removes `bin/` entirely.
- `git status` is clean after `make build-all` (no stray `bin/` artifacts thanks to `.gitignore` from Milestone 1.1).
- CGO is disabled in `build` and `build-all` (`CGO_ENABLED=0`); `-trimpath` and `-ldflags="-s -w"` are applied to the local build.
- No file under `lib/`, `stages/`, `prompts/`, or `tools/` is modified.

Watch For:
- `darwin/*` targets cross-compile cleanly only with CGO off — verify on Linux locally before relying on CI.
- The ldflags target path must match Milestone 1.1's `Version` variable location exactly (`internal/version.Version` if main re-exports, or whatever the agreed final symbol is). A typo in the `-X` path silently leaves `Version` at `dev` — write the Makefile so the version assertion in `make build` would catch this.
- Direct `go build` (without make) deliberately leaves the `dev` sentinel — document this in Milestone 1.3's `docs/go-build.md`.
- Do not introduce any third-party tool (e.g. `goreleaser`) here; plain `go build` with env-var matrix is sufficient and keeps the dependency surface tiny.

Seeds Forward:
- Milestone 1.3's CI workflow invokes `make build-all`, `make test`, and `make build` — those targets' names and behaviors are locked here.
- Milestone 1.3's self-host check shells out to `make build` before running, so its idempotency depends on `make build` being safe to run twice.
