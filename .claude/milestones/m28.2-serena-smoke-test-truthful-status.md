## Design

### Goal 1 — The probe function

Add to `lib/mcp.sh`, after `_resolve_mcp_config` (currently ends at line 141):

```bash
# --- Probe Serena startup -----------------------------------------------------

# Verify the resolved Serena binary can launch its MCP server.
# Runs `serena start-mcp-server --help` with a 2-second timeout.
# Returns: 0 on success (exit 0 within budget), 1 on any failure.
_probe_serena_startup() {
    if [[ -z "${_SERENA_BIN:-}" ]]; then
        return 1
    fi
    if ! timeout 2 "$_SERENA_BIN" start-mcp-server --help >/dev/null 2>&1; then
        return 1
    fi
    return 0
}
```

**Rationale for `--help` vs an actual stdio handshake:** `--help` is constant-time, requires no project state, exercises the same argv-parsing path that real startup uses (so a broken venv or missing dependency still trips the probe). A real stdio probe would need an MCP `initialize` request and would consume 1–2 seconds of rust-analyzer warm-up — too costly for a per-pipeline-start guard. The probe's job is to catch wedge-shaped failures (broken venv, wrong binary, missing console script), not protocol compatibility.

### Goal 2 — `start_mcp_server` flow change

Today (`lib/mcp.sh:198-210`):

```bash
# Claude CLI manages the MCP server lifecycle based on the config file.
# We don't need to start Serena ourselves...
_MCP_SERVER_RUNNING=true
SERENA_MCP_AVAILABLE=true
SERENA_ACTIVE="true"

log_verbose "[mcp] Serena MCP integration enabled."
```

After m28.2:

```bash
# Probe that the resolved binary actually launches before declaring success.
# A pass here doesn't guarantee runtime MCP behavior, but a fail here
# guarantees runtime MCP failure — cheap pre-flight catch.
if ! _probe_serena_startup; then
    warn "[mcp] Serena startup probe failed (binary: ${_SERENA_BIN:-unresolved})."
    warn "[mcp] Continuing without LSP-backed tools."
    SERENA_MCP_AVAILABLE=false
    SERENA_ACTIVE=""
    return 1
fi

_MCP_SERVER_RUNNING=true
SERENA_MCP_AVAILABLE=true
SERENA_ACTIVE="true"

log_verbose "[mcp] Serena MCP integration enabled (probe passed)."
```

The pipeline's `[✓] Indexer + Serena MCP ready (auto)` checkpoint in `tekhton-legacy.sh` (or its Go equivalent after m20) keys on `SERENA_ACTIVE`. After 28.2, that line reflects actual probe state. The non-zero `start_mcp_server` return on probe failure is the existing contract the caller already handles (`[mcp] Serena not found …` and `[mcp] Cannot find or generate MCP config.` already return 1).

- [ ] `_probe_serena_startup` returns 1 when `_SERENA_BIN` is empty.
- [ ] `start_mcp_server` calls `_probe_serena_startup` after `_resolve_mcp_config` succeeds and before setting `SERENA_ACTIVE="true"`.

## Watch For

- **`timeout` on macOS.** The script already assumes GNU coreutils elsewhere; macOS CI runners install it via brew in the existing job. Don't drop in a bash `&` + `wait` + `kill` shim unless a real macOS CI failure surfaces — extra complexity, same outcome.
- **Probe failure must NOT exit the pipeline.** `start_mcp_server` already returns 1 from three other branches (Serena not installed, CLI lacks `--mcp-config`, config can't be generated), and the caller treats that as "continue without LSP". Preserve that contract — do not change `set -e` semantics, do not add `exit 1`.
- **Don't pass `--mcp-debug` to claude unconditionally.** That flag is loud (~200 lines of stderr per agent call) and would pollute the causal log. The probe's job is binary success/fail at the resolver layer, not debug capture at the claude layer.
- **`--help` is the right probe shape, not `--version` or a no-args invocation.** Some serena versions emit a banner on no-args; some `--version` paths short-circuit before importing rust-analyzer integration code. `--help` is the canonical "exercise the argv parser" probe.
- **The probe runs once per pipeline start, not per agent call.** Don't move it into `agent.sh`; the resolver state is reused across the whole run.

## Seeds Forward

- **m28.3** will stub `_SERENA_BIN` to fake binaries (`/usr/bin/false`, `/usr/bin/echo`, a hanging script) to exercise the probe in `tests/test_mcp.sh` without a real Serena install. Don't make the probe depend on Serena-specific output — `_SERENA_BIN=/usr/bin/echo` returning 0 should make the probe pass.
- **Post-m28**: the probe is the natural attachment point if more MCP servers join the surface. Generalize the function shape only when the second server arrives.
