#### Milestone 1.2: Cross-Platform Build + CI Matrix

Extend the Makefile with `build-all` to cross-compile the binary established in 1.1 to five OS/arch targets (`linux/amd64`, `linux/arm64`, `darwin/amd64`, `darwin/arm64`, `windows/amd64`) with CGO disabled, and wire up the `go-build.yml` GitHub Actions workflow that runs build, vet+test, and `golangci-lint` jobs. Output filenames follow `bin/tekhton-<os>-<arch>[.exe]`. The CI workflow does NOT run `bash tests/run_tests.sh` — the bash suite stays under its existing gates.

Files to modify:
- `Makefile` (add `build-all` target)

Files to create:
- `.github/workflows/go-build.yml`

Acceptance criteria:
- `make build-all` produces all five expected binaries with correct naming (`.exe` suffix on windows).
- `file bin/tekhton-*` confirms each binary's target architecture matches its filename.
- Each binary's `--version` output matches `VERSION` when run on the matching platform (verified in CI where the runner exists; shape-check via `file` otherwise).
- `go-build.yml` triggers on PR and push to `main` and `feature/GoWedges`.
- Build job uploads all five binaries as workflow artifacts.
- Vet+test job runs `go vet ./...` and `go test ./...` and is green.
- Lint job runs `golangci-lint` with the "advanced" preset against `./...` and is green.
- `actions/setup-go` reads `go-version-file: go.mod` so CI Go version tracks the module pin.
- `make clean` removes `bin/` (verifies `clean` from 1.1 still works post-`build-all`).
- No file under `lib/`, `stages/`, `prompts/`, or `tools/` is modified.

Watch For:
- `darwin/*` cross-compile from a Linux host requires CGO off — verify locally before pushing to CI.
- No coverage gate yet — that lands in m04. Do not add one here.
- `golangci-lint` "advanced" preset can surface stylistic findings; treat clean as a requirement, not a target.
- Do not let `make build-all` leak intermediate `.o` or test binaries into the repo — `.gitignore` from 1.1 must continue to cover artifacts.

Seeds Forward:
- Milestone 1.3 depends on this workflow being green so the self-host check can be exercised in the same CI run.
- m04 hardening will add the 80% coverage gate on top of the test job stood up here.
