# m38.4 — Test Audit Family

## Overview

| Item | Detail |

| **Arc motivation** | Fourth decimal of m38 and the largest by LOC (846 bash → ~900 Go). ## Design

### Goal 1 — `internal/test_audit/` package layout

```
internal/test_audit/
├── audit.go              # Orchestrator: Run + RunStandalone + rework loop
├── audit_test.go
├── helpers.go            # CollectAuditContext + DiscoverAllTestFiles + BuildTestAuditContext
├── detection.go          # DetectOrphanedTests + DetectTestWeakening (pure-IO)
├── sampler.go            # M89 K=3 rolling sampler + JSONL history
├── symbols.go            # M88 LSP-gated stale-reference detector (native Go JSON)
├── verdict.go            # ParseAuditVerdict + RouteAuditVerdict (4 outcomes)
└── testdata/
    ├── orphan/           # Fixtures: deleted module + test that imports it
    ├── weakening/        # Fixtures: git-diff samples showing assertion downgrades
    ├── stale-sym/        # Fixtures: test_map.json + tags.json with missing symbols
    └── verdict/          # Fixtures: TEST_AUDIT_REPORT.md with each verdict
```

### Goal 2 — `AuditContext` struct (shared across all six files)

```go
// internal/test_audit/helpers.go
package test_audit

type AuditContext struct {
    TestFiles          []string  // from `^- [x] \`path\`` in TESTER_REPORT.md
    ImplFiles          []string  // from CODER_SUMMARY.md
    DeletedFiles       []string  // from git diff --name-status (D entries) + staged
    SampleFiles        []string  // M89 rolling sample
    OrphanFindings     []string  // from DetectOrphanedTests
    WeakeningFindings  []string  // from DetectTestWeakening
    SymbolFindings     []string  // from DetectStaleSymbolRefs (M88)
}

func CollectAuditContext(ctx context.Context, req *Request) (*AuditContext, error)
func DiscoverAllTestFiles(ctx context.Context, projectDir string) ([]string, error)
func BuildTestAuditContext(ac *AuditContext) (testAuditContextStr, coderDeletedFiles string)
```

### Goal 3 — Detection (pure-shell-equivalent in Go)

`detection.go` ports two pure-shell scans:

- **Orphan detection** — for each test file, extract import targets (Python `from X import` / `import X`, JS-TS `require('X')` / `from '...'`, Go would be added if needed), cross-reference against deleted-files list (basename without extension), emit `ORPHAN: <test> imports deleted module '<deleted>'` for matches.
- **Weakening detection** — for each MODIFIED (not new) test file, run `git diff HEAD -- <file>`, count removed vs added assertion lines via regex (assert, expect, should, assertEqual, assertEquals, assertThat, assertTrue, assertFalse, toBe, toEqual, toMatch, toThrow), emit `WEAKENING: <test> — net loss of N assertion(s)` if removed > added; detect specific→broad swaps (assertEqual replaced with assertTrue, etc.); detect removed test functions (`def test_`, `it(`, `test(`, `func Test`, `describe(`).

```go
func DetectOrphanedTests(ac *AuditContext) []string
func DetectTestWeakening(ctx context.Context, ac *AuditContext, projectDir string) []string
```

Native Go uses `os/exec` for `git diff` (already established pattern from M38.3). No shell-out for the regex scans — `regexp.MustCompile` instead.

### Goal 4 — M89 rolling sampler

```go
// internal/test_audit/sampler.go
type SamplerOptions struct {
    K                int    // TEST_AUDIT_ROLLING_SAMPLE_K=3
    MaxRecords       int    // TEST_AUDIT_HISTORY_MAX_RECORDS=500
    HistoryFile      string // {cache_dir}/test_audit_history.jsonl
}

type historyEntry struct {
    Timestamp string `json:"ts"`
    File      string `json:"file"`
}

func EnsureHistoryFile(projectDir string) string
func RecordAuditHistory(files []string, projectDir string) error  // append + prune
func PruneAuditHistory(opts SamplerOptions) error                   // tail -n MaxRecords
func SampleUnauditedTestFiles(ctx context.Context, ac *AuditContext, projectDir string) ([]string, error)
```

The sampler reads the JSONL history into a `map[string]string` (file → last-audited timestamp), gets the full test-file list via `DiscoverAllTestFiles`, sorts by last-audited timestamp ascending (unseen files get `"0000-..."` so they sort first), skips files already in `ac.TestFiles`, returns the first K of the sorted-leftover list. Atomic prune via tmp+rename matches the bash pattern.

### Goal 5 — M88 symbol detector (native Go, LSP-gated)

The bash version at `test_audit_symbols.sh:37-70` shells out to `python3` with an inline script that reads `test_map.json` + `tags.json` and emits `STALE-SYM: <test> references '<sym>' not found in any source definition` lines. **The Go port does NOT shell out** — `encoding/json` does the same work directly.

```go
// internal/test_audit/symbols.go
type testMap struct {
    Files map[string][]string `json:"files"`  // path → symbols referenced
}

type tagsData map[string]struct {
    Tags struct {
        Definitions []struct {
            Name string `json:"name"`
        } `json:"definitions"`
    } `json:"tags"`
}

func DetectStaleSymbolRefs(ctx context.Context, ac *AuditContext, opts SymbolOptions) ([]string, error)
```

LSP gating preserved: returns empty when `TEST_AUDIT_SYMBOL_MAP_ENABLED=false` or `TEST_SYMBOL_MAP_FILE` is empty/missing or `tags.json` is missing. `SERENA_ACTIVE` is the env-level gate from the request envelope.

### Goal 6 — Four-outcome verdict router

```go
// internal/test_audit/verdict.go
type Verdict int
const (
    VerdictPASS Verdict = iota   // missing report also → VerdictPASS (bash default)
    VerdictCONCERNS
    VerdictNEEDS_WORK
)

func ParseAuditVerdict(reportPath string) Verdict
func RouteAuditVerdict(ctx context.Context, req *Request, verdict Verdict) error
```

Routing side effects:
- PASS — `success("Test audit passed — all tests meet integrity standards.")`, return nil.
- CONCERNS — warn, append findings to `NON_BLOCKING_LOG_FILE` (via `internal/notes` or shim), return nil.
- NEEDS_WORK — warn, return a sentinel error (so the orchestrator's rework loop can act on it). The bash `_route_audit_verdict` returns 1 for NEEDS_WORK; the Go port returns `ErrAuditNeedsWork`.

### Goal 7 — Orchestrator with rework loop

```go
// internal/test_audit/audit.go
type Options struct {
    Enabled                  bool   // TEST_AUDIT_ENABLED=true
    OrphanDetection          bool   // TEST_AUDIT_ORPHAN_DETECTION=true
    WeakeningDetection       bool   // TEST_AUDIT_WEAKENING_DETECTION=true
    RollingEnabled           bool   // TEST_AUDIT_ROLLING_ENABLED=true
    SamplerK                 int    // TEST_AUDIT_ROLLING_SAMPLE_K=3
    MaxTurns                 int    // TEST_AUDIT_MAX_TURNS=8
    MaxReworkCycles          int    // TEST_AUDIT_MAX_REWORK_CYCLES=1
    SymbolMapEnabled         bool   // TEST_AUDIT_SYMBOL_MAP_ENABLED=true (LSP-gated)
}

type AuditResult struct {
    Verdict            Verdict
    OrphanFindings     []string
    WeakeningFindings  []string
    SymbolFindings     []string
    ReworkCycles       int
}

func Run(ctx context.Context, req *Request) (*AuditResult, error)
func RunStandalone(ctx context.Context, req *Request) (*AuditResult, error)  // --audit-tests
```

The orchestrator:
1. Gate on `TEST_AUDIT_ENABLED`.
2. `CollectAuditContext`.
3. `SampleUnauditedTestFiles` (if rolling enabled).
4. Skip if neither modified nor sampled files (early return).
5. Run three detectors (orphan/symbol/weakening), each gated on its own flag.
6. `BuildTestAuditContext` — assemble TEST_AUDIT_CONTEXT for the agent prompt.
7. Render `test_audit` prompt, invoke audit agent with the reviewer model + reviewer tools.
8. `ParseAuditVerdict`, emit causal event, route.
9. On NEEDS_WORK: rework loop up to `MaxReworkCycles=1` — re-collect, re-detect, render `test_audit_rework` prompt, invoke tester agent, re-audit, re-parse. Exhausted cycles warn and return.

## Watch For

- **Verdict has 4 outcomes — the 4th is implicit.** PASS, CONCERNS, NEEDS_WORK are the parsed verdicts; the 4th outcome is "missing report → PASS" (current bash default). M38.4 preserves this behavior. If a future operator wants the missing-report case to be a separate verdict (GENERIC_FAIL, ORPHAN_FAIL), that's a behavior change requiring a new milestone — do not slip it into M38.4. Same goes for the parent-flagged "weakened" detection findings — these are findings ATTACHED to one of the three verdicts, not separate verdicts.
- **M88 symbol detector MUST use native Go JSON — no python shell-out.** The bash version shells out to python3 because bash lacks structured JSON support. Go has `encoding/json` natively. The M38.4 port removes a runtime python dependency from this code path. A grep test guards this.
- **`SERENA_ACTIVE` gates M88, not `TEST_AUDIT_SYMBOL_MAP_ENABLED` alone.** The bash version returns early on `TEST_AUDIT_SYMBOL_MAP_ENABLED=false` OR missing `TEST_SYMBOL_MAP_FILE`. The Go port preserves both gates. In practice, only Serena (the LSP) writes `test_map.json` and `tags.json`, so without SERENA_ACTIVE the file paths don't exist and the second gate fires. The acceptance criterion targets the second gate explicitly.
- **The six bash files cross-call heavily — they MUST port as one package.** `audit.sh` calls into `helpers.sh` calls into `sampler.sh` calls back into `helpers.sh`. Splitting them into sub-packages creates import cycles. One `internal/test_audit/` package, six Go files. (Same shape as the bash partitioning.)
- **The rework loop's max is 1, not 3.** `TEST_AUDIT_MAX_REWORK_CYCLES=1` — going higher led to runaway scope expansion in earlier dogfooding. Preserve the default of 1. A test asserts `DefaultOptions().MaxReworkCycles == 1`.
- **`run_standalone_test_audit` is the `--audit-tests` CLI entry, not a stage call.** It is invoked from the CLI as a one-shot bootstrap for projects adopting M20-era test audit. The Go port exposes `RunStandalone` and the CLI command `tekhton audit-tests` wires to it. Different control flow from `Run` (no continuation, no rework — just discover-all-tests + audit-agent + print verdict).
- **`emit_event "test_audit" ...` causal event must be preserved.** Operators consume the causal log; the event payload `{"verdict":"X","orphans":"found"|"","weakening":"found"|""}` is grep-piped in dashboards. Byte-for-byte preservation required. M38.4 calls `causal.EmitEvent` from `internal/causal` (the m02-shipped package).
- **`_record_audit_history` is invoked AFTER a successful verdict (PASS or CONCERNS) AND after a successful rework (NEEDS_WORK then re-audit reaches PASS).** It is NOT invoked on the initial NEEDS_WORK — that would let a NEEDS_WORK file get refreshed in the sampler before the operator fixes anything. Preserve the timing.
- **`_AUDIT_TEST_FILES` and `_AUDIT_SAMPLE_FILES` are tracked separately for a reason.** The audit context renders them in separate labeled sections in the agent prompt ("modified this run" vs "freshness sample — may be stale") so the agent applies scope-alignment scrutiny to sampled files without assuming recent coder changes caused any issues. The Go port preserves the separation in `BuildTestAuditContext`.
