#### Milestone 1.3: Self-Host Harness and Developer Documentation
Add `scripts/self-host-check.sh` and `docs/go-build.md`. The self-host check builds the Go binary, prepends `bin/` to `$PATH`, exercises the dispatcher routing matrix in its default CI-safe mode, and asserts `tekhton --version` matches `VERSION`. The full `tekhton.sh --dry-run` smoke (which invokes live Claude CLI agents requiring auth) is gated behind `TEKHTON_SELF_HOST_DRY_RUN=1` for local human runs only.

Files to create:
- `scripts/self-host-check.sh` (executable; default mode: `make build`, prepend `bin/` to `$PATH`, exercise dispatcher routing, assert `tekhton --version` == trimmed `VERSION`. Gated mode under `TEKHTON_SELF_HOST_DRY_RUN=1`: also run `tekhton.sh --dry-run` against a fixture task and assert exit code + expected artifacts. Idempotent — safe to run twice in the same job.)
- `docs/go-build.md` (~80 lines, one-page max: Go install prerequisites, `make` target reference, cross-compile output layout, CI artifact location, how the binary sits on `$PATH` during pipeline runs but is called by no production code yet)

Acceptance criteria:
- `scripts/self-host-check.sh` exits 0 in default mode on a clean checkout.
- The script builds via `make build`, prepends `bin/` to `$PATH`, and asserts `tekhton --version` output equals trimmed `VERSION`.
- `TEKHTON_SELF_HOST_DRY_RUN=1 scripts/self-host-check.sh` exits 0 on a host with Claude CLI auth available; the gated tier exercises `tekhton.sh --dry-run` against a fixture and asserts expected artifacts.
- Running the script twice in succession in the same working directory exits 0 both times (idempotency).
- `docs/go-build.md` exists and covers all four required sections (install, `make` targets, cross-compile layout, CI artifact location).
- No file under `lib/`, `stages/`, `prompts/`, or `tools/` is modified.
- `bash tests/run_tests.sh` output identical before and after — the Go binary's presence on `$PATH` is observed but unused by any bash code path.

Watch For:
- The script must be idempotent. No lockfile or state-file writes that fail on re-run.
- CI cannot satisfy Claude CLI auth — the live `tekhton.sh --dry-run` tier MUST stay gated behind `TEKHTON_SELF_HOST_DRY_RUN=1`. Default-mode failure on a CI runner without auth is a bug in the script.
- The version comparison must trim trailing whitespace on both sides (`VERSION` typically ends with `\n`).
- `docs/go-build.md` is dev-onboarding, not a manual — keep to one page. Don't pre-document subcommands m1.1 deliberately didn't add.
- Don't add Go subcommands to satisfy the dispatcher routing exercise — the routing test must work against the stub root from m1.1.

Seeds Forward:
- m02's `tekhton causal emit` becomes the first subcommand actually invoked by bash code; the self-host harness here will gain assertions for it then.
- m05's `tekhton supervise` will be the first production call site; the `$PATH` plumbing established here is what makes that invocation reachable.
- The `tekhton --version` single-source-of-truth convention established here is preserved through finalize-stage version bumping (per CLAUDE.md `MAJOR.MINOR.PATCH` format).
