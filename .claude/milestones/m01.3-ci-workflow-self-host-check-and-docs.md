#### Milestone 1.3: CI Workflow, Self-Host Check, and Docs
Wire the GitHub Actions matrix, add the self-host smoke harness with the Go binary prepended to `$PATH`, and ship the dev-onboarding doc. End state: CI is green on PR + push to `main` and `feature/GoWedges`; humans can run the full self-host dry-run locally; new contributors have a one-page build doc.

Files to create:
- `.github/workflows/go-build.yml` (three jobs: `make build-all` upload artifacts, `go vet ./...` + `go test ./...`, `golangci-lint run ./...` advanced preset; all read Go version via `go-version-file: go.mod`)
- `scripts/self-host-check.sh` (builds via `make build`, prepends `bin/` to `$PATH`, asserts `tekhton --version` matches `VERSION`, exercises dispatcher routing matrix; full `tekhton.sh --dry-run` gated behind `TEKHTON_SELF_HOST_DRY_RUN=1`)
- `docs/go-build.md` (~80 lines: prerequisite install, `make` targets, cross-compile output layout, CI artifact location)

Acceptance criteria:
- CI workflow `go-build.yml` passes on the V4 branch with all three jobs (build+artifacts, vet+test, lint) green.
- Five workflow artifacts upload from the build job, one per OS/arch target.
- `actions/setup-go` is configured with `go-version-file: go.mod` (no hardcoded version drift).
- `scripts/self-host-check.sh` exits 0 in its default CI-safe mode: builds the Go binary, prepends `bin/` to `$PATH`, asserts `tekhton --version` matches `VERSION`, exercises dispatcher routing.
- `scripts/self-host-check.sh` is idempotent — running it twice in the same shell succeeds both times.
- With `TEKHTON_SELF_HOST_DRY_RUN=1`, the script additionally runs `tekhton.sh --dry-run` against the fixture task and asserts exit code + expected artifacts.
- `bash tests/run_tests.sh` produces identical output before and after this milestone (parity check, archived to artifact).
- `docs/go-build.md` covers all four required topics (install, targets, cross-compile layout, CI artifacts).
- No file under `lib/`, `stages/`, `prompts/`, or `tools/` is modified.

Watch For:
- The bash CI (`tests/run_tests.sh`) is NOT invoked from `go-build.yml` — it stays gated by its existing rules. Phase 0 only adds Go CI.
- The self-host check must not write lockfiles or state files that break re-run idempotency.
- `golangci-lint` "advanced" preset can be noisy on near-empty code — confirm clean run before merging.
- Full `tekhton.sh --dry-run` calls live Claude CLI agents (intake, scout) that need auth CI cannot provide; that tier must stay env-gated.

Seeds Forward:

- m04's 80% coverage gate replaces the current "no coverage gate" stance — the workflow file shape laid down here is where the gate gets added.
- m05+'s `tekhton supervise` subcommand will be the first wedge where the self-host check exercises a real Go code path called by bash; the harness here is intentionally a no-op to prove the wiring before any wedge depends on it.
