### Goal 1 — `Rescan(ctx, opts) (*Result, error)` decision tree

Port `rescan.sh:rescan_project` lines 28-115 verbatim. The decision tree:

```go
// rescan.go
func Rescan(ctx context.Context, opts RescanOptions) (*Result, error) {
    indexFile := filepath.Join(opts.ProjectDir, ProjectIndexFile)
    indexDir := filepath.Join(opts.ProjectDir, ".claude", "index")

    // Branch 1: --full flag forces full crawl.
    if opts.ForceFull {
        return Crawl(ctx, opts.AsCrawlOptions())
    }

    // Branch 2: no existing index file → full crawl.
    if !fileExists(indexFile) {
        return Crawl(ctx, opts.AsCrawlOptions())
    }

    // Branch 3: no structured index (meta.json) → migration full crawl.
    if !fileExists(filepath.Join(indexDir, "meta.json")) {
        return Crawl(ctx, opts.AsCrawlOptions())
    }

    // Branch 4: not a git repo → full crawl (warn, but not fail).
    if !isGitRepo(opts.ProjectDir) {
        log.Warnf("not a git repository — falling back to full crawl")
        return Crawl(ctx, opts.AsCrawlOptions())
    }

    // Branch 5: no recorded scan commit → full crawl.
    lastScanCommit, _ := ExtractScanMetadata(indexFile, "Scan-Commit")
    if lastScanCommit == "" || lastScanCommit == "non-git" {
        return Crawl(ctx, opts.AsCrawlOptions())
    }

    // Branch 6: recorded scan commit no longer exists (rebased away) → full.
    if !gitCommitExists(opts.ProjectDir, lastScanCommit) {
        log.Warnf("recorded scan commit %s no longer exists — full crawl", lastScanCommit)
        return Crawl(ctx, opts.AsCrawlOptions())
    }

    // Branch 7: no changes since last scan → no-op.
    changes, err := DetectChangedFiles(ctx, opts.ProjectDir, lastScanCommit)
    if err != nil { return nil, err }
    if len(changes) == 0 {
        log.Successf("no changes since last scan (%s). Index is up to date.", lastScanCommit)
        return &Result{NoOp: true}, nil
    }

    // Branch 8: major changes → full crawl for accuracy.
    sig := ClassifyChanges(changes)
    if sig == Major {
        log.Infof("major structural changes detected — running full crawl for accuracy")
        return Crawl(ctx, opts.AsCrawlOptions())
    }

    // Incremental update path.
    return updateIndexSections(ctx, opts, changes, indexDir)
}
```

The eight branches preserve bash semantics exactly. The fall-back-to-`Crawl` paths reuse the m30.1 engine. The incremental path (final return) does the selective regeneration.

### Goal 2 — `updateIndexSections` — selective regeneration

Ports `_update_index_sections` from `rescan.sh:117-224`. Decision logic:

```go
func updateIndexSections(ctx context.Context, opts RescanOptions, changes []Change, indexDir string) (*Result, error) {
    var regenTree, regenInventory, regenDeps, regenConfig, regenSamples bool

    var hasNewDirs, hasManifestChange, hasConfigChange bool

    for _, c := range changes {
        regenInventory = true  // ANY change triggers inventory regen.
        switch c.Status[0] {
        case 'A', 'D':
            if filepath.Dir(c.Path) != "." {
                hasNewDirs = true
            }
        case 'R':
            hasNewDirs = true
        }
        if IsManifestFile(c.Path) { hasManifestChange = true }
        if IsConfigFile(c.Path)   { hasConfigChange = true }
    }
    if hasNewDirs        { regenTree = true }
    if hasManifestChange { regenDeps = true }
    if hasConfigChange   { regenConfig = true }

    // Check if any currently-sampled files were modified or deleted.
    currentSamples, _ := ExtractSampledFiles(filepath.Join(opts.ProjectDir, ProjectIndexFile))
    for _, sample := range currentSamples {
        for _, c := range changes {
            if c.Path == sample {
                regenSamples = true
                break
            }
        }
        if regenSamples { break }
    }
    // Resample if new high-priority files were added.
    for _, c := range changes {
        if c.Status[0] == 'A' && isHighPriorityExt(c.Path) {
            regenSamples = true
            break
        }
    }

    fileList, err := listTrackedFiles(opts.ProjectDir)
    if err != nil { return nil, err }

    if regenTree {
        emitTreeTxt(indexDir, /* ... */)
    }
    if regenInventory {
        inv, err := buildFileInventory(ctx, opts.ProjectDir, fileList)
        if err != nil { return nil, err }
        if err := emitInventoryJSONL(indexDir, inv); err != nil { return nil, err }
    }
    if regenDeps {
        graph, err := parseDependencies(ctx, opts.ProjectDir)
        if err != nil { return nil, err }
        if err := emitDependenciesJSON(indexDir, graph); err != nil { return nil, err }
    }
    if regenConfig {
        cfg, err := buildConfigInventory(ctx, opts.ProjectDir, fileList)
        if err != nil { return nil, err }
        if err := emitConfigsJSON(indexDir, cfg); err != nil { return nil, err }
    }
    if regenSamples {
        samples, err := sampleFiles(ctx, opts.ProjectDir, fileList, opts.BudgetChars)
        if err != nil { return nil, err }
        if err := emitSamplesManifest(indexDir, samples); err != nil { return nil, err }
    }
    // Always update meta (scan date, commit, file count) regardless.
    meta := buildMeta(opts.ProjectDir, /* doc_quality=0 since recompute is expensive */)
    if err := emitMetaJSON(indexDir, meta); err != nil { return nil, err }

    // Regenerate the markdown view from updated structured data.
    return regenerateView(ctx, opts.ProjectDir, opts.BudgetChars)
}
```

The five `regen*` flags + the always-update-meta step preserve bash semantics. The `regenSamples` triggers (modified sample OR new high-priority file) match `rescan.sh:186` (`^A.*\.(md|json|toml|yaml|yml)$`).

### Goal 3 — `DetectChangedFiles` — git diff + status merge

Ports `_get_changed_files_since_scan`. Two-source merge:

1. `git diff --name-status ${lastScanCommit}..HEAD` for committed changes.
2. `git status --porcelain` mapped to diff-style status codes (`??` → `A`, `D` → `D`, `M` → `M`, `R` → `R`).
3. Deduplicate by filename — working tree wins (bash: `awk -F'\t' '!seen[$NF]++'`).

```go
type Change struct {
    Status   string  // "A", "D", "M", "R...M" etc — first byte is the primary status
    Path     string
    RenameTo string  // for R-status, the new path
}

func DetectChangedFiles(ctx context.Context, projectDir, sinceCommit string) ([]Change, error) {
    committed, err := exec.CommandContext(ctx, "git", "-C", projectDir, "diff",
        "--name-status", sinceCommit+"..HEAD").Output()
    if err != nil { /* tolerate, treat as empty */ }

    workingTree, err := exec.CommandContext(ctx, "git", "-C", projectDir, "status",
        "--porcelain").Output()
    /* parse porcelain output, map status codes */

    // Merge, deduplicate (working tree wins).
    seen := map[string]Change{}
    for _, c := range append(committedChanges, workingChanges...) {
        seen[c.Path] = c  // last write wins; working tree comes second
    }
    out := make([]Change, 0, len(seen))
    for _, v := range seen { out = append(out, v) }
    sort.Slice(out, func(i, j int) bool { return out[i].Path < out[j].Path })
    return out, nil
}
```

Test scenarios: pure committed-only changes, pure working-tree-only changes, both (working-tree must override committed for same file), rename with cross-directory move (R-status with two paths).

### Goal 4 — `ClassifyChanges` — significance classifier

Ports `_detect_significant_changes`. Rules:

```go
type Significance int
const ( Trivial Significance = iota; Moderate; Major )

func ClassifyChanges(changes []Change) Significance {
    var newDirs, deletedFiles, manifestChanges int

    for _, c := range changes {
        switch c.Status[0] {
        case 'D':
            deletedFiles++
            if IsManifestFile(c.Path) { manifestChanges++ }
        case 'A':
            if filepath.Dir(c.Path) != "." { newDirs++ }
            if IsManifestFile(c.Path) { manifestChanges++ }
        case 'M':
            if IsManifestFile(c.Path) { manifestChanges++ }
        case 'R':
            if c.RenameTo != "" {
                if filepath.Dir(c.Path) != filepath.Dir(c.RenameTo) { newDirs++ }
            }
        }
    }

    // Thresholds preserved from rescan_helpers.sh:98-102.
    if manifestChanges >= 2 || newDirs >= 5 || deletedFiles >= 10 {
        return Major
    }
    if manifestChanges >= 1 || newDirs >= 1 {
        return Moderate
    }
    return Trivial
}
```

The threshold constants (2 manifests, 5 dirs, 10 deletions for major; 1+ manifest or 1+ dir for moderate) are load-bearing — port verbatim. A unit test must assert each threshold (boundary cases at 1 and 2 manifests, 4 and 5 dirs, 9 and 10 deletions).

### Goal 5 — Metadata extraction with legacy fallback

Ports `_extract_scan_metadata`. Prefers structured `.claude/index/meta.json`; falls back to HTML-comment parsing for legacy projects (`<!-- Scan-Commit: <sha> -->` markers in PROJECT_INDEX.md).

```go
func ExtractScanMetadata(indexFile, field string) (string, error) {
    projectDir := filepath.Dir(indexFile)
    metaFile := filepath.Join(projectDir, ".claude", "index", "meta.json")

    jsonField := map[string]string{
        "Scan-Commit": "scan_commit",
        "Last-Scan":   "scan_date",
        "File-Count":  "file_count",
        "Total-Lines": "total_lines",
    }[field]

    if fileExists(metaFile) && jsonField != "" {
        var meta map[string]any
        // ... read + json.Unmarshal
        if v, ok := meta[jsonField]; ok && v != nil {
            return fmt.Sprint(v), nil
        }
    }
    // Legacy fallback: parse HTML comment from markdown.
    return extractHTMLCommentField(indexFile, field)
}
```

The legacy fallback exists for backward compat with pre-M68 projects (HTML-comment metadata only, no `meta.json`). The Go port preserves this fallback — do NOT drop it; field reports show projects in the wild still have this shape.

### Goal 6 — Skip-unchanged optimization preservation

The skip-unchanged semantics are the critical perf invariant for `tekhton --rescan`. Branches 7 and 8 of the decision tree (no changes / major changes) drive the user-visible perf characteristic:

| Scenario | Bash behavior | Go behavior MUST match |
|----------|---------------|------------------------|
| Project unchanged since last scan | `success "No changes since last scan ... Index is up to date."` + exit 0, no artifact writes | `Result{NoOp: true}` returned, no Write() calls to indexDir, exit 0 |
| Single file modified (trivial) | `_update_index_sections` regenerates ONLY inventory + samples (if file was sampled) + meta | `updateIndexSections` regenerates exactly the same subset; tree.txt, deps.json, configs.json NOT touched |
| New file added to existing dir (moderate) | inventory + samples + meta regenerate; tree.txt NOT touched | Same |
| New directory created (moderate) | tree + inventory + samples + meta regenerate | Same |
| Manifest file edited (moderate, but triggers regenDeps) | inventory + deps + meta regenerate | Same |
| 2+ manifests changed (major) | Full crawl fallback | Full `Crawl` invocation |
| 5+ new dirs (major) | Full crawl fallback | Same |
| 10+ files deleted (major) | Full crawl fallback | Same |

A regression here (e.g. always regenerating tree.txt on any change) wastes 2-3 seconds per rescan against a moderate-sized project — not catastrophic, but the parity test should catch it.

The parity test enforces this with a **write-count assertion**: inject a fake `Writer` in tests, run each scenario, assert the exact set of artifact paths written matches the expected subset. This is the *only* place in the m30 arc where the test goes beyond byte-identical artifact comparison; the write-set assertion is necessary because byte-identical-meta doesn't catch "did we needlessly rewrite tree.txt with the same content."

### Goal 8 — Parity gate scenarios

`tests/test_rescan_parity.sh` runs four scenarios against `internal/crawler/testdata/rescan_scenarios/`:

1. **`no_changes/`** — fixture with `.claude/index/` populated and a known last-scan commit. Re-run = no-op. Assert: zero new writes to `indexDir`, stdout contains "Index is up to date".
2. **`trivial/`** — fixture with one source file edited since the last-scan commit (no new dirs, no manifest changes). Assert: `inventory.jsonl` and `meta.json` rewritten; `tree.txt`, `dependencies.json`, `configs.json` NOT rewritten; `samples/manifest.json` rewritten iff the edited file was in the sample set.
3. **`moderate_manifest/`** — fixture with `package.json` edited (manifest change → moderate). Assert: `inventory.jsonl`, `dependencies.json`, `meta.json` rewritten; `tree.txt`, `configs.json` NOT rewritten.
4. **`major_manifest/`** — fixture with two manifests changed (2+ → major). Assert: full crawl fallback (every artifact rewritten, behaves identical to `tekhton crawler crawl`).

Each scenario's expected write-set is encoded in `expected_writes.txt` alongside the fixture. The parity test compares the fake-Writer log against this file.

## Watch For

- **Skip-unchanged semantics are load-bearing for perf.** A regression where rescan rewrites `tree.txt` on every invocation (because the regen-decision logic drifted) doesn't *break* correctness — but it doubles the rescan time on every change, which compounds across the dogfood loop. The fake-writer write-set assertions in the parity gate exist specifically to catch this. Do not weaken them to "all expected files present" — the test must also assert the *absence* of unexpected writes.
- **Eight-branch decision tree is fragile.** Each branch's exit point matters (success vs warn vs full-crawl-fallback). Porting `rescan_project` 1:1 by line order is the cheapest correctness path. If you find yourself "tidying up" the branches into a switch statement, stop — preserve the bash order; let a future cleanup pass do the refactoring after the parity gate has been green for a release cycle.
- **`_get_changed_files_since_scan` dedup direction matters.** When the same file appears in both `git diff --name-status` (committed M) and `git status --porcelain` (uncommitted D), the working-tree entry wins. Bash does this via `awk -F'\t' '!seen[$NF]++'` *with the working tree concatenated AFTER committed*. The Go port's map-merge must do the same — working-tree appended last so it overwrites in the map. Reversed order silently breaks the "I deleted a file that was committed" case.
- **Legacy HTML-comment metadata fallback is real.** Pre-M68 projects don't have `.claude/index/meta.json`; they have `<!-- Scan-Commit: <sha> -->` in PROJECT_INDEX.md. The fallback in `metadata.go` must stay until an explicit migration milestone retires legacy projects. Do not drop the HTML-comment parsing because "M68 was years ago" — projects in the wild persist.
- **`tekhton-legacy.sh:550` is the last bash-side call site.** After rewiring, search the entire repo for any other `rescan_project` invocation: `grep -rn 'rescan_project' .`. Any leftover (e.g. in a hook script, a test helper, a doc snippet) is a landmine — the bash function will not exist after the deletes. The wedge-audit assertion catches this if added to `scripts/wedge-audit.sh` as required.
- **VERSION bump is m30.2's exclusive responsibility.** m30.1 must NOT touch VERSION (or only patch-bumps 4.29.x for regression hygiene). The minor bump to 4.30.0 lands at m30.2 close. This matches m27.3's pattern — the closing child owns the arc-level version bump, not the opening child. A version drift between m30.1 and m30.2 close is a sign of the wrong commit boundary.
- **Parent `m30-crawler-port.md` status flip is part of the deliverable.** Forgetting to flip `status: "split"` → `status: "done"` on m30.2 close means the manifest cleanup pass (`internal/finalize/cleanup_milestone.go`) won't retire the parent file. Add this to the close-out checklist explicitly — the acceptance criterion above is the gate.
